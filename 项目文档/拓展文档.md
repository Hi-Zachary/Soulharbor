## NF4

**NF4（NormalFloat 4）** 是一种专门为深度学习模型权重量化设计的 **4 位（4-bit）浮点数据格式**。它是 QLoRA 技术的核心创新之一，由 Tim Dettmers 等人在 2023 年提出。

传统的 4-bit 量化（如 INT4 或标准的 4-bit 浮点数）通常采用**等间距的均匀分割**，在压缩大语言模型（LLM）时容易导致严重的精度损失。而 NF4 则通过利用神经网络权重的统计规律，实现了在极低比特下对模型精度的“无损”压缩。

### 一、 为什么传统 4-bit 量化效果不好？

在深度学习模型中，神经网络在经过训练后，其层与层之间的**权重分布并不是均匀分布的**，而是高度符合**均值为 0 的正态分布（高斯分布）**。

- **传统 INT4/FP4（均匀量化）**：将数值范围划分为 16 个等宽的区间（如 $-8, -7, -6, \dots, 7$）。但因为大部分权重都挤在 0 附近，尾部（较大/较小的值）权重极少，这种均匀划分会导致 **0 附近密集的权重缺乏足够的表示精度**，而两侧的许多区间却被浪费了。

### 二、 NF4 的核心原理：分位数量化（Quantile Quantization）

NF4 的设计哲学是：**让每一个量化区间内包含相同数量的权重数据**。

1. **正态分布映射**：假设模型权重完全服从标准正态分布 $N(0, 1)$。
2. **保熵区间划分**：NF4 将正态分布的累积分布函数（CDF）分成 **16 个概率相等的区间**（因为 4 位二进制数最多表示 $2^4 = 16$ 个离散值）。
3. **信息量最大化**：这样划分后，在权重密集的 0 附近，量化格点非常密集；而在权重稀疏的两端，量化格点相对稀疏。这确保了这 16 个离散点能够最大化地保留原始正态分布的信息熵（Information Entropy）。

#### NF4 的 16 个具体查找表数值：

NF4 实际上是一个预先计算好的硬编码数组，对应正态分布下的 16 个最佳离散点（范围在 $[-1, 1]$ 之间）：

> ```
> [-1.0, -0.696192801, -0.525073051, -0.387913168, -0.269084814, -0.16009818, -0.05618311, 0.0, 0.05618311, 0.16009818, 0.269084814, 0.387913168, 0.525073051, 0.696192801, 1.0]
> ```

*(注：为了准确表示精准的 0 值，实际算法中对正负半轴进行了微调，负数侧有 8 个点，正数侧有 8 个点，且包含固定的 0)*

### 三、 NF4 在实际量化中的工作流程

当将一个 16-bit（如 FP16）的权重矩阵量化为 NF4 时：

1. **计算缩放因子（Absolute Maximum Scaling, $c$）**：找到该权重块（Block）中的绝对最大值 $c = \max(\vert{}W\vert{})$，将矩阵内的所有权重归一化到 $[-1, 1]$ 范围（即 $W_{\text{norm}} = \frac{W}{c}$）。
2. **查找表匹配（Quantization）**：对 $W_{\text{norm}}$ 中的每一个浮点数，在上述 NF4 的 16 个离散值中找到距离最近的一个，并记录其索引（0 到 15 的 4-bit 整数）。
3. **实时解量化（Dequantization）**：在模型进行前向传播计算时，硬件会根据 4-bit 索引查出对应的 NF4 浮点值，并乘以缩放因子 $c$，还原为 16-bit（FP16/BF16）参与矩阵乘法计算。

### 四、 NF4 与其他 4-bit 格式的区别

| **特性**         | **INT4**               | **FP4 (E2M1)**     | **NF4 (NormalFloat 4)**        |
| ---------------- | ---------------------- | ------------------ | ------------------------------ |
| **数值分布假设** | 均匀分布               | 类似对数分布       | **正态分布 $N(0, 1)$**         |
| **区间划分**     | 线性等间距             | 按照指数和尾数划分 | **按照累积概率相等划分**       |
| **信息保留度**   | 低（0 附近精度损失大） | 中等               | **极高（最契合 LLM 权重）**    |
| **适用场景**     | 传统边缘设备推理       | 通用低精度计算     | **大语言模型 4-bit 微调/量化** |

### 总结

**NF4 的本质就是用“非均匀的网格”去贴合“非均匀分布的神经网络权重”。** 它用极其巧妙的数学推导，证明了在 4-bit 限制下，针对正态分布数据的最优量化表示方式，也是 QLoRA 能在只占用极小显存的同时保持高准确率的最关键基石。



没问题！我们不用复杂的数学公式，用**打比方和直观的图解**把这件事彻底讲透。

要理解 NF4，我们需要搞懂三件事：

1. **大模型的权重到底长什么样？为什么像正态分布？**
2. **普通的 INT4 是怎么“切蛋糕”的？为什么会把模型切坏？**
3. **NF4 是怎么“量体裁衣”，变成一种新格式的？**

### 一、 什么是“权重”？为什么它偏偏符合正态分布？

#### 1. 什么是权重？

你可以把大模型想象成一个拥有数千亿个**微调开关**的超级复杂机器。每一个开关上的数值，就是**权重（Weight）**。

- 当你输入一句话，数据就会经过这几百亿个开关。
- 开关数值的大小，决定了对输入信息的“放大”还是“缩小”。

#### 2. 为什么权重会符合正态分布（钟形曲线）？

在模型还没训练时（随机初始化），工程师就会按照正态分布来设置初始权重。

而在经过几万亿个 token 的训练后，权重依然保持正态分布，这是由**深度学习的数学本质（中心极限定理）\**和\**训练机制**决定的：

- **绝大多数开关是“平庸”的**：大部分权重的数值都在 **0 的附近**（比如 -0.1, 0.02, 0.05）。它们只起辅助微调作用。
- **只有极少数开关是“极端”的**：极少数权重的数值很大（比如 -2.5 或 +3.0）。它们是决定模型逻辑的关键开关。
- **正则化约束（L2 Regularization）**：训练时算法会惩罚过大的权重，防止模型“过拟合”，这就像一股引力，不断把权重往 0 附近拉。

> **形象比喻**：
>
> 想象全中国人口的身高分布，绝大多数人都在 1.6米~1.8米 之间（对应 0 附近的权重），极少数人很矮，极少数人非常高（对应两端的极端权重）。**这就是典型的正态分布（中间多、两头少）。**

### 二、 普通的 INT4 是啥样的？为什么它会“伤模型”？

“量化”的本质，就是**把精度极高的连续数值，压缩到只有 16 个固定的选项里**（因为 4-bit 二进制数只有 $2^4 = 16$ 种组合，即 0000 到 1111）。

#### 传统的 INT4：等间距“硬切蛋糕”（均匀量化）

INT4 的做法非常直男：它把最大值和最小值之间的范围，**平均分成 15 等份**。

**我们还拿身高打比方**：

假设我们要用 4 个等级（比如 INT2）来记录全中国人的身高，范围是 0.5 米到 2.5 米。

- **INT 的做法**：平均切 4 块——
  - 级别 1：0.5米 ~ 1.0米
  - 级别 2：1.0米 ~ 1.5米
  - 级别 3：1.5米 ~ 2.0米
  - 级别 4：2.0米 ~ 2.5米

**坏处在哪里？**

1. **区间浪费**：级别 1（0.5-1.0米）几乎根本没人，这个分类名额被**白白浪费**了！
2. **精度灾难**：级别 3（1.5-2.0米）挤进了全国 90% 以上的人！1.55米 的人和 1.95米 的人在这个系统里被划成了同一种人，**细节全部丢失**。

这就是普通 INT4 压缩大模型会“变笨”的原因：**它把绝大多数集中在 0 附近的微小权重硬生生归为一类，导致模型的细腻推理能力大量丧失。**

### 三、 NF4 变成了什么？它是怎么解决这个问题的？

NF4（NormalFloat 4）的核心理念是：**既然我知道绝大多数权重都在 0 附近，那我就把更多的“名额”分配给 0 附近的区间！**

#### NF4 的做法：按照“人口密度”来切蛋糕（非均匀量化）

NF4 不再平均分配区间，而是根据正态分布的曲线，**让每个区间里包含的权重数量完全相等**。

**继续用身高打比方（NF4 的逻辑）**：

- 级别 1（极矮）：1.4米 以下（占全国 5% 人口）
- 级别 2（偏矮）：1.4米 ~ 1.65米（占全国 45% 人口）
- 级别 3（偏高）：1.65米 ~ 1.85米（占全国 45% 人口）
- 级别 4（极高）：1.85米 以上（占全国 5% 人口）

发现区别了吗？

- 在人多的地方（1.65m - 1.85m），划分的边界非常细，能精确区分 1.70m 和 1.75m。
- 在人少的地方（1.4m 以下），划分得很稀疏。

#### NF4 最终变成了什么？

在计算机内存里，NF4 变成了**一个 4-bit 的索引数字（0 到 15） + 一张固定的“映射密码表”**。

这 16 个密码表里的数字是专门用数学公式计算出来的非等距数值：

> **密码表数字**：
>
> ```
> [-1.0, -0.69, -0.52, -0.38, -0.26, -0.16, -0.05, 0.0, 0.05, 0.16, 0.26, 0.38, 0.52, 0.69, 1.0]
> ```

注意看这些数字之间的间隔：

- 在 **0 附近**：`0.0` $\to$ `0.05` $\to$ `0.16`（间隔非常小，只有 **0.05~0.1**，分辨率极高）
- 在 **边缘两端**：`0.69` $\to$ `1.0`（间隔很大，有 **0.31**）

### 四、 一图总结：数据的变身之旅

假设模型里有一个权重原始值是 `0.048`（FP16 格式，占用 16 位）：

1. **普通 INT4 看到后**：
   - 它的刻度太粗了（比如 0, 0.2, 0.4...），只能把 `0.048` 强行四舍五入变成 `0`。
   - **结果：精度丢失，信息损坏。**
2. **NF4 看到后**：
   - 查密码表，发现 `0.05` 这个刻度离 `0.048` 非常近！
   - 它把 `0.05` 对应的密码代号（假设是数字 `8`，二进制 `1000`）存进显存。
   - **结果：只用了 4 位（4-bit）的超小空间，却几乎完美还原了原始数据！**

总结来说，**NF4 并没有改变计算机存储 4 位的底层机制，而是用一套极其聪明的“非等距标尺”，完美契合了大模型数据的分布规律**，从而实现了“用 4 位的空间，办成了 16 位的事”。



我们用一个**极度具体的“数字拆解”例子**，把把 FP16 变成 NF4（量化）、以及从 NF4 变回 FP16（解量化）的整个数学过程一步一步算一遍。

在讲例子前，先搞懂关键的角色：

- **原始数据（FP16）**：16 位的浮点数，比如 `2.534`。
- **缩放因子（Scale / Absolute Maximum $c$）**：用来把任意范围的数值**等比例缩小**到 $[-1, 1]$ 之间的一个比例尺。
- **NF4 密码表**：固定不变的 16 个基准刻度（范围都在 $[-1, 1]$ 之间）。
- **量化后的数据（NF4）**：一个 4 位的索引号（比如 `8`，或者二进制 `1000`）。

### 一、 准备工作：假设我们有一组原始权重

假设模型某一层里面有 **4 个权重（FP16 格式）**：

$$W = [0.112, \quad 0.820, \quad -1.450, \quad 0.380]$$

这 4 个数字每个都占 16 位（FP16），我们要把它们压缩成 NF4（每个只占 4 位）。

### 二、 第一步：量化过程（FP16 $\rightarrow$ NF4）

#### 1. 寻找绝对值最大值（计算缩放因子 $c$）

在这组数字里找到绝对值最大的那个数：

$$\vert{}-1.450\vert{} = 1.450 \implies \text{缩放因子 } c = 1.450$$

#### 2. 归一化（等比例缩放到 $[-1, 1]$ 范围内）

把这组数字全部除以 $c$，把它们强制映射到 $[-1, 1]$ 的区间：

- $0.112 / 1.450 = \mathbf{0.0772}$
- $0.820 / 1.450 = \mathbf{0.5655}$
- $-1.450 / 1.450 = \mathbf{-1.0000}$
- $0.380 / 1.450 = \mathbf{0.2621}$

现在我们得到了归一化后的数据：$W_{\text{norm}} = [0.0772, \quad 0.5655, \quad -1.0000, \quad 0.2621]$。

#### 3. 查 NF4 密码表（找离谁最近）

接下来，拿着归一化后的数字，去对比 **NF4 的 16 个固定刻度**（索引编号为 0 到 15）：

| **索引号 (4-bit)** | **二进制** | **NF4 刻度值** |
| ------------------ | ---------- | -------------- |
| 0                  | 0000       | -1.0000        |
| 1                  | 0001       | -0.6962        |
| ...                | ...        | ...            |
| 7                  | 0111       | 0.0000         |
| **8**              | **1000**   | **0.0562**     |
| ...                | ...        | ...            |
| **10**             | **1010**   | **0.2691**     |
| ...                | ...        | ...            |
| **12**             | **1100**   | **0.5251**     |
| **13**             | **1101**   | **0.6962**     |
| ...                | ...        | ...            |

我们开始一个个就近匹配（四舍五入到最近的刻度）：

1. **第一个数 `0.0772`**：
   - 离刻度 `0.0562`（索引 8）的距离是 $0.0210$。
   - 离下一个刻度 `0.1601`（索引 9）的距离是 $0.0829$。
   - **结论**：距离**索引 8** 最近，存下 **`8`**。
2. **第二个数 `0.5655`**：
   - 离刻度 `0.5251`（索引 12）距离 $0.0404$。
   - 离刻度 `0.6962`（索引 13）距离 $0.1307$。
   - **结论**：距离**索引 12** 最近，存下 **`12`**。
3. **第三个数 `-1.0000`**：
   - 刚好等于刻度 `-1.0000`（索引 0）。
   - **结论**：存下 **`0`**。
4. **第四个数 `0.2621`**：
   - 离刻度 `0.2691`（索引 10）极近（只差 $0.0070$）。
   - **结论**：存下 **`10`**。

#### 最终显存里存了什么？

压缩完成后，显存里**不再存储那四个占用空间的大浮点数**，而是只存了：

1. **4 个 4-bit 的整数索引**：`[8, 12, 0, 10]`
2. **1 个缩放因子（FP16 格式）**：`c = 1.450`

> **空间省了多少？**
>
> 原来存 4 个数需要 $4 \times 16 = 64$ bit。
>
> 现在存 4 个索引只需要 $4 \times 4 = 16$ bit（加上共享的 16 bit 缩放因子 $c$），**节省了近 60%~75% 的空间！**

### 三、 第二步：解量化过程（NF4 $\rightarrow$ FP16）

当模型要进行计算时，显卡必须把它们**还原成真实的数值**来进行乘法运算：

还原公式非常简单：

$$\text{还原后的 FP16 权重} = \text{密码表刻度值}[\text{索引号}] \times \text{缩放因子 } c$$

1. **第 1 个数（索引 8）**：
   - 查表得刻度值 `0.0562`
   - $\text{还原值} = 0.0562 \times 1.450 = \mathbf{0.0815}$ （原始值是 `0.112`）
2. **第 2 个数（索引 12）**：
   - 查表得刻度值 `0.5251`
   - $\text{还原值} = 0.5251 \times 1.450 = \mathbf{0.7614}$ （原始值是 `0.820`）
3. **第 3 个数（索引 0）**：
   - 查表得刻度值 `-1.0000`
   - $\text{还原值} = -1.0000 \times 1.450 = \mathbf{-1.4500}$ （原始值是 `-1.450`，完全精准）
4. **第 4 个数（索引 10）**：
   - 查表得刻度值 `0.2691`
   - $\text{还原值} = 0.2691 \times 1.450 = \mathbf{0.3902}$ （原始值是 `0.380`）

### 四、 什么是“缩放因子”？为什么它至关重要？

你看完上面的推导就会发现：**密码表里的数字范围永远固定在 $[-1, 1]$ 之间。**

但是大模型不同层、不同神经元的权重，数值范围是千变万化的！

- 有的层的权重范围在 $[-0.01, 0.01]$（非常小）。
- 有的层的权重范围在 $[-50, 50]$（非常大）。

**缩放因子（Scale Factor $c$）就像是一个“变焦镜头”**：

- 当权重都很小（比如最大是 $0.01$），缩放因子 $c = 0.01$，把 $[-1, 1]$ 的 NF4 网格缩小 100 倍，精准去贴合很小的数。
- 当权重很大（比如最大是 $50$），缩放因子 $c = 50$，把 $[-1, 1]$ 的 NF4 网格放大 50 倍，去匹配很大的数。

这就是为什么必须给每一组权重配一个**缩放因子 $c$** 的原因：**没有它，NF4 固定的 16 个刻度就没办法适应模型中千奇百怪的真实数值范围。**
