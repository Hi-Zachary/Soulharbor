### 1.1 训练格式一览

| 格式名 | 本项目哪里用 | 核心字段 | 框架如何读 |
|--------|--------------|----------|------------|
| **纯文本 PT** | `pt.jsonl` | `text` | `dataset_info`：`columns.prompt ← text`，stage=`pt` |
| **ShareGPT 对话** | SFT | `conversations[{from,value}]`，可选 `system` | `formatting: sharegpt`，`from∈{human,gpt}` |
| **ShareGPT + ranking** | DPO | 同上 + `chosen`/`rejected` | `formatting: sharegpt` + `ranking: true` |
| **Instruction JSONL** | 意图分类 | `instruction`/`input`/`output` | `train_classifiers_hf.py` 拼成分类输入 |

**一句话：** 对话主线与 DPO 都走 LLaMA-Factory 的 **ShareGPT**；PT 是整段 text 的 CLM；意图分类不用 ShareGPT。线上只挂 **一份 chat LoRA（DPO）** + MacBERT 意图头 + BGE-M3。

## 2. 上游来源、论文/项目引用与用途

对话微调需要三样东西：领域文本（让基座熟悉心理中文）、指令对话（学会咨询式应答）、偏好对（学哪种回应更好）。本项目复用两条成熟的公开数据链路——SoulChatCorpus（论文级心理多轮，做主 SFT 主体与 DPO 的 prompt 池）和 EmoLLM（开源项目整理好的 PT / 多轮中间产物，做领域补强），再自建 DPO 负样本与意图分类数据。这样既保证数据量，又能对每个阶段的来源做出处可查的交代。

上游原始文件统一放在 `archive/sources/` 下，未加工，构建脚本读取后转为 `train/data/` 的活跃 JSONL。下表给出学术与开源出处。

### 2.1 上游出处总表

| 数据（仓库路径） | 上游项目 / 论文 | 链接 | 本仓库用途 |
|----------|-----------------|------|------------|
| `soulchat/SoulChatCorpus-sft-multi-Turn.json` | **SoulChat / SoulChatCorpus**（华南理工等）。论文：Chen et al., *SoulChat: Improving LLMs' Empathy, Listening and Comfort Abilities…*，**Findings of EMNLP 2023**。原论文公开 2 M+ 多轮样本；本文件为开源 ModelScope 版本（过滤隐私/敏感后 **258 354 条 / 13 个 topic**，约 1.5 M 轮）。 | [Anthology](https://aclanthology.org/2023.findings-emnlp.83/) · [GitHub](https://github.com/scutcyr/SoulChat) · [ModelScope](https://www.modelscope.cn/datasets/YIRONGCHEN/SoulChatCorpus) | 主 SFT 混合主体、意图**正样本**、DPO prompt 池（与进 SFT 的样本**互斥**）、主对话 BLEU/ROUGE 评测 |

### 2.2 EmoLLM 数据本身从哪儿来？——更上游链路

EmoLLM（`SmartFlowAI/EmoLLM`）本身不是一手心理咨询语料的生产者，而是「二次集成 + 开源大模型微调」的项目：一方面整合多个公开心理与对话数据集，并在开源基座上做增量 PT 与 SFT；另一方面把微调过程中的中间产物（PT 语料、多轮 SFT）开源在 `datasets/` 目录供下游复用。本项目复用的是其已经整理好的 `pt.json` / `data_pro.json` 等中间产物，并在此基础上做格式对齐与混比。

因此，本仓库 `archive/sources/llm/` 下的文件实际溯源到 EmoLLM 的 `datasets/` 目录，其更上游则常常包括 PsyQA（中文心理健康问答聚合）、CPsyCounD / PsyQA-DPO 等中文心理对话数据集，以及公开心理咨询相关脱敏文本（具体由其仓库 `datasets/README` 声明）。

### 2.3 本仓库自建 / 合成（无独立上游论文）

| 产物（仓库路径） | 怎么来的 |
|------|----------|
| `train/data/llm/dpo.jsonl` | SoulChat **互斥切片**作上下文 + 语料中质量较好的助手回复作 **chosen**；**MiniMax-M2.7** 按「敷衍/欠共情」指令生成 **rejected**（`train/scripts/alignment/`） |
| `train/data/classifiers/train/intent/intent_*.jsonl` | SoulChat 正样本 + LCCC 负样本（1:1、USER-only、按轮数/字长对齐），由 `train/scripts/classifiers/build_intent_dataset_v4.py` 写成 instruction / input / output JSONL |

### 2.4 基座与编码器（模型选型详见 [`01` §五](./01_项目大纲与架构.md) / [`02` §2.1](./02_项目详尽技术文档.md)）

| 组件 | 出处（简述） | 为何选 | 本项目用法 |
|------|--------------|--------|------------|
| Qwen3-14B | 阿里通义 Qwen3 开源稠密 LLM（~14.8B） | 中文强、可 tool-call、单卡 4-bit 可部署 | 全部 LLM 生成的唯一基座 |
| chat LoRA `dpo_synth_*` | 本仓库 DPO 产物 | 偏好对齐、可调 scale | 用户对话（会话摘要走裸基座） |
| chinese-macbert-base → intent ckpt | MacBERT（Cui et al., Findings of EMNLP 2020） | 快、稳、与生成解耦；分流任务 base 足够 | 咨询/闲聊分流（`checkpoint-188`） |
| bge-m3 | BAAI BGE-M3（arXiv:2402.03216） | 中文检索强、开箱即用、支持较长文本 | 记忆 embedding，**不另训** |
| MiniMax-M2.7 | 外部 API | 批量合成「敷衍」负样本 | **仅** DPO 数据构建 |

构建脚本：`train/scripts/llamafactory/build/`、`alignment/`、`classifiers/`。

## 3. PT — 继续预训练（`pt.jsonl`）

### 3.1 原始来源

- **上游**：`archive/sources/llm/pt.json`（EmoLLM 开源的 `datasets/pt.json`，约 195 545 行 / **24 443 条**单轮样本）。
- **原始 schema**：每条形如 `{"conversation": [{"input": "...", "output": "问题:...\n答案:..."}]}`，是 `问题：…\n答案：…` 形式的心理 Q-A 文本片段（无对话结构）。

### 3.2 原始样本（`archive/sources/llm/pt.json`，第 1 条）

```json
{
  "conversation": [
    {
      "input": "",
      "output": "问题:心理咨询师，我觉得我的胸闷症状越来越严重了，这让我很害怕。\n答案:我能理解你的感受，首先我们要明确你的症状并不是生理问题，而是心理问题。我们可以尝试找出引发你胸闷的心理原因。"
    }
  ]
}
```

### 3.3 构建方式

1. **脚本**：`train/scripts/llamafactory/build/build_lmf_pt_jsonl.py`
   - 读取 `archive/sources/llm/pt.json`（顶层 JSON list）；
   - 取 `conversation[0].output`，用正则 `^\s*问题\s*[:：]\s*(?P<q>...)\s*\n\s*答案\s*[:：]\s*(?P<a>...)` 切成 Q/A；
   - 拼成 `[USER] {q}\n[ASSISTANT] {a}`，写出 `{"text": "..."}`。
2. **不是 ShareGPT**：整段 `text` 进 LLaMA-Factory `stage=pt`（causal LM），把 `[USER]` 当普通 token 预测下一 token；不区分 system/user/assistant。
3. **训练**：`train/configs/pt.yaml` / `run_pt.sh`（QLoRA 4-bit；超参见文档 02 §10.6）。

### 3.4 规模与形态

- **24 443** 条；平均约 **110** 字符 / 条（偏短片段）。  
- `dataset_info` 键：`soulharbor_pt`，列映射 `columns.prompt = text`。

### 3.5 处理后样本（`train/data/llm/pt.jsonl`，第 1 条，与原始同源）

```json
{
  "text": "[USER] 心理咨询师，我觉得我的胸闷症状越来越严重了，这让我很害怕。\n[ASSISTANT] 我能理解你的感受，首先我们要明确你的症状并不是生理问题，而是心理问题。我们可以尝试找出引发你胸闷的心理原因。"
}
```

> 字段说明：`text` 是 PT 唯一字段；`dataset_info` 中 `columns.prompt ← text` 表示把这串整段文本作为语言建模目标。

PT 的作用是让 14B 在心理中文分布上更熟悉，不直接教工具调用或偏好排序；形式上是单段连续文本的因果语言建模，不是 ShareGPT 的多角色结构。

## 4. 主指令 SFT — `sft_instruction.jsonl`

### 4.1 原始来源（两条支路混合）

| 支路 | 仓库路径 | 形态 |
|------|----------|------|
| SoulChat 支路 | `archive/sources/soulchat/SoulChatCorpus-sft-multi-Turn.json` | 258 354 条多轮对话，13 个 topic，每条 `{"id": int, "topic": str, "messages": [{"role": "user"/"assistant", "content": str}]}` |
| EmoLLM data_pro 支路 | `archive/sources/llm/data_pro.json` | 6 281 条多轮心理咨询对话，每条 `{"conversation": [{"system": str, "input": str, "output": str}, ...]}` |

### 4.2 原始样本

**SoulChat 第 1 条**（`archive/sources/soulchat/SoulChatCorpus-sft-multi-Turn.json`）：

```json
{
  "id": 0,
  "topic": "成长",
  "messages": [
    {"role": "user",      "content": "最近感觉很焦虑，不知道如何缓解。"},
    {"role": "assistant", "content": "我明白你的感受。首先，要知道焦虑是一种正常的情绪。但是，当它影响到你的生活质量时，就需要采取行动了。"},
    {"role": "user",      "content": "可是我总觉得自己做什么都不够好，很害怕失败。"},
    {"role": "assistant", "content": "这可能是完美主义导致的。完美主义者总是把难度设置得很高……其实，你是一个有自尊和价值的人，无论成败。"}
  ]
}
```

**SoulChat topic 分布（13 类，均衡度较高）**：`婚恋 55 111`、`情绪 31 796`、`人际 29 887`、`家庭 25 611`、`治疗 24 622`、`成长 24 190`、`行为 20 960`、`自我 20 017`、`社会 9 757`、`职场 9 174` 等。

**EmoLLM data_pro 第 1 条**（`archive/sources/llm/data_pro.json`）：

```json
{
  "conversation": [
    {
      "system": "现在你是一个心理专家，我有一些心理问题，请你用专业的知识帮我解决。",
      "input":  "医生，我最近在社交场合总是感到非常紧张和焦虑，尤其是当有很多人的时候，我甚至会出汗、心跳加速。\n\n",
      "output": "我理解你的感受，社交焦虑是很常见的。首先，我想告诉你，你并不孤单。请问你能告诉我，在哪些具体的社交场景中，你感到最不舒服或焦虑呢？\n\n"
    },
    {
      "input":  "主要是参加聚会或者需要公开发言的场合。我总是担心自己会说错话，或者别人会对我有不好的评价。\n\n",
      "output": "明白了。在这种情况下，我们首先要认识到，每个人都有可能说错话或遇到尴尬的情况，这是正常的。我建议你可以尝试一些放松技巧，比如深呼吸、正念冥想，或者在参加社交活动前进行一些轻松的身体活动，以减轻紧张感。\n\n"
    }
  ]
}
```

### 4.3 构建方式

1. **SoulChat 支路**：`build_lmf_sharegpt_soulchat.py` 读 SoulChat 多轮 →
   - `role: user/assistant` → `from: human/gpt`；
   - 按 topic 均衡 + **校园相关关键词**（如「大学」「考研」「高考」「大学生」等）提高校园占比（默认 `--campus-ratio 0.62`）；
   - 写出 ShareGPT（仅 `conversations` + `system`，无 `tools`）。
2. **EmoLLM data_pro 支路**：`build_lmf_sharegpt_data_pro.py` 把 `conversation[]` 中的 `input/output` 拍扁成 `from: human/gpt` 交替的 ShareGPT，写到中间文件 `sft_data_pro.jsonl`。
3. **混合**：`build_lmf_sharegpt_mixed_campus.py` 去重 + 按首轮用户句签名做互斥，再截断到目标条数。当前活跃的 `sft_instruction.jsonl`（**20 000 条**）按首轮用户句对齐估计约 **90% SoulChat + 10% data_pro**（≈ 18 000 / 2 000）。
4. 统一 **ShareGPT**：每条 `{ "conversations": [...], "system": <统一 SoulHarbor 人设>, "tools": [] }`。
5. **训练**：`train/configs/sft_main.yaml`（stage=`sft`，template=`qwen3_nothink`；超参见 02 §10.6）。

### 4.4 规模与形态

- **20 000** 条对话；平均约 **11.3** 条消息 / 对话（median 12）；对话轮数分布：12 轮 6 717 / 10 轮 5 465 / 14 轮 3 288 / 8 轮 1 615 / … / 2 轮 535。  
- `dataset_info` 键：`soulharbor_mixed_campus_sft`，`columns.messages = conversations`。  
- 全部带统一 `system = "你是Soulharbor心理健康助手，请你用专业温和的方式帮助用户解决心理问题。"`，`tools = []`（主对话 SFT 不教工具调用）。

| `system` | 可选系统提示（训练时进 chat template 的 system 槽位） |
| `tools` | 主对话 SFT 一律为 `[]`（主对话无工具调用） |

## 5. DPO — `dpo.jsonl`（线上对话 LoRA 的关键数据）

### 6.1 原始来源

- **Prompt 池**：`archive/sources/soulchat/SoulChatCorpus-sft-multi-Turn.json`（258 354 条多轮），与已用于主 SFT 的样本**互斥**（以首轮用户句签名去重）。

- **Rejected**：调用外部 **MiniMax-M2.7** API 生成，按 prompt「较差但仍相关：偏空泛、欠共情、敷衍、略说教、复读用户原话等」产出。

### 6.2 构建流水线

生产 `train/data/llm/dpo.jsonl`（dataset 名 `soulharbor_dpo_soulchat_exclusive_minimax_3k`）大致步骤：

1. **Prompt 池**：从 SoulChat 多轮切出「上文 + 当前用户句」；脚本：`alignment/build_prompts_pool.py`、`build_dpo_pairs_from_soulchat_exclusive.py` 等。

   - `conversations`：到「待回复的用户句」为止的上下文（最后一轮常为 human）；

5. **训练**：

### 8.3 构建方式（当前版本：intent_v4）

`train/scripts/classifiers/build_intent_dataset_v4.py`（历史 v2 脚本 `build_classifier_dataset_v2.py` 保留在仓库，但现行数据以 v4 为准）关键步骤：

1. **正样本**：从 SoulChat 多轮里按 `id + 轮次` 随机取连续 1/2/3 条用户话轮，拼成 `[USER] …\n[USER] …` 的 USER-only 输入；`n_turns` 覆盖 1/2/3 且各分桶内**字长匹配**（同轮数桶内按字符长度分 bin 对齐），避免分类器靠"长度"取巧。
2. **负样本**：从 LCCC-base train 取连续 1/2/3 条用户话轮，先按中文标点重新断句合并空格，同样做轮数与字长对齐。
3. 写成 instruction / input / output 三段 JSONL；output 一律 `{"is_consult": 0/1}`。
4. 划分：**3 000 train / 300 valid / 300 test**；**正负严格 1:1**（各 1500 / 150 / 150），不再做"偏咨询召回"的比例偏置——因为线上分类器的作用只是选 LoRA scale（0.7/0.3），判错咨询的代价从"漏掉一次认真倾听"变成了"语气稍重"，不值得为此牺牲均衡性。
5. **格式**：非 ShareGPT；HF Trainer 在 `train_classifiers_hf.py` 里把 `instruction + input` 拼接、tokenize 成 MacBERT 输入；output 作为标签（`CrossEntropyLoss`）。
6. **训练**：`train/configs/intent_classifier.json` + `train/scripts/classifiers/train_classifiers_hf.py`（**MacBERT-base**，epochs 1，lr 2e-5，train batch 16，eval batch 32，max_length 512，seed 42）；`train_meta.json` 记录 **valid 准确率 99.67% / test 99.0%**（`checkpoint-188` 所在 run）。

## 10. 训练格式选型对比（为什么用 ShareGPT，能用 Qwen 原生 ChatML 吗？）

### 11.1 四种主流格式横向对比

| 格式 | 数据形状 | 典型来源 | 一行代码长这样 | 优点 | 缺点 | 本项目用到 |
|------|----------|----------|---------------|------|------|-----------|
| **纯文本 PT（causal LM）** | `{"text": "..."}` 整段拼接 | EmoLLM / 通用爬虫 | `[USER] 你好\n[ASSISTANT] 你也好` | 极简、不依赖 chat 模板、CLM 训练直接吃 | 不区分角色、不能教工具调用 | §3 PT（2.4 万） |
| **Alpaca（Stanford）** | `{"instruction", "input", "output"}` 三段 | Self-Instruct / WizardLM | `{"instruction":"翻译","input":"hello","output":"你好"}` | 简单、单轮、可读性好 | **只支持单轮**，没有 system/tools；不能直接表示多轮对话 | ❌ |
| **ShareGPT**（`anon8231489123/ShareGPT-Chinese`） | `{"conversations":[{"from":"human"/"gpt","value":"..."}], "system"?,"tools"?}` | ShareGPT 原始导出 | 多轮 `from/value` 交替 | **多轮 / 可选 system / 可选 tools**；LLaMA-Factory 原生支持 `formatting: sharegpt` | 字段名约定私有（不是 OpenAI 标准），要靠 LMF 翻译 | ✅ SFT / DPO |
| **OpenAI ChatML / Messages** | `{"messages":[{"role":"system"/"user"/"assistant"/"tool","content":"..."}], "tools"?}` | OpenAI 官方 | 标准多轮 JSON | **行业标准**；可直接调 OpenAI/Anthropic/智谱 API；结构最干净 | LLaMA-Factory 直到较新版本才原生支持；本仓库用的 0.9.4 仍以 ShareGPT 为主 | ❌（评测脚本转写时用过） |

### 11.2 为什么本项目最终选 ShareGPT，而不是 OpenAI Messages？

1. **LLaMA-Factory 0.9.4 原生支持最完善的就是 ShareGPT**：所有 `stage=pt/sft/dpo` 的列映射、mask 逻辑、`tools` 角色、chosen/rejected 都是先按 ShareGPT 设计；切到 OpenAI Messages 路径反而要自己写 formatter。  
3. **多轮场景天然贴合**：SoulChat 多轮对话本来就是「user / assistant 交替」，ShareGPT 的 `conversations[].from` 直接 1:1 映射 `human/gpt`，转换无信息损失。  
4. **共享社区生态**：SoulChatCorpus、EmoLLM 等上游语料已经习惯用 ShareGPT 形态发布；用 ShareGPT 训练可以零成本复用上游数据。  

### 11.3 Qwen 自己也有原生数据格式（ChatML），那为什么 ShareGPT 也能训 Qwen？

> 这是最常被问的问题之一，本节拆开讲清楚。

**Qwen 的原生 chat 格式是 ChatML**（Chat Markup Language），形如：

```
<|im_start|>system
你是 SoulHarbor 心理健康助手。<|im_end|>
<|im_start|>user
我最近很焦虑。<|im_end|>
<|im_start|>assistant
我理解你的感受，……<|im_end|>
```

这套特殊 token（`<|im_start|>` / `<|im_end|>` / `<|im_endoftext|>`）是 Qwen tokenizer 自带的，**Qwen 预训练时就是在这个格式上学的对话**。所以 Qwen 推理时必须用 `tokenizer.apply_chat_template(messages, tokenize=False)` 把消息列表渲染成 ChatML 文本，再送进模型。

那为什么 ShareGPT 也能训练 Qwen？——**因为 LLaMA-Factory 在内部完成了一次「格式翻译」**：

1. 你提交的 ShareGPT JSONL（`conversations[].from/value`）首先被 LLaMA-Factory 的 `aligner.py` 解析为标准 `messages` 列表（`role: system/user/assistant`）；
2. 再交给 Qwen3 的 template（`template=qwen3_nothink`），调用 `tokenizer.apply_chat_template(...)` 渲染成上面那段 ChatML 文本；
3. 渲染出来的 ChatML 文本才会被 tokenizer 切成 token 喂给模型；
4. **SFT/DPO 阶段**：ChatML 里 assistant 之前的部分 mask 掉，只在 assistant 回复的 token 上算 loss——这与原生 ChatML 训练完全等价。

**所以本质上，「用 ShareGPT 训 Qwen」和「用 ChatML 训 Qwen」走的是同一条路**——ShareGPT 只是 LLaMA-Factory 提供的一个**比 ChatML 更人类可读、更跨模型兼容的 JSON 抽象层**。你写 `{"from":"human","value":"你好"}` 和你写 `{"role":"user","content":"你好"}`，最终喂进 Qwen 的 token 序列几乎完全相同（`<|im_start|>user\n你好<|im_end|>`）。

**唯一需要小心的差异**：
- ShareGPT 默认 `from: human/gpt`（不是 `user/assistant`）；LMF 的 ShareGPT parser 会自动映射成 ChatML 的 `role: user/assistant`，无需手动改。  
- 如果你启用了 `template=qwen3_nothink` + `enable_thinking=false`，模型不会输出 `<think>...</think>` 段；如果你想训带思考的版本，把 template 换成 `qwen3` 即可。  

**结论一句话：** Qwen 不挑训练格式，挑的是**渲染后的 ChatML 文本**；ShareGPT / OpenAI Messages / Alpaca 只是不同入口，LMF 在 `apply_chat_template` 处会归一到 ChatML，再走 Qwen 原生的训练与推理路径。

## 12. 数据部分小结

训练数据来源包括 SoulChatCorpus（EMNLP 2023 Findings）、EmoLLM 开源中间产物、LCCC（NLPCC 2020）以及 MiniMax 合成的 DPO 负样本。形态上，PT 为纯文本；SFT 与 DPO 为 ShareGPT（DPO 另加 ranking）；意图分类为 instruction JSON。SFT 约九成 SoulChat、一成 EmoLLM data_pro，并偏向校园相关话题。规模约为 PT 2.4 万、SFT 2 万、DPO 3 千、意图 3 千。

DPO 的 prompt 与主 SFT 样本互斥，避免同一批对话既 SFT 又 DPO 造成泄漏。选用 ShareGPT 而非手写 ChatML，是因为 LLaMA-Factory 会在 `apply_chat_template` 处统一归一为 ChatML 再喂给 Qwen；详见 §11.3。PT 使用 `[USER]`/`[ASSISTANT]` 套壳，是为了让基座先见到「用户提问 → 助手回答」的双行排布，且这些标记在 Qwen tokenizer 中各为单 token，副作用可忽略。意图分流使用 MacBERT 而非 14B，是为了与生成解耦并保持低延迟。LCCC 原文是字级分词加空格分隔，构建时需去空格并按中文标点断句，否则分类器会把空格当词边界学到噪声。
