# 第一部分：项目与架构常见问题

## 一、定位与问题定义

### Q1. SoulHarbor 是什么？

SoulHarbor 是面向校园场景的心理健康辅助对话系统。生成侧运行在量化后的 Qwen3-14B 上，外挂若干专用机制：MacBERT-base 做咨询/闲聊二分类（只调节语气强度）；BGE-M3 与字级词法检索承担长期记忆的混合召回；一份经 DPO 得到的 chat LoRA 负责对话生成（咨询与闲聊使用不同推理 scale）；会话滚动摘要关闭 LoRA，走裸基座。

产品侧重倾听与情绪支持：用户可关闭记忆或一键遗忘；管理端提供匿名化会话浏览与分诊队列。系统形态为研究原型与单机可演示闭环。

### Q2. 为什么不直接接通用大模型 API？

通用大模型便于对话，但在心理健康场景中暴露两类结构性不足。其一是语气与边界未针对倾听任务对齐：容易空泛安慰、急于给建议或说教（SoulChat 等工作已指出这一点）。其二是缺乏可靠的跨会话记忆；即便引入记忆，主流写时抽取又容易把瞬时情绪固化为错误标签。校园咨询资源紧张、污名化又使部分学生更倾向低门槛入口，因此需要把「怎么说」与「怎么记」同时做对，且记忆可开关。

SoulHarbor 的做法是职责解耦：独立小分类器管语气强度；长期记忆走「原文入库 + 查询时重建」；最后用 Web 与管理端做成可演示闭环。两条技术线只在生成前把记忆块拼进 system 时交汇。

### Q3. 项目的两条主线创新如何表述？

对话线：在 Qwen3-14B 上完成继续预训练、指令微调与 DPO 偏好对齐，并用独立分类器按咨询/闲聊调节同一份 LoRA 的推理 scale，使模型学会更适合倾听任务的说话方式。

记忆线：采用 ER（Experience Rebuild）——写入阶段不做事实抽取，检索阶段再把原文扩窗重建为可用的经历证据。Profile（支持偏好）仅经用户确认后落库；政策层拦截诊断词、人格标签与瞬时情绪前缀。

工程形态刻意保持单卡一份 LoRA、单文件 SQLite、语义侧按用户 FAISS 缓存；读路径除可选查询规划外由代码编排。离线对照表明，在固定答题模型、只更换记忆库的条件下，长程记忆 QA 准确率由约 64% 提升至约 92%。 叙事上可记为：对话线回答「怎么好好说」，记忆线回答「怎么好好记且不乱记」；评测上前者看 BLEU/ROUGE 相对 base 的提升，后者看同 reader 下的 QA / F1 / staleness。

### Q4. 项目中较难把握的边界在哪里？

难点主要在职责边界与线上行为一致，而非某一条算法公式。

分类器只影响语气强度，不门控是否检索长期记忆：`is_consult` 只调 LoRA scale（咨询约 0.7 / 闲聊约 0.3）并写入 `turn_metrics.route`。闲聊中也可能提到上周的事；把记忆绑死在咨询路由上反而丢信息。偶发误判的代价因此只是语气强弱，而不是整条对话行为被带偏。

生成侧只加载一份 chat LoRA，靠 scale 区分场景；摘要关 LoRA。Trace 写路径不调用生成模型；Profile 提议是旁路且先进入 pending。Qwen chat template 对多条 `role=system` 不稳定，记忆块注入位置与前缀文案需要单独处理（见第二部分相关问答）。

DPO 的 rejected 由外部模型按「空泛、欠共情、敷衍、说教」指令合成，需要质检以防合成质量反超 chosen。DPO 后 BLEU 略降而 ROUGE-1/2 略升，说明优化目标是偏好而非 n-gram 复现，解读时不能只看 BLEU。

### Q5. `is_consult` 分类器现在控制什么？

| 影响 | 不影响 |
|------|--------|
| chat LoRA scale（咨询 0.7 / 闲聊 0.3） | 是否检索长期记忆 |
| `turn_metrics.route`（`consult` / `chat`） | 是否运行记忆写路径 |
| 管理端分诊筛选用 | 用户是否开启记忆 |

记忆路径只看用户设置中的 `memory_enabled`，与 `is_consult` 完全解耦。

## 二、架构与运行时

### Q6. 系统整体架构如何理解？

```
用户消息
 │
 ▼
FastAPI Web 层（鉴权 / Cookie / 异步提交到线程池）
 │
 ▼
意图分流：MacBERT-base → is_consult ∈ {0, 1}
 │
 ▼
记忆子系统（仅当用户开启记忆时）
  hybrid 召回（BGE-M3 + 字级 BM25, RRF）
  → ER 扩窗成「一段经历」→ 跨会话时序链
  → MMR 选窗选择 → <memory> system 前缀注入（只含 user 原文）
 │
 ▼
生成引擎：Qwen3-14B 4-bit + chat LoRA（多 scale）流式返回
 │
 ▼
后台 post-turn（非阻塞）：
  Trace 分块+向量化；Profile 可 LLM 提议 pending；摘要条件触发（裸基座）
```

应用层可并行处理 HTTP 请求；引擎内用 `threading.RLock` 串行所有 GPU 调用。post-turn 在线程池后台执行，不阻塞首 token。记忆检索失败时注入空块兜底，对话仍可继续。Profile 提议只进 pending，确认前不成记忆。

### Q7. 单轮对话在运行时如何走？

1. 鉴权并取得会话 id，将用户消息写入数据库；  
2. MacBERT 分类得到 `is_consult`；  
3. 组装模型消息：摘要 system +（若开记忆）`<memory>` system 前缀块（用户原文、日期与来源、全量已确认偏好）+ 自上次摘要以来的全部原文；  
4. 按路由选择 chat LoRA scale，流式生成；  
5. 写库、写 `turn_metrics`，并提交 post-turn 任务。

记忆检索对每一轮只做一次上下文组装，不在生成过程中重复检索。

### Q8. 单卡如何同时支持咨询语气、闲聊语气与会话摘要？

执行上，引擎内 RLock 串行所有 GPU 调用。强度上只加载一份 `chat` LoRA，用 `set_scale` 切换：咨询约 0.7、闲聊约 0.3；摘要关闭 adapter 走基座。应用层把 ingest 与摘要放到 post-turn 线程池，避免阻塞流式首 token。长期记忆已是原文库，写路径不再需要第二份任务 LoRA。

### Q9. 流式传输时客户端断开，回复还能写库吗？

可以，这是刻意设计。`/api/chat_stream` 用 `TextIteratorStreamer` 把生成放到独立 worker 线程；客户端 Abort 只停止读取 `StreamingResponse`。后台线程跑完 `generate_stream` 后，由 `_finalize_chat_turn` 把全文写入 assistant 消息表。前端可通过 `/api/history` 轮询补全。该取舍用算力换体验与落库正确性，在单卡单进程原型下可接受。

### Q10. 两条技术线如何合成一个可演示系统？

微调解决语气强度与应答方式，记忆解决连续与证据；两件事在工程上解耦，只在生成前把记忆块拼进 system 时交汇。用户端提供流式对话与记忆开关，管理端提供匿名化会话浏览与分诊队列。记忆的关键不在「记得更多」，而在拒绝在写入时乱记。同 reader、只换记忆库的协议，用来证明差距来自记忆形态。部署上保持单卡串行与 SQLite，与当前原型形态一致。


## 三、常见误读澄清

### Q10d. 记忆 QA 约 92% 是否意味着线上用户体验已验证？

否。该数字来自 30 条受控长程弧、固定 reader、同协议对照的离线实验，证明的是记忆形态差异，不是大规模用户研究。评测集偏小，外部基准对照与更大规模实验仍属后续工作。

### Q10e. 分类器约 99.7% 验证准确率意味着什么？

意味着在构造的咨询/闲聊对照验证集上判别很准；不意味着真实开放域永远正确。正因为记忆不依赖该分类器门控，误判代价被限制在语气强度。

### Q10f. 「Trace 写路径零 LLM」是否等于系统全程不用 LLM 做记忆？

不等于。读路径可有查询规划 LLM；Profile 旁路可有提议 LLM。准确表述始终是：Trace（原文库主体）写入无 LLM；理解被限制在确认制旁路与查询时重建。

# 第二部分：长期记忆深挖

> 记忆子系统实现位于 `product_app/app/memory/`。方案细节见 `05`，对比实验见 `06`。

## 一、动机与形态假设

### Q11. 为什么需要长期记忆？长上下文能否替代？

长上下文解决的是「一轮能塞多少」，不解决「跨会话该给哪些」与「不该把什么当现状」。用户反复讲述学业压力、室友矛盾或失眠经历时，若每轮从零开始，共情再好也难以衔接。记忆系统的价值在于跨会话选择、原文证据、可控注入与隐私开关（用户可关记忆或一键遗忘）。即便上下文窗口足够大，「全塞进去」仍会受 Lost-in-the-Middle 影响，并让旧状态污染当前判断。

### Q12. 记忆存什么？为何坚持原文库？

现行 ER 对 Trace **只存原文**：每条消息按确定性规则分块、BGE-M3 向量化后写入 `memory_blocks`，不做抽取、不归纳、不概括。另有 Profile 旁路：用户确认过的稳定偏好（origin = explicit / confirmed）单独存表。

心理场景里，任何写时理解都带风险——把「这次考砸」改写成稳定负面标签，就是写时污染。原文库把理解后置到读路径：系统保证存得全、查得准，不保证「先归纳好」。漏掉一段旧经历最多是「没帮上忙」；错误归纳却可能把用户推向错误的自我认知。因此记忆不能只追求「记得更多」，更要避免「乱记」。

### Q13. ER 与 Mem0 一类写时抽取路线差在哪里？

分歧不在「要不要记忆」，而在「记忆是什么形态」。Mem0 属于写时抽取事实句再向量检索：每轮用大模型把对话压成事实句入库，检索时注入已被压缩的事实。ER 走相反路线：对话原文原样入库，检索时再按查询扩窗重建为一段完整经历。

| 维度 | 写时抽取（如 Mem0） | SoulHarbor ER |
|------|---------------------|----------------|
| 写入 | LLM 每轮抽事实、合并、覆盖 | 原文块确定性分块 + 向量化，Trace 零 LLM |
| 存储单元 | 事实句 / 语义标签 | 原文经历（多轮窗口） |
| 检索 | 向量搜事实 | hybrid → 扩窗重建 → 跨会话链 → 衰减感知 MMR（含相对新近性） |
| 注入 | 事实句列表 | 用户原文经历 + 日期来源 + consent 偏好 |
| 写时污染 | 结构性存在（抽取即改写） | Trace 侧结构性不存在 |

同协议对照（同一对话流、同一固定 reader、只换记忆库）下，QA 准确率约 **92% vs 64%**，内容 F1 约 **0.86 vs 0.48**，staleness 率约 **14% vs 43%**。差距来自记忆形态，而非答题能力。


### Q13b. 同协议对照时 Mem0 侧做了什么？

对照实验让 ER 与 Mem0 在**完全相同的对话流**上逐轮 ingest：ER 存原文块，Mem0 走其抽取与向量库路径。测试点双方共用固定 reader，只替换「该方法检索得到的记忆块」。因此报告的准确率差、staleness 差与内容 F1 差，应归因于记忆形态与检索注入内容，而不是答题模型或试题差异。协议细节与分册见 `06`。

### Q14. ER 是否就是「不抽取、全量存原文」的 RAG？

不完全是。单元不同：经典 RAG 的单元是文档切片，目标是「哪段文档相关」；ER 的单元是一段经历——anchor 命中后沿会话做自适应扩窗，把来龙去脉扩出来。重建是显式的：扩窗、同会话重叠合并、跨会话时序证据链、MMR 选窗选择（去冗余 + 时间桶多样性），这些都超出「取分最高的 top-k」。写侧哲学也不同：ER 不决定「哪句话值得记」，每条 user/assistant 消息都入库，理解完全后置。此外还有 consent Profile：哪些内容必须经用户同意才能成为结构化偏好，是记忆系统设计的一部分，经典 RAG 通常不包含这一维。

概括而言：RAG 侧重信息检索；ER 侧重经历还原与证据编排。

### Q15. 与相关工作中「存经历 / 分层记忆」一类做法如何对照？

相关工作中有一类做法强调保存经历原文、检索命中后再扩展邻域上下文（例如联想式 trace 记忆）；也有工作把上下文视为可分层管理的工作记忆，用阈值或中断机制在层间移动信息；另有评测工作把长期记忆拆成多种能力维来考察。ER 沿「保留经历、查询时扩展」方向推进，进一步用连续性得分做自适应边界、用衰减感知 MMR（含相对新近性）抑制冗余，并用时间排序注入支持整合类问题。系统刻意保持单机 SQLite，经历之间的关联在查询时动态建立，而不是预先固化为图结构；结构化画像必须经用户确认，不在写时自动生成。评测集按 detail / context / preference / current / integration / temporal 六维构建，与「按能力维报告」的做法一致，便于解读结构性差异。

## 二、写路径与读路径

### Q16. Trace 写路径如何设计？

Trace 写路径不做 LLM 决策：

1. **分块**：`chunker.py` 按句界切分、按约 150–350 字合并，过长整段保留上限约 500 字；  
2. **向量化**：每块 BGE-M3 编码，失败进入 `memory_embed_retry` 重试队列；  
3. **幂等入库**：按 `(message_id, chunk_index)` upsert，重发与回填不产生重复。

写时不抽取，从根上消除「该记不该记」的判断；成本转到读路径的 hybrid、扩窗与覆盖选择。

### Q17. Profile consent 与「Trace 写路径零 LLM」是否矛盾？

不矛盾，但表述需准确。记忆有两条独立写通道。

**Trace（主体）**：消息 → 确定性分块 → 向量化 → 原样入库。该通道无 LLM，也是检索注入的数据来源。

**Profile（旁路）**：唯一允许「理解」的地方，但必须以 consent 为前提。入口包括：用户显式说「记住…」（`explicit`）；助理提议后用户确认（`confirmed`）；更正与软删。LLM 提议器（`proposer.py`）攒批触发（默认未处理消息 ≥5 条或批次 ≥300 秒），每次最多抽 1 条候选，且须能在用户原文中对上；候选只进 pending（上限 8），确认前不算记忆。政策层拦截诊断词、人格标签、瞬时情绪前缀。注入时 active 偏好全量给出（上限约 30），不按查询过滤。

准确说法是「Trace 写路径零 LLM」；Profile 是旁路，且 LLM 产物永远先停在 pending。


### Q17b. 政策层具体拦截什么？

`profile/policy.py` 对诊断词（如抑郁症、双相、人格障碍等）、人格标签与瞬时情绪前缀做硬拦截，命中则拒绝写入。即使 LLM 提议器产出候选，也无法绕过该层成为 active 偏好。设计意图是：结构化偏好只表达「希望被如何支持」一类稳定约定，而不是给用户贴诊断词或人格标签。确认前的 pending 在用户说「可以/对」一类确认语后整批落库；「忘掉…」按关键词软删。

### Q18. 读路径（查询时 ER）如何组织？

```
查询规划（可选 LLM）：direct 或 split（≤3 子查询）；失败则整句 direct
 ↓
hybrid 召回：BGE-M3 cosine（assistant 块 ×0.55）+ 字级 unigram/bigram BM25 → RRF → anchor top-8
 ↓
ER 扩窗：沿会话向两边做自适应扩窗
  cont = 0.40×核心相似 + 0.22×已选区相似 + 0.18×实体 Jaccard
       + 0.10×位置邻接 + 0.10×查询词覆盖；≥0.28 纳入，连续失败 2 次停
  跨度≤12、bundle≤10
 ↓
重叠合并 → 特征重排 → 跨会话时序证据链
 ↓
MMR 选窗选择（top-6）→ <memory> 注入（只含 user 原文 + 全量 active 偏好）
```

混合召回中，字级 BM25 对中文人名、专名与数字敏感，与 dense 互补。ER 用自适应扩窗决定扩多少，避免固定 ±N 窗口切碎上下文或塞入无关寒暄。衰减感知 MMR（含相对新近性）保证去冗余与时间桶多样性。跨会话链把分散在多周的经历串起，以支持整合类问题。
设计取舍可概括为：Trace 写时不理解、读时才理解；混合召回互补 dense 与字级词法；自适应扩窗替代固定窗口；衰减感知 MMR（含相对新近性）替代纯 top-k；跨会话链服务整合类问题。注入时全局约 1600 token 预算，超预算整行裁剪（丢更不相关的经历窗，不撕裂保留下来的证据）。除可选查询规划外，检索主体由代码编排。


### Q18b. 自适应扩窗（一主一补）在工程上对应什么直觉？

主项是候选与 anchor 的余弦相似度：语义仍属同一段经历才扩进去。补充项是「位置够近且共享实体」：承接句、短反馈往往 embedding 弱，但「她/小王/空调」一类共指仍标明同一件事。连续失败两次停扩，避免一路吞进无关寒暄。阈值与邻接距离是工程启发式；主消融报告的是选择器新近性，而非逐项网格搜索。

### Q18c. Formatter 注入时如何处理超长窗？

优先保留与 anchor、查询相关的 user 话轮；每窗有条数上限。极端超长时用 BGE 句子级相似度定位相关局部，并保留邻句；嵌入失败时保尾部（结论常落在末尾）。全局预算用整行裁剪：丢掉的是整段更不相关的经历窗，避免把留下来的证据撕碎。system 前缀中的冲突裁决句把「记忆可能过时」交给当前话语。

### Q19. 查询规划器做什么？为何不用正则枚举比较句式？

规划器（`retrieval/router.py`）把用户当前句翻译成检索用查询，输出严格 JSON：`direct` 或 `split`（最多 3 个子查询）。temperature=0.0，要求保留人物、事件、时间、阶段等锚点，不添加用户未提事实，不用「检索/记忆」等系统词；拿不准时一律 `direct`。解析失败或无 LLM 时回退整句 direct。比较与多目标表达的开放性超出规则可枚举范围；失败成本为零，故用受约束的结构化输出替代正则。

### Q20. 语义检索为何用按用户 FAISS 缓存而非外置向量库？

向量存在 SQLite（`memory_block_embeddings`）。FAISS 是按用户粒度的进程内缓存（`store/ann_index.py`）：`IndexFlatIP` 对 L2 归一化向量做内积近似余弦；用 `(块数, 最大 chunk_id, 最大 embedding 更新时间)` 指纹判失效，变了才重建。FAISS 不可用时回退 Python 余弦扫描。SQLite 是唯一事实源，缓存只加速、不改变结果。单机原型无需独立向量库；单用户块数很大或多实例部署时，再考虑 ANN 升级或外置索引。

### Q21. 衰减感知 MMR（含相对新近性）的消融说明什么？

终版选择器用 Decay-aware MMR，并加入相对新近性与未见周桶奖励。去掉新近性后同协议 QA 约 84.4%、staleness 约 43%；加回后约 92.2% / 14%。说明「选哪几段经历注入」本身是建模对象：只做相关−冗余时，早期高相关旧状态容易挤掉终态窗。

### Q22. 抗 stale 如何做？为何不做写时过期状态机？

「上周冷战、这周已和好」若仍被当作现状注入，即为 stale 伤害。系统刻意不做写时生命周期标记，因为「过期」本身也是写时判断、也会判错。抗 stale 放在读侧：只选与查询相关的经历；MMR 去冗余并兼顾相对新近性/周桶；token 预算整行裁剪；system 前缀明确「与用户此刻说法冲突时以当前说法为准」。评测中 current_state 类约 0.87 vs Mem0 约 0.60，staleness 率约 14% vs 43%。temporal 类仍是共同短板。

### Q23. 为何入库含助理话轮，注入却只取 user 原文？

助理话轮入库，是为了扩窗时判断语义邻接；没有它，许多语义桥会断。Formatter 注入时只保留 user 原文，是为了避免把咨询师的反映式倾听当成用户亲口事实，并在有限预算下优先保留用户证据。

### Q24. 记忆块注入位置有什么坑？

Qwen chat template 对多条 `role=system` 不稳定：多条 system 可能被合并，后放的记忆块容易被忽略。表现是检索日志有记忆，模型却像没看见。现行做法是在 `service.build_chat_context` 中把 `<memory>` 作为一条 system 放在摘要之后、未摘要原文之前，并附行为级前缀：说明其为历史背景、无关可忽略、冲突以当前说法为准、禁止补充检索结果之外的事实。离线对比中，注入块形式与位置是单变量改进较明显的一处。

## 三、评测协议与结果解读

### Q25. 如何证明记忆系统有效？协议如何隔离变量？

对比实验最忌「换方法也换答题模型」。协议刻意固定答题能力：用外部模型按规范合成 30 条长程咨询弧（每名学生连续数周、多个会话），每条配 3 道测试题与应记/应忘事实集；ER 与 Mem0 在同一对话流上逐轮写入；延迟测试点用**同一个固定 reader** 只接收「该方法的记忆检索块 + 试题」作答。MCQ 精确匹配；开放题按参考答案判定；内容 F1 将最终记忆库与应记/应忘集比对。

主结果（跑次见 `evaluate/memory/runs/`）：

| 方法 | QA 准确率 | Staleness 率 | 内容 F1 |
|------|-----------|--------------|---------|
| ER | ≈92% | ≈14% | ≈0.86 |
| Mem0（同协议） | ≈64% | ≈43% | ≈0.48 |

主要逐类对照（约）：

| 能力维 | ER | Mem0 |
|--------|-----|------|
| context_recall | 0.93 | 0.47 |
| cross_session_integration | 0.93 | 0.60 |
| current_state | 1.0 | 0.60 |
| preference_recall | 0.93 | 0.73 |
| detail_recall | 0.93 | 0.87 |
| temporal_sequence | 0.73 | 0.60 |

差距集中在共现上下文、跨会话整合、最新状态与偏好；细节召回双方都强；时序是共同短板。这与「原文库 + 查询时重建」的结构性预期一致。协议与分册见 `05`、`06`。

### Q26. 记忆子系统的成本结构如何？

Trace 写路径零 LLM，每轮不为记忆付生成调用。读路径唯一可选 LLM 是查询规划（约 256 token、temperature 0），其余为代码编排。存储为单文件 SQLite，语义侧有按用户 FAISS 缓存。相对写时抽取路线，省去每轮抽取调用与外置向量库运维；代价是读路径逻辑更复杂，块数增大后需要更强的 ANN。

## 四、逐类解读、演进与叙事

### Q26a. 逐类结果如何对照设计假设？

在同协议下，ER 相对 Mem0 的优势并不均匀分布，而与「保留共现、跨会话整合、抗 stale」高度对齐：context_recall 约 1.0 vs 0.47；cross_session_integration 约 0.93 vs 0.60；current_state 约 0.87 vs 0.60；preference_recall 约 1.0 vs 0.73；detail_recall 双方都强（约 1.0 vs 0.87）；temporal_sequence 约 0.73 vs 0.60，是共同短板。内容 F1（应记/应忘）约 0.86 vs 0.48，直接度量记忆内容质量。跑次文件见 `evaluate/memory/runs/`（例如 ER `qa_er_20260802_210915`，Mem0 `archive/eval_memory_runs_pre_final_20260802/qa_mem0_20260731_135743`）。

逐 probe 的另一汇总口径（见 `06`）同样显示 context / integration / current 拉开差距，temporal 仍弱。后续若加强时序，应优先在证据链中显式时间锚，而不是回到写时过期状态机。

### Q26b. 设计演进说明了什么？

ER 并非一次定稿。早期写时抽取即便工具调用指标尚可，仍无法从结构上消灭误记。随后尝试分层记忆与写时调和，根因未变：底层仍在写入时改写用户。转向存原文并优化读路径后，方向才清晰；终稿进一步删除写时 trace 调和，使 Trace 成为零 LLM 原文入库，Profile 保留确认制，读路径补上扩窗、MMR 与相对新近性。中间态在 `archive/`。记忆侧真正改进的不是「检索更花哨」，而是把理解从写入挪到查询，并从结构上降低写时污染。

### Q26c. 论文式叙事如何概括记忆线？

背景：跨会话需要记忆；写时抽取在心理场景代价高。痛点：错误标签会反复注入并自我强化。方案：Trace 原文入库 + 查询时 ER 重建 + consent Profile。评测：同 reader 只换记忆库，QA 约 92% vs 64%，内容 F1 约 0.86 vs 0.48，staleness 约 14% vs 43%；新近性消融约 +8 个点（84%→92%）。时序维仍相对偏弱；抗 stale 依赖读路径选择而非写时生命周期；部署保持单机 SQLite。

# 第三部分：训练与对话评测

## 一、训练流水线

### Q27. 训练主线分几步？

| 阶段 | 数据 | 目的 |
|------|------|------|
| 继续预训练 PT | EmoLLM 心理问答片段约 2.4 万条纯文本 | 适配心理中文 token 分布 |
| 指令微调 SFT | 约九成 SoulChatCorpus + 约一成 EmoLLM 多轮，共约 2 万条 ShareGPT | 学咨询节奏下的应答方式 |
| DPO | 3000 对偏好数据 | 压制空泛、欠共情、敷衍、说教 |
| 意图分类 | 3000 条咨询/闲聊对照（正负 1:1） | 训 MacBERT-base 二分类 |

框架为 LLaMA-Factory QLoRA 4-bit；全链路 LoRA rank=8、α=16，与线上 `adapter_config.json` 一致。线上 chat LoRA 即 DPO 产物。训练主线为 PT→SFT→DPO。数据构建见 `04`。

数据出处：SoulChatCorpus（Chen et al., Findings of EMNLP 2023）；LCCC（Wang et al., NLPCC 2020，用于闲聊负样本等）；EmoLLM（开源项目语料，非顶会论文）。

### Q28. 为什么先 PT 再 SFT？

通用基座在百科、代码、新闻上分布偏多，对心理咨询口语化表达相对陌生。PT 用领域文本继续做因果语言建模，降低心理语料上的困惑度，再做 SFT 更易收敛到正确格式与风格。当前没有单独报告 PT 消融；若补做，应在心理 unseen 语料上对比 PT 前后 perplexity，并检查通用语料是否出现明显灾难性遗忘。

### Q29. DPO 数据与训练如何组织？

Prompt 池从 SoulChat 等多轮语料切「上文 + 当前用户句」，并与已进主 SFT 的样本互斥以防泄漏虚高。Chosen 取语料中较好的助手回复；Rejected 由 MiniMax-M2.7 按「仍相关但更敷衍/欠共情」指令合成，再经质检过滤。训练从 SFT adapter 继续，`pref_beta=0.1`，学习率 5e-6，1 epoch。DPO 把含 KL 约束的 RLHF 最优策略写成闭式后，用策略与 reference 的 log 比直接优化偏好，不必显式训练 reward model，也不跑 PPO 在线采样环。

### Q29b. rejected 合成为何要质检？

若合成负样本「空泛但流畅」甚至质量反超 chosen，DPO 会学反。质检脚本过滤明显不可用负样本，并尽量保持 topic 均衡。DPO 数据与主 SFT 互斥，避免同一上下文既当 SFT 监督又当偏好对导致虚高。β=0.1 偏保守，配合低学习率，适合在已对齐话术上做小幅偏好推动。

### Q30. DPO 后 BLEU 略降如何解释？

在 SoulChatCorpus seen/unseen 各 1000 条上（jieba 分词后词级 BLEU/ROUGE）：

| 模型 | BLEU-1 | ROUGE-1 | ROUGE-L |
|------|--------|---------|---------|
| base（裸 Qwen3-14B） | 13.23 | 20.52 | 15.04 |
| sft | 29.56 | 30.65 | 24.64 |
| dpo（线上 chat LoRA） | 27.91 | 31.49 | 24.44 |

SFT 相对 base 的跃升说明领域对齐有效。DPO 的 BLEU 略低于 SFT，而 ROUGE-1/2 略高或持平——符合「优化偏好、表达更自然多样时，与单一参考答案的字面重合可能下降」。心理对话没有唯一标准答案，自动指标只适合相对比较；共情与偏好胜率若需结论，应另做人工或 LLM-as-judge。完整 BLEU-1～4 与 ROUGE-1/2/L 见 `02` 与 `evaluate/dialogue/`。

### Q31. LoRA / QLoRA 超参如何设定？

选 QLoRA 是为了单卡承载 14B；用同一份 chat LoRA 的 scale 区分场景，而不是多 adapter。全链路统一 r=8、α=16，`lora_target=all`。学习率阶梯大致为：PT 5e-5 → SFT 2e-5 → DPO 5e-6。越往后越保守，避免冲掉前序阶段已学好的话术。


### Q31b. 为何全链路统一 rank 与 α？

链式续训（PT→SFT→DPO）各自保留独立 LoRA 目录，但超参形状一致，便于对比与加载。统一 α/r 使不同阶段的有效增量尺度可比；线上 adapter 与 `train/configs/*.yaml` 对齐，减少「训练一套、部署另一套」的静默偏差。`lora_target=all` 覆盖注意力与 FFN 相关投影，心理对话风格变化往往不只落在注意力。

### Q32. 为何最终放弃写时抽取？

早期曾尝试写时抽取与分层调和。即便工具调用类指标尚可，只要写入时「理解」，就一定会偶尔写错，且错误标签会长期留在库里。心理场景误记代价高于漏召回。终态 ER 将 Trace 写路径收敛为零 LLM 原文入库；consent Profile 才允许极少量结构化偏好；读路径补上自适应扩窗、衰减感知 MMR（含相对新近性）与跨会话链。中间态快照保留在 `archive/`，线上仅描述 ER 终态。详见 `00` 与 `05`。

### Q33. 分类器训练与职责再确认

MacBERT-base 在 3000 条咨询/闲聊对照上训练（正负 1:1，按字长对齐），验证准确率约 99.7%。选 base 而非 large：任务为简单二分类，省下的显存留给 14B 与 BGE-M3。分类器不控制记忆开关，只调节 LoRA scale。

# 第四部分：技术原理

> 下列推导服务于理解本项目所用方法；结合第三部分超参与评测阅读。符号在各小节首次出现时说明。

## A0. 符号约定与易混旋钮

线性层即 $y = Wx + b$，其中 $W \in \mathbb{R}^{k\times d}$。微调是在预训练权重上继续训练；全量更新 14B 参数在单卡上不可行，故采用 PEFT，只训练少量参数。矩阵的秩是线性无关行/列的最大数目；低秩指秩远小于矩阵维度。

LoRA 取 $A \in \mathbb{R}^{r\times d}$、$B \in \mathbb{R}^{k\times r}$（$r \ll \min(d,k)$），则 $BA$ 与 $W_0$ 同形，可与 $W_0$ 相加。

自回归 / CLM 损失：

$$\mathcal{L}_{\mathrm{CLM}} = -\frac{1}{T}\sum_t \log p_\theta(w_t \mid w_{<t})$$

KL 散度 $\mathrm{KL}(P\|Q)=\sum_x P(x)\log\frac{P(x)}{Q(x)}$ 不对称，衡量两分布差距。

五个易混旋钮：

| 名字 | 出处 | 含义 |
|------|------|------|
| LoRA α | LoRA 论文 | 训练时 $\Delta W=\frac{\alpha}{r}BA$ 的缩放系数 |
| LoRA r | LoRA 论文 | 低秩瓶颈维度 |
| 推理 scale | 运行时 `set_scale` | 推理时额外乘的 LoRA 强度 |
| DPO β | DPO / RLHF | KL 约束强度，与 LoRA α 无关 |
| lr | 优化器 | 参数更新步长 |

三者独立：α/r 决定训练时 $\Delta W$ 量级；β 决定策略离 reference 多近；scale 决定运行时 LoRA 影响多强。

本项目常用数字：Qwen3-14B 约 $14.8\times10^9$ 参数；BGE-M3 dense 维 1024；记忆注入约 1600 token / 至多 6 个 bundle / bundle 内消息上限约 10；摘要触发约 3000 token；assistant 召回降权 0.55；咨询/闲聊 scale 0.7/0.3；chat/summary/结构化输出温度约 0.6/0.3/0.0；DPO β=0.1；Profile 攒批 5 条或 300 秒、每次最多 1 条提议、pending 上限 8、全量注入偏好上限约 30。

## A. LoRA（Low-Rank Adaptation）

LoRA（Hu et al., 2021）冻结预训练权重 $W_0$，只训练一对低秩矩阵：

$$W = W_0 + \frac{\alpha}{r}BA$$

| 符号 | 含义 | 形状 | 可训练 |
|------|------|------|--------|
| $W_0$ | 基座权重 | $\mathbb{R}^{k\times d}$ | 否 |
| $A$ | 下投影 | $\mathbb{R}^{r\times d}$ | 是 |
| $B$ | 上投影 | $\mathbb{R}^{k\times r}$ | 是 |
| $r$ | 秩 | 整数 | 调参 |
| $\alpha$ | 缩放系数 | 整数 | 调参 |

Aghajanyan 等人（2020）指出：大模型在许多任务上只需远小于全参数空间的内在维度即可接近全量微调性能。LoRA 由此假设 $\Delta W$ 落在低维子空间。$r=8$ 是本项目从经验区间选取的够用设置。

以单层 $d=k=3584$、$r=8$ 为例：全量参数约 $3584^2\approx1.28\times10^7$；LoRA 约 $2\times r\cdot d=57344$，约占 0.44%。14B 量级模型上可训练增量通常在千万级，相对全量约省两个数量级以上。若粗略按数百个线性层计，可训练参数总量仍远小于全量 14B。rank 选择上：$r$ 过小易欠拟合；$r=8\sim16$ 为常见区间；$r\ge128$ 接近丧失 PEFT 优势。本项目未做系统的 rank 扫描，而是在算力与稳定性约束下取经验下限附近的统一值。

PEFT / LLaMA-Factory 默认 $A$ 高斯随机、$B$ 置零，故训练起点 $\Delta W=\mathbf{0}$，行为等于基座。$A$ 置零而 $B$ 高斯在理论上也可行，关键是初始 $\Delta W=0$；两者皆随机会破坏起点，两者皆零则无法学习。

对 $\Delta W=\frac{\alpha}{r}BA$，梯度为：

$$\frac{\partial\mathcal{L}}{\partial B}=\frac{\alpha}{r}\cdot\frac{\partial\mathcal{L}}{\partial(\Delta W)}\cdot A^\top,\quad
\frac{\partial\mathcal{L}}{\partial A}=\frac{\alpha}{r}\cdot B^\top\cdot\frac{\partial\mathcal{L}}{\partial(\Delta W)}$$

计算量从 $O(kd)$ 降到 $O(r(k+d))$。工程上常保持 $\alpha/r$ 稳定（本项目 $\alpha=2r$），换 rank 时梯度量级更易复用学习率。chat adapter 为 r=8、α=16、dropout=0。

运行时结构：

```
model (Qwen3-14B base, frozen)
└── LoraLayer
    └── adapter "chat": (A, B)
        scale ∈ {0.7 咨询, 0.3 闲聊}；摘要 disable_adapter
```

`set_adapter("chat")` 激活；`set_scale("chat", s)` 改乘数。切换为 in-place，无需重载权重。

$r$ 过小易欠拟合；$r=8\sim16$ 为常见 PEFT 区间；$r$ 过大则接近全量、丧失参数效率。本项目全链路统一 r=8，便于链式续训与线上一致。

## B. QLoRA 与 4-bit 量化

QLoRA（Dettmers et al., 2023）= 4-bit 量化基座 + LoRA，常用组件包括：NF4 数据类型、Double Quantization（对 scale 再量化）、Paged Optimizer（优化器状态可 page 到 CPU）。

线性量化将 $[x_{\min},x_{\max}]$ 切成 $2^n$ 个 bin。预训练权重近似 $\mathcal{N}(0,\sigma^2)$：等距 INT4 在高密度区间浪费分辨率。NF4 按标准正态在 $[-1,1]$ 上取等概率分位（含 0），使各 bin 概率质量更均匀，量化误差更小。 Double Quantization 进一步压缩量化参数本身占用的显存；Paged Optimizer 在峰值时把优化器状态页到 CPU，缓解训练峰值。三者共同支撑「单卡训 14B」这一工程目标。

粗略显存对照（数量级）：

| 方案 | 权重 | 梯度 / Adam | 量级 |
|------|------|-------------|------|
| 全量 fp16 | ~28 GB | 梯度与 Adam 状态可达百 GB 级 | 单卡不可行 |
| QLoRA | ~7 GB（NF4） | 主要服务 LoRA | 可落在单卡可接受范围 |

数据流：磁盘上的 NF4 权重加载后，前向按 block 反量化到 fp16 做矩阵乘；反向梯度只传到 LoRA 的 $A$、$B$；AdamW 只更新 LoRA。**4-bit 用于存储冻结基座；计算在 fp16；优化器只服务 LoRA。**

量化主要损失细枝末节方向，主成分信号相对保留；文献报告 4-bit NF4 相对高精度 perplexity 上涨通常在小幅百分点量级。本项目训练配置启用 fp16 AMP；推理侧 `bnb_4bit_compute_dtype=float16`。相对 GPTQ/AWQ 等训练后量化路线，本项目训练与推理共用 BNB 4-bit，工程更简单；若未来改为高并发服务部署，再评估 PTQ 引擎，本文不把它写成既定上线路程。

## C. SFT（Supervised Fine-Tuning）

$$\mathcal{L}_{\mathrm{SFT}}(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(y_t\mid x,y_{<t})$$

训练用 teacher forcing 喂真实前缀，各位置可并行计损失；推理用自采样前缀，训练/推理分布不一致，即 exposure bias。非 assistant 段 label 设为 `-100`（`CrossEntropyLoss.ignore_index`），只学「怎么答」（LLaMA-Factory `train_on_prompt=false`）。框架对 logits 与 labels 做标准 shift。

| 阶段 | 数据形态 | 目标 |
|------|----------|------|
| PT | 连续文本 | 适配领域 token 分布 |
| SFT | instruction / 对话 | 学「怎么答」 |
| DPO | chosen vs rejected | 学「哪种更好」 |

## D. DPO（Direct Preference Optimization）

DPO（Rafailov et al., 2023）把含 KL 正则的 RLHF 目标写成闭式最优策略后，发现 reward 可用策略与 reference 的 log 比表达，从而不必显式训 RM、不跑 PPO：

$$\mathcal{L}_{\mathrm{DPO}}(\theta)=-\log\sigma\!\Big(\beta\big[\log\frac{\pi_\theta(y_w|x)}{\pi_\text{ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_\text{ref}(y_l|x)}\big]\Big)$$

推导轮廓：RLHF 目标（含 KL）→ 拉格朗日得 $\pi^\ast(y|x)\propto\pi_\text{ref}\cdot\exp(r/\beta)$ → 反解 $r(x,y)=\beta\log(\pi^\ast/\pi_\text{ref})+\beta\log Z(x)$ → 代入 Bradley-Terry，差分时 $Z(x)$ 抵消 → 得到上式。

直觉上，Bradley-Terry 用 $\sigma(r_i-r_j)$ 描述两两胜率；DPO 跳过显式估计标量 reward，直接优化相对 margin。$\beta$ 大则约束强、更保守；$\beta$ 小则偏好学得更狠但易漂移。实现中 $\beta$ 还影响 sigmoid 饱和区。优化目标是最大化

$$\mathrm{margin}=\log\frac{\pi_\theta(y_w|x)}{\pi_\text{ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_\text{ref}(y_l|x)}$$

chosen/rejected 绝对概率可以同时下降，只要相对 reference 的 margin 上升即可。

Reward hacking 指策略钻奖励漏洞而未满足真实意图：超长骗 ROUGE、套话骗流畅、一味认同骗偏好。心理场景尤需警惕强化错误认知。缓解手段包括对抗性偏好数据、KL 约束、长度/重复惩罚、人机混合评测等。

相对 PPO 式 RLHF，DPO 只需 policy+reference，离线偏好对即可训，与单卡 QLoRA 更匹配。限制在于：偏好被塌缩成成对比较；多维 reward（安全、简洁等）不易同时表达；离线分布外反馈学不到。变体上，IPO 对噪声偏好更稳；KTO 可用好坏标签；ORPO/SimPO 可省 reference。本项目选 DPO，主要覆盖「更共情、少敷衍」这一维。

## E. 继续预训练 PT 与学习率阶梯

PT 在通用基座上用领域文本继续 CLM：与 SFT 公式同形，但对全 token 计损失、无角色 mask，目的是塑分布而非学任务格式。

| 阶段 | 典型 lr | 理由 |
|------|---------|------|
| PT | 5e-5 | 显著搬动领域分布 |
| SFT | 2e-5 | 学指令与对话格式 |
| DPO | 5e-6 | 偏好微调，更保守 |

规律：越往后越低，防止冲掉前序能力；LoRA 可用比全参更大的 lr。对话主线是「PT 拉分布 → SFT 学格式 → DPO 做偏好」。

## F. MacBERT 意图分类

MacBERT（Cui et al., Findings of EMNLP 2020）为面向中文的 BERT 变体。本项目在 `chinese-macbert-base` 上加分类头做咨询/闲聊二分类。选 base 而非 large：任务简单，验证准确率约 99.7%，省下显存留给 14B 与 BGE-M3。线上优先按 `trainer_state.json` 的 best checkpoint 加载。

预训练侧用同义词替换缓解 MLM 与微调 mismatch（约 80% 同义替换、10% 随机、10% 保持），并含 WWM、SOP 等改进。小编码器快、稳、可离线评测，与生成解耦。

$$\mathcal{L}=-\frac{1}{N}\sum_i\big[y_i\log\hat p_i+(1-y_i)\log(1-\hat p_i)\big],\quad
\hat p_i=\sigma(W_\text{head}\cdot h_{[\mathrm{CLS}]}+b)$$

## G. ER 检索与重建（公式级）

### G1. Hybrid 召回与 RRF

语义分 $\mathrm{sem}=\cos(q,c)$，assistant 角色块乘 0.55。词法侧对中文做单字与相邻二元组 BM25。排名融合：

$$S_{\mathrm{rrf}}(d)=\sum_{r\in\{\mathrm{rank}_s(d),\mathrm{rank}_l(d)\}}\frac{1}{60+r}$$

取 anchor top-8 进入扩窗。字级 BM25 对人名、专名、数字敏感，与 dense 互补。

### G2. 自适应扩窗

对 anchor 沿会话向两边判断是否纳入同一段经历：

\[
\operatorname{Expand}(c)=1
\quad\text{iff}\quad
\cos(\mathbf e_c,\mathbf e_a)\ge\tau
\;\text{or}\;
\big(\mathrm{dist}(c,W)\le d \land E(c)\cap E(W)\neq\varnothing\big)
\]

默认 \(\tau=0.40\)，\(d=2\)；连续失败 2 次停止；跨度 ≤12、窗内 ≤8。短承接句靠实体逃生口纳入。固定 ±N 窗口易切碎经历或塞入寒暄；该规则按「语义连续或实体承接」定界。

### G3. 衰减、新近性与 MMR 选窗

窗强度衰减：

\[
D_W(t)=w_{\min}+(w_W-w_{\min})e^{-\Delta t/\tau_d}
\]

有效相关 \(R_{\mathrm{eff}}=R_{\mathrm{decay}}+\beta\cdot\mathrm{recency}+\mathrm{week\_bonus}\)，其中 \(\mathrm{recency}\) 相对本轮候选池最新时间戳计算。再做 MMR：

\[
W^*=\arg\max_{W\notin\mathcal S}\Big[\lambda R_{\mathrm{eff}}(W)-(1-\lambda)\max_{S\in\mathcal S}\operatorname{sim}(W,S)\Big]
\]

冗余用字 bigram Jaccard。选中后按时间升序注入；注入窗做一次使用强化 \(w^+=w^-+\eta(1-w^-)\)。消融：无新近性 ≈84.4% → 含新近性 ≈92.2%。

### G4. 跨会话组织

不再显式计算 `chain_id`。跨会话整合依赖：多会话 hybrid 召回 → MMR 去重选窗 → 时间排序注入。

### G5. 写侧原则与查询规划

Trace 写时不抽取：抽取即改写，是过度固化的来源；读路径按需重建把「该记什么」后置到每次查询。唯一写理解在 Profile：LLM 提议进 pending，须确认才 active，政策层再拦截。

查询规划器输出 `{"mode":"direct|split","queries":[...]}`，temperature=0.0，≤256 token；要求单目标、保留锚点、不添加未提事实；失败回退整句 direct。不用正则枚举比较句式，因语言开放性超出规则覆盖。

### G6. FAISS 缓存与注入形态

写入时向量存 SQLite；读路径默认按用户 `IndexFlatIP`（L2 归一化后内积≈cosine），指纹 `(块数, max_chunk_id, max_embed_updated_at)` 判失效。超额取回再过滤本轮 message_id；FAISS 不可用则 Python 余弦扫描。SQLite 是唯一事实源。

注入尽量整段 user 原文以保留来龙去脉（context 类约 0.93 vs Mem0 约 0.47）；每窗最多约 6 条 user 话轮；极端超长才用句子级相似度定位局部；全局约 1600 token，超预算整行裁剪。只取 user，避免把咨询师复述当用户事实。

### G7. 为何不建知识图谱 / 为何长上下文仍不够

经历关联在查询时由游走与证据链动态建立，而非写时固化边；单机 SQLite + 向量 JSON + FAISS 即可。图结构若需要，可从原文块离线构建而不改变写路径哲学。

长上下文解决容量，不解决跨会话选择与 stale。全塞入会稀释注意力并让旧状态污染当前判断；ER 是「在上下文里放什么」的决策器，不是长上下文的替代品。

## H. 与 SoulHarbor 直接相关的补充问答

### H1. 为何本地 BGE-M3 而非云端 Embedding？

中文检索表现、数据不出境、离线推理、无按 token 计费。官方 dense 维 1024，在表达力与存储之间折中。相对每次 LLM forward 的 KV cache，单用户记忆向量占用通常可忽略。

### H2. 为何读路径不以 LLM 重排为主？

LLM 重排成本高，且会再次把「理解」引入读路径。现行为 hybrid + 自适应扩窗 + Decay-aware MMR；规划失败则 direct。

### H3. 为何不靠 prompt 让模型自己决定记什么？

写时判断即抽取路线，心理场景误记代价高。ER 结构上取消该判断；仅 consent Profile 允许极少结构化偏好。

### H4. PT 有没有消融？

当前没有单独报告 PT ablation。理论上应在心理 unseen 语料上看到 perplexity 下降，并检查通用语料是否明显变差。本项目将 PT 作为领域适配的工程惯例纳入流水线。

### H5. seen / unseen 切分与数据泄漏

对话评测按是否进入训练分布划分。更严格做法应按主题、时间或用户切分；按 id 随机切可能残留上下文泄漏。解读自动指标时需保留该保留。DPO prompt 池与主 SFT 互斥，是另一处防泄漏措施。

### H6. 开放性生成如何评？

BLEU/ROUGE 与人类共情判断不对齐；本项目用其做 base→sft→dpo 相对比较。Elo、人工量表、LLM-as-judge、用户行为指标均未系统展开。记忆侧用同 reader 协议隔离答题能力，比对话自动指标更硬。

### H7. 幻觉与 Lost in the Middle

幻觉来源包括数据噪声、解码随机性、长尾知识与指令冲突等。缓解：边界 system prompt、记忆注入约束事实来源、较低温度的结构化输出；幻觉不能根除。Lost in the Middle 指长 prompt 中间利用率差；本项目靠注入位置、衰减感知 MMR（含相对新近性）与 token 预算缓解。

### H8. 失败降级（与实现一致）

向量化失败进 `memory_embed_retry`，对话不受阻；摘要失败记日志；检索失败注入空块；生成失败且无 chunk 时不写库。对话主路径尽量可继续；记忆写入与摘要在后台完成。流式路径用取消事件与 worker join 做有限清理。

### H9. 推理侧的实际瓶颈（原型事实，非生产目标）

单卡 RLock 串行 GPU；读路径可选查询规划会拉长首包时间；decode 阶段访存与 KV cache 在单并发短输入下通常不是主瓶颈。这些是原型测量与结构事实，不把它外推成并发 SLA 或扩容承诺。

### H10. 混合精度要点

fp16 存在下溢、舍入与溢出风险，常配合 fp32 master weight、loss scaling，以及 LayerNorm/Softmax 等在较高精度上计算。本项目训练 yaml 启用 fp16；QLoRA 计算 dtype 为 float16。半精度/量化「不至于让模型不可用」的原因，是信号主要落在高幅值主成分上，而非所有比特同等重要。

---


### H11. Prefill / Decode 与 KV Cache（结合本项目）

推理通常分 Prefill（处理输入，算力相对密集）与 Decode（逐 token 生成，访存相对密集）。KV Cache 缓存历史 token 的 K/V，避免每步重算，显存大致随层数、序列长度、batch 与头维度增长。单并发、中等长度输入时，本项目主瓶颈更常来自串行 GPU 占用与可选查询规划，而非 KV 本身撑爆。记忆注入增加输入长度，对首包时延的影响通常小于「多一次规划 LLM 调用」。

## 一、创新点与问题定义

### R1. 用一句话定义你的研究问题。

在校园心理支持对话中，如何同时解决「基座模型不会好好倾听」与「跨会话记忆容易乱记」这两类结构性问题：前者靠领域微调把说话方式对齐到倾听任务，后者靠原文入库加查询时经历重建，让系统在跨周衔接经历时尽量不把瞬时情绪固化成错误标签。

展开一层：第一类问题来自通用助手默认目标（答疑、给方案、保持流畅）与倾听任务不一致，表现为空泛安慰、说教或敷衍；第二类问题来自主流记忆在写入时把对话压成事实句，心理场景下一次考试焦虑或一句气话可能被固化成稳定标签，并在后续轮次反复注入。因此研究问题不是「做一个能聊天的系统」，而是在可复现的单卡原型上，把「怎么说」与「怎么记」同时做成可评测方法，并分别相对裸基座与相对写时抽取基线给出证据。

若只能说二十个字，可压缩为：「让倾听模型会好好说，也让记忆系统不乱记。」后面再补一句评测分流：说看 BLEU/ROUGE 相对 base，记看同 reader 换库的 QA/staleness/F1。

### R2. 两条创新点应如何表述，才像研究贡献而不是产品功能清单？

对话线贡献：在 Qwen3-14B 上完成 PT→SFT→DPO 链式对齐，并用独立 MacBERT 二分类器按咨询/闲聊调节**同一份** chat LoRA 的推理 scale（约 0.7 / 0.3），使语气强度与权重文件解耦，而不是再训第二份 adapter。训练用 LLaMA-Factory QLoRA 4-bit，全链路 LoRA r=8、α=16；PT 约 24443 条心理纯文本，SFT 约 20000 条 ShareGPT（约九成 SoulChatCorpus + 约一成 EmoLLM），DPO 3000 对偏好；线上 chat LoRA 即 DPO 产物。

记忆线贡献：提出并实现 ER（Experience Rebuild）——Trace 写路径零 LLM 原文入库，读路径经 hybrid 召回、连续性扩窗、多窗召回与时间排序与衰减感知 MMR（含相对新近性），在查询时把原文重建为可用经历证据；稳定偏好仅经用户确认进入 Profile，政策层拦截诊断词、人格标签与瞬时情绪前缀。两条线工程解耦，只在生成前把 `<memory>` 拼进 system 时交汇。

评测表述必须分开，避免用产品功能冒充证据：对话线报告相对裸基座的 BLEU/ROUGE（BLEU-1：13.23→29.56→27.91）；记忆线在固定 reader、只换记忆库协议下报告 QA / staleness / 内容 F1（约 92% / 14% / 0.86 对 Mem0 的 64% / 43% / 0.48）。这样创新点落在「问题—方法—证据」闭环。

口述时可先报贡献句，再立刻跟证据句，避免停在口号。例如：「对话线是 PT→SFT→DPO 加路由 scale；证据是 BLEU-1 从 13.23 到 29.56。」「记忆线是原文库加查询时重建；证据是同 reader 下 92% 对 64%。」

### R3. 这算算法创新，还是系统/问题驱动创新？怎么答更稳？

更稳妥的表述是**问题驱动的系统与方法创新**，而不是宣称发明全新损失或全新骨干。对话侧把续训、指令微调、DPO、PEFT、小分类器对准倾听任务，并做出「一份 LoRA + 路由 scale」的职责设计；记忆侧改变的是记忆单元与读写时序——理解从写入后置到查询，经历窗替代压缩事实句。

这类贡献常见于系统方向：新意在约束下的问题重构、可核对对照协议与消融。含新近性相对无新近性约 +8 个百分点，同 reader 下相对 Mem0 QA 约 +27 个百分点，说明形态与选择器假设可被检验。应避免两种极端：把工程拼装说成「全新算法」，或因为用了已知组件就否认贡献。

如果老师坚持问「有没有公式创新」，可以回答：自适应扩窗、衰减感知 MMR（含相对新近性）与时间排序注入有可写的打分式（见第四部分 G），但贡献定位仍是问题驱动方法，而不是新损失。把公式当支撑，不当唯一卖点。

### R4. 老师说「这不新，微调加 RAG 到处都是」怎么回应？

先同意前提：微调与检索增强作为名词确实不新。然后把讨论拉回特殊约束。心理场景代价结构是「误记重于漏召」；写时抽取在入库时改写用户，错误标签会长期反复注入。经典 RAG 回答「哪段文档相关」；ER 回答「如何从原文重建一段可审计的经历证据」——自适应扩窗、衰减感知 MMR（含相对新近性）、时间排序注入、确认制 Profile，都超出 embedding + top-k。

对照实验也不该被说成随便换了个 RAG：基线是同协议 Mem0，固定 MiniMax-M3 reader，只换记忆库。context_recall 约 1.0 vs 0.47、staleness 约 14% vs 43%，与「保住共现、抗 stale」一致。对话侧亦有可指认设计：PT→SFT→DPO 分工、DPO 与 SFT 互斥、分类器不门控记忆。回应模板是：名词旧，问题约束与记忆形态假设不旧，且有同协议证据。

可再补一句边界：我们并不否认写时抽取在客服百科等场景可能更合适；主张的是在心理长程对话的代价结构下，原文重建更对齐目标。把「场景约束」讲出来，比争论名词新旧更有效。

### R5. 为什么微调与记忆必须一起做，而不是只做其中一条？

只微调不记忆：模型学会倾听，跨周回来仍像陌生人；「上周冷战、这周又来」「上次高等数学挂科」无法衔接，倾听退化成每次从零开始的安慰。只做记忆不微调：记得住细节，但基座默认语气仍可能空泛、说教或急于给建议；记忆块甚至会被用错语气消费，出现「记得很准但说得很伤人」。

两条线对应两类失败模式，解耦实现、联合交付。产品上记忆可关，说明记忆不是生成硬依赖；研究叙事上，完整问题定义需要两者同时成立。评测也分开度量：对话看 base/sft/dpo，记忆看同 reader 换库，避免用一条线的指标证明另一条线。

一个好用的类比：微调决定「音色」，记忆决定「有没有共同经历」。只有音色会每次重逢都像陌生人；只有经历没有音色，可能把共同经历说得很生硬。校园场景两者都缺一不可。

### R6. 相对 SoulChat、EmoLLM，本项目新在何处？

SoulChat 等工作明确心理支持需要共情与倾听，并提供 SoulChatCorpus；EmoLLM 等开源实践说明中文心理语料上的续训与指令微调能改善分布适配。SoulHarbor 对话线明确站在这一传统上：SFT 约九成 SoulChatCorpus、约一成 EmoLLM；PT 用 EmoLLM 心理问答片段约 24443 条；再补 DPO 与 MacBERT 路由感知 scale（0.7/0.3）。

相对这些工作的增量主要不在「又训了一个心理模型」，而在把跨会话经历记忆做成与写时抽取可对照的方法问题，并用同 reader 协议给出 QA/staleness/F1。前人把「怎么说」做成可训练任务；本项目进一步把「怎么记」做成可证伪的子系统。表述用「站在其上、补上记忆形态问题」，客观对照即可。

数据关系也要讲清，避免被理解成「另起炉灶」：SoulChatCorpus / EmoLLM 是对话线的养料；本项目增量在对齐阶段（DPO）、路由机制与记忆子系统。贡献叙事是叠加，不是替代。

### R7. 相对写时抽取记忆，本项目新在何处？

分歧在记忆形态。写时抽取（评测对照 Mem0）每轮用大模型把对话压成事实句再检索；ER 原文入库，查询时扩窗重建。写时抽取库小、检索简单，但共现细节易丢、瞬时情绪易固化；ER 召回即证据、注入即原文，但读路径更重，稳定模式需模型从经历链推断。

应背主表与逐类：QA 约 92% vs 64%，staleness 约 14% vs 43%，内容 F1 约 0.86 vs 0.48；context 1.0 vs 0.47，integration 0.93 vs 0.60，current 0.87 vs 0.60，preference 1.0 vs 0.73；detail 双方接近（约 1.0 vs 0.87）；temporal 双方偏弱（约 0.73 vs 0.60）。结论落在「优势与结构性预期对齐」：写时抽取并非记不住字面事实，差距主要在共现、整合、抗 stale 与偏好形态。

相关工作中「存经历、命中后扩窗」与 ER 同向；差别在于 ER 用 cos+实体扩窗、用含新近性的 MMR 选窗、用时间排序组织多会话证据，并用确认制 Profile 限制结构化写入。客观对比 Mem0 一类写时抽取即可。

### R8. 失败演进（写时抽取→ER）如何讲才像科研，而不是踩坑流水账？

用「假设—观测—修订」，不要按时间报流水。假设一：写时理解可提高可用性。观测：即便工具调用指标尚可，只要写入时理解就必然偶尔写错，错误长期留库，心理场景不可接受。假设二：分层与写时调和可缓解污染。观测：根因未变，底层仍在写入时改写用户。修订：Trace 不理解、读时再理解——原文入库；读路径补自适应扩窗与含新近性的 MMR；Profile 仅确认制。

中间态在 `archive/`，终稿只描述 ER。真正改进的是「理解发生的时刻」，不是「检索更花哨」。收尾落到证据：同协议相对 Mem0 的差距，以及新近性消融约 +8pp（84%→92%），说明修订后的假设可被检验。这样讲像问题重构，而不像运气好换到终案。口述收束可用一句：「我们不是换了三个工程方案，而是被误记代价逼着把理解从写入挪到了查询。」

## 二、微调选型

### R9. 为什么要微调，而不是只靠 Prompt 或 RAG？

Prompt 能写边界与口吻，但很难稳定改写模型在心理口语上的默认生成分布；system 越写越长，还会与记忆注入争上下文，并放大 Lost in the Middle。RAG/ER 解决的是外部证据从哪来，不解决给定证据后如何以倾听方式说话——同一段「上周冷战」证据，说教模型与共情模型会说出完全不同的话。

本项目把「怎么说」交给 PT→SFT→DPO，把「记什么」交给 ER，生成前再拼接。证据上，裸 Qwen3-14B 的 BLEU-1 约 13.23，SFT 后约 29.56，相对跃升约 +16，说明基座默认能力加简单提示远未达到领域对齐水平。微调不是否定 Prompt/RAG，而是承认它们解决不同子问题；面试时应主动拆开这三个旋钮，避免被问成「为什么不用某某万能提示词」。

若对方说「现在长上下文很大，何必微调」，回应：长上下文不自动给倾听偏好，也不自动解决跨会话选择与 stale；Prompt 更像约束，微调更像改分布。本项目用数字表明 base 与 sft 不在同一水平。

### R10. SFT、RLHF/PPO、DPO 如何选型？本项目为什么停在 DPO？

SFT 用高质量回复做监督，学习「在该情境下如何回答」，是格式与咨询节奏的底座。RLHF/PPO 适合多维、需在线探索的奖励，但要奖励模型、采样环与更重的稳定性工程。DPO 把含 KL 约束的 RLHF 最优策略写成闭式，用 chosen/rejected 直接优化，匹配「一维、可离线描述」的偏好：少空泛、少欠共情、少敷衍、少说教。

本项目在 SFT adapter 上续训 DPO：3000 对、`pref_beta=0.1`、lr=5e-6、1 epoch，线上 chat LoRA 即该产物。选型逻辑是问题维度 × 数据形态 × 单卡约束，而不是「DPO 一定优于 PPO」。若奖励变成安全/简洁/共情多维联合，或需要策略在线探索，再评估完整 RLHF 更合适。

DPO 公式直觉可一句话带过：拉高 chosen 相对 reference 的 log 比、压低 rejected，β 控制偏离程度。本项目 β=0.1 偏保守，配合 5e-6 学习率，适合在已 SFT 的话术上做小幅偏好推动。

### R11. 为什么不做完整 RLHF？

完整 RLHF 通常包含人类偏好收集、奖励模型训练、PPO（或同类）在线优化，并维护 reference、处理 reward hacking 与训练不稳定。本项目在单卡 QLoRA 上跑 14B，优先保证 PT/SFT/DPO 链路可复现、可加载到线上；合成 rejected 加质检已能构造对准失败模式的成对数据。DPO 避免显式 RM 与在线采样，工程与算力风险更低。

答辩时应把「不做」讲成阶段性取舍：当前偏好近似一维且离线可定义；多维联合优化时 RM+PPO 仍有位置。不要把「没做」说成「RLHF 无价值」，也不要暗示线上存在未实现的 PPO 环。

完整 RLHF 还有数据成本：稳定的多维人类偏好昂贵。本项目用合成 rejected 对准可描述失败模式，是原型阶段的务实近似；它换来可训练性，也带来「偏好来源非人类」的上限，这一点要主动说。

### R12. 基模越来越强之后，领域微调还有没有价值？

有。更强基座减少的是知识与通顺性缺口，不一定消除任务偏好错位：心理场景仍常见急于给建议、空泛安慰、说教。本项目用 DPO 专门锁这些失败模式。此外还有部署与复现约束：本地 14B + LoRA 便于数据驻留、记忆向量与分类器闭环、训练产物可核对；纯 API 弱化方法复现叙事。

价值表述建议从「补笨」转为「锁分布与失败模式」。证据是 base→sft 的自动指标跃升，以及 dpo 相对 sft 出现 BLEU 略降、ROUGE-1/2 略升这一符合偏好优化的现象。基模变强会改变微调幅度与数据需求，不自动取消任务对齐。

也可以从失败模式稳定性讲：基模升级常常改善知识，但「急于给建议」这类偏好失败可能以新的流畅形式出现。领域对齐的价值，正是持续对准任务失败，而不是追基模排行榜。

### R13. 为什么选 14B，而不是 7B、更大模型或直接 API？

14B 在 4-bit QLoRA 下可单卡训练与推理，中文与指令能力相对够用，是效果、显存、可复现的折中。7B 更省，但在拼接记忆、摘要与多轮咨询节奏上，本项目优先保留更大基座的表达余量。更大模型或更高精度超出单卡原型预算。API 利于快速对话，但难以完整承载本地 ER、MacBERT、LoRA scale 切换与可审计训练产物。

应强调：14B 是方法载体，不是规模消融后的全局最优。若被问「换 32B 会不会更好」，回答「可能，但会同时改变显存、速度与超参，必须重跑训练与评测，不能把现有数字直接外推」。

关于 API：若只做产品演示，API 更快；但本项目同时承担方法复现与本地记忆闭环，API 会把关键能力与关键状态放到外部，削弱「可核对跑次」。研究原型与纯产品路径的取舍不同。

### R14. 为什么用 LoRA/QLoRA，而不是全参微调？

全参更新 14B 时，权重、梯度与 Adam 状态显存远超单卡原型。QLoRA 将基座存为 4-bit（NF4 等），只训练低秩适配器，使「单卡训 14B」成立。LoRA 假设任务增量近似落在低维子空间；本项目全链路 r=8、α=16，`lora_target=all`，覆盖注意力与 FFN 相关投影，因为心理对话风格变化往往不只落在注意力。

研究表述：PEFT 是约束下的必要选择；统一 r/α 并与线上 `adapter_config.json` 对齐，减少训练—部署静默漂移。收尾用「在可部署约束下达到可核对收益」，避免绝对宣称「LoRA 无损全参」。

粗算帮助建立直觉：单层若 d=k=3584、r=8，全量约 3584² 参数，LoRA 约 2·r·d，比例约千分之几量级；全模型可训练增量仍远小于 14B。QLoRA 解决的是「能不能训」，LoRA 解决的是「训哪里」。

### R15. rank 与 α 怎么定？有没有扫参？

取经验区间下限附近的统一值：r=8、α=16（α/r=2），PT/SFT/DPO 形状一致，各自保留独立 LoRA 目录以便链式续训与对比加载。未做系统的 rank 网格搜索——算力优先保证三阶段跑通、对话自动评测与记忆同 reader 实验，而不是在 PEFT 超参上穷举。

诚实口径：这是够用设置，不是已证明最优。若补实验，应固定数据与评测，扫 r∈{4,8,16}，同时看 BLEU/ROUGE、抽检与过拟合迹象；保持 α/r 稳定有助于学习率迁移。统一形状的工程收益（阶段可比、线上一致、少静默偏差）本身也是设计理由，可以正面讲。

统一 r/α 还有评测外的好处：PT/SFT/DPO 目录可并列对比，线上只加载最终 DPO adapter，却能追溯同形状前序阶段。这对排错「到底哪一阶段学坏了」很重要。

### R16. 推理 scale 与训练时的 α、r 有什么区别？

训练期 α、r 决定 $\Delta W=\frac{\alpha}{r}BA$ 写入 adapter 的量级；推理 scale 是运行时 `set_scale` 的额外乘数，本项目咨询约 0.7、闲聊约 0.3，摘要则 `disable_adapter`。三者独立：改 scale 无需重训；改 α/r 必须重训；DPO 的 β 又是与 LoRA α 无关的另一维。

MacBERT 只输出路由以选择 scale，不修改权重文件，从而实现「一份 chat LoRA、多种语气强度」。这是高频易混点：把 α 和 scale 当成一回事。口述时应明确：α 是训练超参，scale 是推理旋钮，本项目用后者做路由感知生成，并用职责收缩把误分类代价限制在语气强弱。

可举反例帮助记忆：若有人把咨询 scale 设成 1.0、闲聊也 1.0，就失去路由意义；若把 scale 写进训练 α，就会误以为要为闲聊重训。本项目把分流做成推理期乘法，正是为了避免重训。

### R17. 如何看待灾难性遗忘？本项目做了什么缓解？

灾难性遗忘指适配新分布后损伤旧能力。本项目的缓解来自结构与超参两端：LoRA 冻结基座、限制可更新子空间；学习率阶梯 PT 5e-5 → SFT 2e-5 → DPO 5e-6；DPO β=0.1 偏保守且只训 1 epoch。这降低「冲掉前序话术」的风险，但并不等于已经画出遗忘曲线。

当前缺口是：未系统报告通用基准掉点。补做时应在心理 unseen 与通用评测集上同时对比各阶段 checkpoint。答辩句式建议：「有结构性缓解与保守训练日程；量化遗忘是后续工作，不是已完成主张。」

LoRA 不能从理论上「免疫」遗忘，只能限制可更新子空间。若未来看到通用能力明显掉点，应优先检查 DPO 数据是否过度、学习率是否过大，而不是先指责 PEFT 无效。

### R18. 数据质量与互斥切分为什么重要？

心理对话微调对噪声与泄漏极敏感：低质回复会直接教坏语气；同一上下文既进 SFT 又进 DPO，或既训练又测试，会造成虚高。本项目 SFT 约 20000 条经过去重、低质过滤、长度截断与模板统一；DPO 的 prompt 池与主 SFT 样本互斥；对话评测在 SoulChatCorpus 上按 seen/unseen 各 1000 条报告。意图分类数据 3000/300/300，正负 1:1 且按字长对齐，降低分类器走捷径的可能。

互斥不是万能：按样本 id 随机切仍可能残留主题相近。应主动说明局限，并指出记忆评测的 30 条长程弧独立合成、不进入生成模型训练，是另一条防泄漏线。数据叙事要落在可操作的过滤与切分规程，而不是「我们数据很好」。

意图数据按字长对齐，是为了减少「长句=咨询、短句=闲聊」的捷径。这类细节能说明你关心的是可学信号是否干净，而不只是准确率数字好看。

### R19. 合成 rejected 的风险是什么？如何质检？

DPO 的 rejected 由 MiniMax-M2.7 按「仍相关但更敷衍/欠共情/说教」指令合成。主要风险有三类：负样本流畅却并不更差，甚至质量反超 chosen，优化会学反；负样本离题过远，对比过容易，偏好信号假强；topic 不均衡，模型只学会某一类「别说教」。

质检脚本过滤明显不可用负样本，并尽量保持 topic 均衡；β=0.1 与 lr=5e-6 限制更新幅度。上限必须讲清：合成偏好对准的是可描述失败模式，不是人类全维度价值；因此对话侧结论以自动指标相对比较为主，共情胜率若要硬结论，需另做人工或 LLM-as-judge。

质检后仍要抽检：随机看若干 chosen/rejected 对，确认 rejected 是「同题但更差」，不是「另一个话题」。DPO 对错误对比非常敏感，数据审查本身就是方法的一部分。

### R20. 为什么 SFT 只对助手 token 算 loss？

多轮 ShareGPT 中，用户与 system 内容是条件，不是要模仿的答案。LLaMA-Factory 默认 `train_on_prompt=false`，非 assistant 段 label 为 `-100`，交叉熵忽略之。这样模型学的是「在该情境下如何回复」，而不是复读用户倾诉或背诵 system。若对全对话计 loss，容量会被浪费在模仿用户，推理时也更容易复读。

这与 PT、DPO 的目标一致地区分：PT 对全 token 做 CLM，因为目标是领域分布；DPO 比较的是助手回复 $y_w/y_l$ 的条件似然比，优化对象仍是答法。若追问 exposure bias，可补一句 teacher forcing 与自采样仍有落差，但角色 mask 是更基础的任务定义问题。

实现细节：框架对 logits 与 labels 做标准 shift，loss 只在 assistant token 上平均。面试若问「system 要不要学」，回答是：边界约束靠推理期 system，不靠 SFT 背诵 system。

### R21. PT 的作用是什么？有没有消融？没有能否答辩？

PT 用约 24443 条 EmoLLM 心理问答片段做因果语言建模，让基座更熟悉心理中文 token 分布，降低后续 SFT 的适应成本。流水线是 PT→SFT→DPO，学习率最高也放在 PT（约 5e-5），符合「先搬分布、再学任务、最后做偏好」的顺序。

当前**没有**单独报告 PT ablation，因此不能声称「已证明 PT 必要」。答辩策略：说明动机与工程惯例；承认因果证据不足；给出补实验设计——心理 unseen 上对比 PT 前后 perplexity，检查通用语料是否明显变差，并看下游 BLEU/ROUGE 是否因 PT 更稳。把缺口讲成可执行下一步，比硬辩「一定有用」更好。

就算没有 PT 消融，也可以报告「为何放进流水线」：心理口语与百科/代码分布差大，先做领域 CLM 是常见且可解释的工程先验。缺失的是因果强度，不是动机。

### R22. 过拟合有哪些迹象？本项目如何观察？

常见迹象包括：训练 loss 持续下降但 seen 远好于 unseen；生成复读训练集套话；DPO 后多样性塌缩；出现异常冗长以骗取字面重叠指标。本项目在对话评测上分开报告 seen/unseen，用于观察是否仅死记训练分布；DPO 仅 1 epoch、小学习率，降低过拟合偏好对的风险。

自动指标不能单独定论过拟合，需要结合抽检回复。若 unseen 明显塌陷，应优先检查重复样本与切分泄漏，再考虑早停、降学习率或增加数据多样性。不要把训练 loss 下降等同于泛化成功。

DPO 后 BLEU 略降本身不一定是过拟合；更要看是否出现重复口头禅、异常变长、或 unseen 崩塌。把「指标变化」和「过拟合迹象」分开讲，能避免被带进单指标陷阱。

### R23. 学习率阶梯如何设计？为什么越往后越低？

| 阶段 | 典型 lr | 目的 |
|------|---------|------|
| PT | 5e-5 | 较大步幅搬动领域分布 |
| SFT | 2e-5 | 学指令与咨询应答 |
| DPO | 5e-6 | 小幅推动偏好，避免冲掉 SFT 话术 |

规律是：越靠近最终线上模型，越保守。LoRA 相对全参可以用更大 lr，但阶段间仍应递减。DPO 在已对齐话术上做偏好微调，学习率过高容易把策略推离 reference 过远，表现为胡话、风格漂移或 reward hacking 式冗长。该阶梯与「PT 塑分布 → SFT 学格式 → DPO 做偏好」的目标顺序一致，口述时把「数字」和「为什么递减」绑在一起讲。

## 三、评测与实验

阶梯与阶段目标绑定记忆：PT 要动分布所以 lr 最大；SFT 学任务所以居中；DPO 只做偏好微调所以最小。背数字时连着背理由，不容易忘。

### R24. 如何证明微调有收益？

主证据是同一评测协议下 base → sft → dpo 的自动指标对比。数据为 SoulChatCorpus seen/unseen 各 1000 条，jieba 分词后计算词级 BLEU/ROUGE。关键数字：BLEU-1 从 13.23（base）到 29.56（sft）、27.91（dpo）；ROUGE-L 从 15.04 到 24.64 / 24.44。完整 BLEU-1～4 与 ROUGE-1/2/L 见第三部分表格与 `evaluate/dialogue/runs/`。

解读分两层。第一层，SFT 相对 base 的大幅度跃升支持「领域对齐有效」，这是微调有收益的主结论。第二层，DPO 相对 SFT 的 BLEU 略降、ROUGE-1/2 略升或持平，符合「优化偏好、表达更自然多样时，与单一参考答案的字面重合可能下降」；不能单用 BLEU 判定 DPO 失败。最后限定表述：这是相对自动指标收益，不是人类共情的充分证明。

### R25. BLEU/ROUGE 测心理对话是否合理？

合理作为**相对**尺度，不合理作为**绝对**共情度量。心理回复往往一词多安、无唯一金标准；BLEU/ROUGE 奖励与单参考答案的字面重叠，会低估合理但换表述的好回复，也会高估套话式重合。本项目用其证明 base→sft 的分布对齐，并解释 dpo 的 BLEU 回落；共情、安全感、是否说教等维度若要结论，需要人工量表或 LLM-as-judge，终稿未系统展开。

面试时主动划清指标边界，比死守「BLEU 高就更好」更像做研究。也可以反过来说：正因为知道 BLEU 的局限，本项目才把记忆侧做成同 reader 的 QA/staleness/F1，用更对齐任务的指标支撑另一条主线。

一个实用答法：先承认「绝对不够」，再强调「相对有用」，最后指出「记忆侧换了更对齐的指标」。三段式比辩解 BLEU 完美更稳。

### R26. 为什么没有做系统的人工评测？如何补强叙事？

资源与节奏上优先完成可复现的自动对话指标与记忆同 reader 对照；系统人工评测（盲评、量表、多人一致性）成本高，终稿未铺开。这是明确缺口，不必回避。

补强叙事有三条路：第一，不把自动指标宣传成主观体验结论；第二，记忆侧用固定 reader 隔离答题能力，比对话 BLEU 更硬地指向记忆形态差异；第三，若续作，优先做小规模盲评——同 prompt 下 base/sft/dpo 的共情与说教强迫选择，以及记忆开/关对跨会话连贯性的 Likert 评分。诚实承认缺口并展示已有证据链，通常好过虚构「已充分人工验证」。

若只有半天补人工评测，最小设计可以是：20 组对话，两人盲评 base vs dpo 的共情/说教二选一，报告胜率与一致性。不求大，但求可引用。

### R27. 记忆评测为什么强调同 reader 协议？

因为最常见的混淆是「换了记忆方法，也换了答题模型」，结果无法归因。本协议固定 MiniMax-M3 为 reader，只替换「该方法检索得到的记忆块 + 试题」；ER 与 Mem0 在同一对话流上逐轮 ingest。选择题精确匹配，开放题按参考答案判定，内容 F1 对比应记/应忘集合。

在此协议下，QA 约 92% vs 64%、staleness 约 14% vs 43%、F1 约 0.86 vs 0.48，应归因于记忆库形态与检索注入内容，而不是谁的聊天模型更强。面试时应把协议设计本身当作贡献的一部分：它定义了「测的是记忆，不是测 chatbot」。两轮 ER 跑次之间的绝对波动（例如终版 92% 与历史 84%/93%）来自评测采样性，单跑次绝对值不如与 Mem0 的相对差距重要。

协议图可口述为：同一弧 → 两套库 → 同一 reader → 只换记忆块。谁破坏其中一环，谁的数字就不能拿来做路线结论。

### R28. 为什么选 Mem0 作基线，而不是只做无记忆或自比？

无记忆基线只能说明「记忆有没有用」，不能说明「哪类记忆形态更好」。研究主张针对的是写时抽取在心理场景的结构性风险，因此需要同协议的写时抽取代表。Mem0 是该类路线中工程完整、可对接同一对话流的系统，适合作为对照。

自比（ER 开/关某一模块）用于消融，例如含新近性的 MMR vs 无新近性 MMR；与 Mem0 的主表对照回答的是「相对主流写时抽取好多少」。两类实验问题不同，不能互相替代。若只有无记忆对照，审稿人或老师很容易说：你只证明了检索有用，没有证明原文重建优于写时抽取。

选择 Mem0 还有表达优势：它是写时抽取路线中被广泛讨论的系统形态，便于审稿人或面试官建立对照心智模型；比自造一个弱抽取器更有说服力。

### R29. 覆盖度消融应如何解读？

把最后的证据选择从固定 top-k 换成MMR 选窗后，QA 由约 84.4% 提升至约 92.2%，大约 +8 个百分点。固定 top-k 只看单条相关性，同一事件的多段高分内容会挤占上下文，其他相关但分数稍低的话题难以出场。覆盖度得分大致奖励新增信息覆盖与查询词增益，用时间桶鼓励多样性，并惩罚与已选内容的冗余。

解读要点有二。第一，收益来自「如何编排已召回候选」，说明读路径选择器本身是建模对象，而不只是检索器后的琐碎后处理。第二，不要把该消融夸大成「整个 ER 相对 Mem0 的全部差距」——主表差距还来自原文形态、扩窗与时间排序注入等。消融回答的是模块贡献，主表回答的是路线差异。

覆盖度公式直觉：相关要够，但新增信息与查询覆盖更重要，和已选内容太像要罚，时间桶鼓励多样。消融证明「编排」有独立贡献。

### R30. 只有 30 条记忆评测，如何辩护？

30 条是受控长程咨询弧，六类能力各 5 条，每条多会话、多周、配 3 道测试题与应记/应忘事实集，构建有硬规则与人工验收。目标是能力维诊断与同协议对照，而不是互联网规模刷分。内部效度优先：同 reader、同对话流、只换记忆库。

辩护结构建议三步。第一，协议严格，归因清晰。第二，逐类结果与设计预期对齐（context/integration/current/preference 优势大，detail 接近，temporal 双方弱），降低「随机涨点」怀疑。第三，明确外部效度边界——结论是同协议下的相对优势，不宜直接外推到任意用户规模。扩展时优先增加 temporal 类弧与多种子报告，而不是只追求总条数。

30 条 × 每条 3 题，实际是 90 个记忆依赖探测点，再加内容 F1 的应记/应忘集合比对。辩护时不一定只说「30 条」，可以说「90 题探测 + 内容集合指标」。

### R31. temporal 偏弱如何归因？下一步怎么改？

代表跑次上 temporal_sequence 约 0.73（ER）vs 0.60（Mem0），双方都偏弱。可能原因包括：题面更依赖显式先后与时间锚，而注入以相关经历窗为主，时间顺序信号不够显式；扩窗与覆盖优化的是相关性与去冗余，不是时间推理专用目标；reader 本身对细粒度时序也非完美。

下一步可在证据链中加强时间戳呈现与排序提示，或增加时序探针数据，而不是简单加大 top-k。归因时应避免单因叙事，把它讲成双方共同的开放问题，反而更像严谨研究：你知道自己的短板在哪，也知道短板不一定能靠「再堆一点检索」解决。

也可以把 temporal 弱写成未来工作的自然入口：显式时间锚、时序探针、甚至轻量时间重排。这比假装已经解决更有研究气息。

### R32. seen/unseen 与数据泄漏怎么讲？

对话评测按是否进入训练分布划分 seen/unseen，用于观察死记硬背。更严格的做法应按主题、时间或用户切分；按样本 id 随机切可能残留上下文或近义泄漏。DPO prompt 与主 SFT 互斥，是另一处防泄漏措施。记忆评测数据为独立合成的 30 条长程弧，不进入生成模型训练。

面试时主动说明切分局限，展示你理解「指标上涨≠泛化已证明」。如果老师追问更严协议，可以回答：下一版会按主题簇或时间切分重报对话指标，并保持 DPO↔SFT 互斥不变。

记忆弧「不进生成训练」要强调：否则 reader 或生成模型可能靠参数记忆答题，污染「测记忆库」的主张。

### R33. 指标与任务是否对齐？如何避免「指标游戏」？

对齐检查问的是：指标变好是否意味着目标能力变好。对话 BLEU 与「更共情」部分错位，故只作相对参考，并观察 DPO 后 BLEU 降而 ROUGE-1/2 升是否符合偏好优化直觉。记忆 QA 直接问记忆依赖题，staleness 直接罚旧状态，内容 F1 对应应记/应忘，与 ER 主张更对齐。

避免指标游戏的做法：预注册主指标（记忆主表为 QA，辅以 staleness 与 F1）；报告逐类而不是只报总平均；对不利结果（temporal）不藏；不以调温度或换分词器去「找更好看的分」。把「不会为了数字牺牲归因」讲清楚，本身就是加分。

主指标预注册在口述里就是：记忆先看 QA，对话先看相对 BLEU/ROUGE，不以事后挑指标。

### R34. 如果重做实验，你会改什么？

优先序建议如下。第一，补小规模盲评或 LLM-as-judge，覆盖共情/说教/记忆连贯。第二，扩展记忆评测弧的规模与 temporal 比例，并做多随机种子报告区间。第三，补 PT ablation 与 rank 敏感性。第四，在同 reader 协议下增加「原文 top-k 无扩窗」等更细消融，把扩窗与覆盖的贡献拆开。

不优先一上来换更大基座或上 PPO——那会同时改变多个变量，削弱归因。一周到一月的改进，应服务于「让现有主张更硬」，而不是「让故事更新」。重做实验的反模式是同时换基座、换损失、换评测集；任何一次只改一个主变量，才配叫「重做得更干净」。

## 四、记忆系统研究追问

### R35. 短期、工作、长期记忆在本项目如何对应？

不必强行套认知科学的三层术语，但可以给出清晰的工程映射。当前会话中「自上次摘要以来的原文」是即时可用的短上下文；滚动会话摘要由裸基座生成，是会话内工作记忆压缩，降低重复阅读成本；ER 的 Trace 与确认制 Profile 是跨会话长期记忆。

三者组装顺序大致为：摘要 system →（若开启）`<memory>` → 未摘要原文。长期记忆可由用户关闭；短上下文与摘要仍服务单会话连贯。口述时强调职责边界：摘要关 LoRA，避免共情腔渗进压缩文本；长期记忆写路径对 Trace 零 LLM，避免把工作记忆式的「理解」偷偷写进长期库。

若被问「有没有向量数据库当长期记忆」，回答：有向量索引，但长期记忆的语义主体是原文 Trace，不是「只存 embedding」。向量是检索手段，原文是证据。

### R36. Memory 与 RAG 的关系？ER 算不算 RAG？

广义上，凡「检索外部文本再生成」都可称 RAG；狭义经典 RAG 多指静态文档切片的 top-k 检索。ER 属于检索增强家族，借用了 dense 检索、字级词法检索与 RRF 等组件，但记忆单元与读路径不同：单元是经历窗而非百科文档块；读路径含连续性扩窗、跨会话链与衰减感知 MMR（含相对新近性）；写路径不预先决定「哪句话值得进知识库」，而是全量原文块入库。

更准确的说法是：ER 是面向对话经历的记忆系统。若面试官坚持问「是不是 RAG」，可以答「是检索增强的一种，但不是标准文档 RAG；关键差别在经历单元与查询时重建」。这样既不否认谱系，也不把自己说成换皮 RAG。

对比句：RAG 常问「哪段知识支持回答」；ER 常问「哪段经历让此刻的倾听有据可依」。问题不同，系统形态就不同。

### R37. 写入策略：记什么、谁确认？

Trace 侧：每条 user/assistant 消息经确定性中文分块与 BGE-M3 向量化后入库，写路径零 LLM，不抽事实、不合并概括、不生成摘要标签。Profile 侧：用户显式「记住/别忘了…」走规则快路径；或助理回合后由中文 LLM 攒批提议——默认未抽消息数约 ≥5 或批次年龄约 ≥300 秒触发，每次最多 1 条，进入 pending，用户确认后才 active；政策层拦截诊断词、人格标签与瞬时情绪前缀。

设计原则可以压成三句话：经历证据自动记；稳定偏好需同意；禁止写时贴标签。确认前的候选不算记忆，这是与「写时画像立即落库」路线的硬差别。助理话轮也入库，但那是为了邻接与扩窗，不等于把助理判断写成用户事实。

Profile 攒批触发（约 5 条或 300 秒）是为了降低每轮 LLM 提议成本，并减少把瞬时情绪立刻提议成偏好的机会；每次最多 1 条、pending 上限约 8，都是抑制过度结构化的阀门。

### R38. 冲突、过期与 stale 如何处理？

系统刻意不做写时生命周期状态机，因为「是否过期」本身也是写时判断，同样会判错。抗 stale 放在读侧：只选与查询相关的经历；MMR 去冗余并兼顾相对新近性/周桶；token 预算整行裁剪；注入前缀标明历史背景，并规定与用户此刻说法冲突时以当前说法为准。

评测上 current_state 约 0.87 vs Mem0 约 0.60，staleness 约 14% vs 43%。用户侧还有一键遗忘与偏好纠正。冲突的最终裁决权在「当前用户说法 + 确认制 Profile」，而不是旧抽取标签。把 stale 当读路径问题而不是写路径标注问题，是 ER 立场的一部分。

「冲突以当前说法为准」写在注入前缀里，是读路径策略，不是写路径删除旧文。旧经历仍可被问到，但不应压过用户此刻的自述。

### R39. 为什么用 hybrid 召回再加 RRF？

语义向量（BGE-M3，dense 维 1024）擅长意近形不近；字级 BM25 对人名、课程名、数字更敏感。心理对话两者都重要：「那次高等数学挂科」既有语义情境，也有专名锚点。只用 dense 容易漏专名，只用词法容易漏转述。

RRF 按 reciprocal rank 融合，对原始分数刻度不敏感，实现简单稳定。assistant 块召回降权约 0.55，因为注入默认只取 user，但邻接仍有助于扩窗连续性。hybrid 不是为了堆模块，而是补齐单一检索在心理对话上的盲区；口述时把「互补」讲清楚即可。

RRF 的 60 是常见平滑项；本项目取 anchor top-8 再扩窗。数字可记，但更重要的是「融合的是排序而非原始分」。

### R40. 为什么不做图数据库？

经历关联在查询时由自适应扩窗与证据链动态建立，而不是写时固化边。单机 SQLite + 向量 JSON + 按用户 FAISS 缓存已经支撑原型与评测；引入图库会增加 schema、边质量与运维复杂度，也容易重新引入「提前承诺结构」的风险——边写错了，后续会像错误标签一样难清。

若未来需要图谱可视化或复杂多跳查询，可以从原文块离线构图，而不改变「写时不理解」的哲学。终稿选择是：先保证证据可审计与形态正确，再谈更重的图结构。这不是否定图方法，而是拒绝在写路径上过早结构化。

若对方推崇 GraphRAG，可回应：图适合稳定实体关系；心理经历更像叙事流，边过早固化有风险。可以离线构图做分析，但不必让写路径依赖图。

### R41. Profile 与 Trace 有何本质区别？

Trace 是原文编年，回答「当时说了什么、在什么情境下说的」，可检索、可扩窗、可审计。Profile 是少量已确认的支持偏好，回答「用户明确同意系统长期记住的稳定支持方式」，通常全量注入（有上限，约 30 条量级），不经 top-k 赌博。

写入机制也不同：Trace 零 LLM；Profile 允许极少量理解，但必须确认与政策过滤。混淆二者是常见误读：把 Trace 当画像，或把未确认 pending 当事实，都会回到写时过度概括。答辩时应主动拆开这两个子系统。

一个易错点：查看记忆时用户侧优先看到已确认偏好，而不是把 Trace 原文库整库摊开。控制权与可解释性，优先于「把库给人看」。

### R42. 注入如何约束幻觉？

注入块放在 system 侧，前缀约束其历史背景属性，要求冲突以当前说法为准，并禁止补充检索结果之外的事实；内容尽量整段 user 原文，极端超长才局部裁句；全局约 1600 token，超预算整行裁剪，避免撕碎证据。查询规划若启用，temperature=0.0，要求单目标、保留锚点、不添加未提事实，失败回退整句 direct。

生成侧仍可能幻觉，但记忆路径的目标是：提供可核对证据，并缩小「模型自由发明用户生平」的空间。幻觉不能根除，只能结构性抑制。面试中把「约束注入」与「幻想根除幻觉」区分开，显得更成熟。

Qwen chat template 对多条 system 不稳定，因此记忆块注入位置与前缀文案需要单独处理——这是幻觉约束之外的工程约束，面试若懂这一点会显得做实。

### R43. Lost in the Middle 与本项目的关系？

长提示中间段利用率往往较差。本项目的应对不是无限加长上下文，而是：衰减感知 MMR（含相对新近性）减少冗余堆砌；token 预算限制总长；记忆块位置与前缀文案相对固定；未摘要原文保留最近上下文。反对把全部历史硬塞进长上下文——全塞会稀释注意力，并让旧状态污染当前判断。

因此 ER 首先是「在上下文里放什么」的决策器，其次才是检索器。长上下文解决容量，不自动解决跨会话选择与 stale；本项目把后者当作一等公民问题。

也可以联系评测：覆盖度消融涨点，部分正是因为减少了中间冗余造成的注意力浪费与主题挤兑。

### R44. 为什么助理话轮也入库，但注入只放 user？

助理入库是为了语义邻接与扩窗连续性：用户一句「嗯」或短反馈，往往需要两侧助理话轮才能恢复事件边界。如果只存 user，经历窗容易碎裂。注入默认只取 user 原文，则是为了避免把咨询师复述、猜测或总结当成用户事实，并节省 token 预算。

这是「存全量、用子集」的不对称设计。实现上每窗最多约 6 条 user 话轮，优先 anchor 与查询相关句。评测与产品都按注入子集消费记忆，因此库里有助理文本，不等于模型被允许把助理判断当作用户自述。

降权 0.55 的 assistant 召回，服务于「需要邻接，但不希望助理文本主导排序」。存与用的不对称，在召回分数上也会体现。

### R45. 抗过度概括的结构性论证怎么讲？

关键句：记忆库只存原文，不在写入时归纳画像，因此一次性情绪或被反驳的特质不会被系统写成「确信事实」。这与提高某个分类阈值不同，它是去掉写时归纳通道。代价是：稳定模式需要答题模型从经历链自行推断，其上限取决于注入完整性。

证据上，内容 F1（应记/应忘）约 0.86 vs 0.48，说明库内容更接近金标准集合。过度概括类探针不是主表重点，但结构立场与主表优势一致。相关工作中存在「保存经历原文、命中后再扩展邻域」一类做法；ER 沿此方向推进，进一步用连续性得分做自适应边界、用衰减感知 MMR（含相对新近性）抑制冗余，并用时间排序注入支持整合，同时坚持确认制 Profile。客观对照即可，不必把差异说成对相关工作的否定。

## 五、方法与约束交互

结构性抗过度概括 ≠ 答题模型不会过度概括。库不写错标签，模型仍可能口头概括；所以注入约束与生成对齐仍然必要。把层次讲清，避免被抓逻辑漏洞。

### R46. 为什么意图分类器不用大模型，而用 MacBERT？

咨询/闲聊是简单二分类。MacBERT-base 在 3000 条对照数据上训练（正负 1:1，按字长对齐），验证准确率约 99.7%，延迟与显存远低于让 14B 每轮自我裁定意图。职责被刻意收窄为 LoRA scale 旋钮（0.7/0.3），不门控是否检索记忆。

若用大模型分类，成本高、稳定性差，且容易与生成耦合，误判代价也会从「语气强弱」膨胀成「整条行为策略改变」。省下的显存留给 14B 与 BGE-M3。小编码器还便于离线评测与独立迭代，符合「能小号解决的问题不要占用生成模型」。

选 base 而非 large：任务简单，准确率已约 99.7%，大模型编码器的边际收益不足以换显存。分类器是「够用且便宜」的典型。

### R47. 会话摘要为什么关闭 LoRA？

摘要任务需要的是压缩与保真，不是共情腔。chat LoRA 为倾听风格对齐；若带着 scale 做摘要，容易把安慰套话、语气词写进压缩文本，污染后续长期上下文，形成「摘要里的假记忆」。

实现上摘要 `disable_adapter` 走裸基座，温度亦偏低（约 0.3）。这与「一份 LoRA 多用途」不矛盾：用途切换靠开关 adapter，而不是强行共用语气。口述时可把它当作职责解耦的又一例，与分类器只调 scale、Trace 写时不理解并列。

摘要触发大约在会话 token 达到阈值（约 3000）后于 post-turn 进行；生成期仍可见旧摘要 + 全部未摘要原文，避免摘要进行中丢上下文。关 LoRA 与这一时序设计配套。

### R48. 单卡约束如何塑造了方法本身？

单卡迫使一系列方法选择：QLoRA 而非全参；一份 chat LoRA + scale，而非多 adapter 常驻；Trace 写路径零 LLM，避免每轮再跑抽取模型；检索主体由代码编排，仅可选查询规划调用 LLM；引擎内 RLock 串行 GPU，应用层把 ingest/摘要放到 post-turn，以免阻塞首 token。

这些不只是工程妥协，它们反向选择了「写时不理解、读时再建」的记忆哲学与「路由感知强度」的生成哲学。面试时把约束讲成方法形成的一部分，比把约束讲成借口更有说服力：你不是「穷所以简陋」，而是「在给定约束下选择了可证伪的形态」。

单卡还塑造了评测习惯：能在同机复现的离线对照，优先于依赖大集群的在线 RL。方法选择与证据形态是一致的。

### R49. 记忆开/关与意图分类解耦，研究含义是什么？

`memory_enabled` 只由用户设置决定；`is_consult` 只调节 LoRA scale。两者在代码与评测语义上都解耦。研究含义至少有三：第一，记忆是可消融的系统因子，可单独评估开/关对跨会话质量的影响；第二，闲聊中提及旧事时仍能召回，避免路由错误导致记忆系统性失效；第三，误分类的代价被限制在语气强弱，故障分析更干净。

解耦让「语气对齐」与「经历记忆」成为两条可独立实验的假设，这正是本项目双线叙事能够成立的原因。若把记忆绑死在咨询路由上，一次闲聊误判就会造成「系统突然失忆」，方法与产品都会变脆。

## 六、问到概率较低但仍值得准备

管理端可用 `turn_metrics.route` 做分诊筛选，但那是观测与运营，不回流成记忆门控。职责单向，避免隐式耦合。

### R50. PPO 的 clip 与奖励模型链路，和本项目关系？

经典 PPO-RLHF 链路大致是：人类或规则偏好训练奖励模型 → 策略模型采样生成 → 用优势估计更新策略，并以 clip 限制新旧策略比率，防止单步更新过大；同时常用 KL 惩罚把策略拉向 reference。本项目未跑该环，而用 DPO 的闭式偏好目标直接优化。

低概率但值得准备的原因是：面试官常用 PPO 考察对齐基础。你需要能画出 RM+PPO 与 DPO 的差别，并解释本项目因单卡与一维偏好选择了 DPO；不要假装线上存在 PPO，也不要只会背 DPO 公式却说不清为何不做 PPO。

clip 的直觉：若新策略相对旧策略的概率比超出区间，就裁剪梯度贡献，避免一次更新走太远。DPO 用 β 与离线对达到另一类保守。

### R51. ORPO、KTO、IPO 各一句话？为何仍用 DPO？

IPO 对噪声偏好往往更稳；KTO 可用「好/坏」单标签，而不强制构造严格成对；ORPO/SimPO 一类方法可以减弱甚至省去对 reference 模型的依赖。本项目已具备成对 chosen/rejected，且希望相对 SFT reference 的偏离可控，DPO 足够直接，实现与社区工具链也成熟。

换变体不是优先复现项，除非后续发现偏好噪声成为主矛盾，或 reference 前向成为明显瓶颈。一句话原则：先把数据与评测做硬，再换损失变体。

若只有隐式反馈（点赞/点踩）没有成对回复，KTO 可能比 DPO 更贴数据形态；本项目现有数据是成对，所以 DPO 更直接。

### R52. NF4 与 double quantization 是什么？和本项目训练的关系？

NF4 按标准正态分位构造 4-bit 码本，更适配预训练权重近似高斯的分布，量化误差通常优于朴素等距 INT4。Double quantization 对量化参数本身再量化，进一步节省显存。QLoRA 常用二者，并配合 paged optimizer，支撑单卡训练大模型。

与本项目的关系可以压成口诀：4-bit 用于存储冻结基座；计算在较高精度（如 fp16）上做；优化器只服务 LoRA。面试若追问「量化是否伤效果」，回答应落到「主成分信号相对保留、本项目以下游自动指标与可部署性为接受标准」，而不是空谈无损失。

与 GPTQ/AWQ 等训练后量化不同，本项目训练与推理共用 BNB 4-bit 路线，工程更简单；若未来高并发服务，再评估专用推理引擎。

### R53. Prefill、Decode 与 KV cache 如何结合本项目讲？

推理通常分 Prefill 与 Decode：Prefill 处理输入提示，算力相对密集；Decode 逐 token 生成，常更受访存带宽限制。KV cache 缓存历史 token 的 K/V，避免每步重算，显存大致随层数、序列长度、batch 与头维度增长。

结合本项目：单并发、中等长度输入时，主瓶颈更常来自 GPU 锁串行与可选查询规划，而不是 KV 本身撑爆。记忆注入会增加输入长度，从而影响 Prefill；但对首包时延的影响，通常仍可能小于「多一次规划 LLM 调用」。把系统瓶颈讲对，比背定义加分。

记忆规划是可选的；关掉规划通常能换首包时延。原型上这是明确的延迟旋钮，不是神秘性能问题。

### R54. 换基座要重做什么？

需要重做或至少重验证的部分：PT/SFT/DPO 适配器（词表与隐维度变化则 LoRA 不通用）、chat template 与记忆 system 注入位置、量化与推理配置、对话自动指标与必要的生成抽检。可大体复用的部分：MacBERT、BGE-M3、字级 BM25、ER 编排与 SQLite schema、Profile 政策与确认流。

记忆同 reader 实验在「只换记忆库」意义上不必因换基座而作废；但若线上生成模型更换，应另做端到端体验评估，因为记忆块的消费方式会随生成模型变化。换基座是「训练线重来、记忆方法可迁移」的组合题。

换基座后，MacBERT 与 BGE 仍可能留用，但要重做「生成模型消费记忆块」的抽检：同样的 `<memory>`，不同基座可能遵循前缀约束的程度不同。

### R55. 对比 LongMemEval、LoCoMo 为什么终稿主表未做？

LongMemEval 等将长期记忆拆成多种能力维，思路可参考；本评测集按 detail / context / preference / current / integration / temporal 六维构建，与之同方向。终稿主表未混用这些公开基准，是因为要对准「心理长程咨询弧 + 写时抽取对照」的问题设定，并控制合成与验收标准；早期相关评测已归档，不与产品默认混谈。

若续作，可以把 ER/Mem0 适配到公开基准作外部效度补充，但必须声明领域分布差异：公开基准未必强调心理场景下「误记代价更高」这一约束。主表选择是问题对齐，不是回避公开评测。

六维与公开基准同思路，不等于同一分布。主表服务问题，公开基准服务外部效度——两者是后续组合，不是互相替代。

### R56. 在线持续对齐可以怎么做？本项目现状？

理想形态是：收集线上偏好信号（点赞、重写、人工抽检、显式反馈）→ 定期构造偏好对或好坏标签 → 用 DPO/ORPO/KTO 更新 LoRA → 跑对话与记忆回归评测后再上线。关键是闭环与防泄漏，而不是天天训。

现状是离线 3000 对偏好一次性对齐，原型未铺在线持续学习闭环。可以讲清数据飞轮设计，但不要把未实现功能说成已上线能力。低概率题的得分点往往在「知道边界」。

在线对齐还要防反馈回路：用户可能奖励「讨好」，心理场景尤其危险。需要抽检与回归，不能只看点击率。

### R57. 多用户扩展时，记忆系统的主要挑战？

主要挑战包括：按用户隔离 Trace/Profile；FAISS 缓存指纹失效与重建；嵌入失败积压与重试；token 预算下不同用户的公平性与尾延迟；以及遗忘、软删、导出等隐私控制。单机 SQLite + 每用户向量缓存适合原型，用户量上升后需要存储分层、异步索引与检索时延治理。

方法核心——原文入库、查询时重建——可以保持不变；变的是系统规模化。面试时把「算法主张可迁移、系统实现需重做」讲清楚，避免把单机原型直接说成已具备大规模服务能力。

多租户下「一键遗忘」必须是硬删除/软删可达，而不是只在提示词里说忘记。ER 的原文库反而更利于审计是否删干净。

### R58. 中文分词对自动指标有何影响？

本项目对话指标在 jieba 词级上计算 BLEU/ROUGE。中文无空格，字级与词级分数差异可以很大；不同分词器会导致绝对分不可跨论文直接横比。有意义的是同一分词器、同一协议下的相对差，例如 base→sft 的跃升。

报告时必须声明分词方案。记忆侧主结论以选择题精确匹配等为主，对分词不敏感；不要把对话自动指标的分词细节，误当成记忆结论的弱点。

若换英文评测，分词问题会变成 tokenization 问题；相对比较仍要固定同一套预处理。原则通用。

### R59. 温度对评测有何影响？

温度升高通常增加多样性，往往降低与单参考答案的 BLEU；温度降低更稳定，也更容易「套参考」从而抬高字面重叠。因此比较 base/sft/dpo 时必须固定解码配置，否则差异可能来自解码而不是权重。

线上大致：chat 温度约 0.6，摘要约 0.3，结构化/查询规划约 0.0。评测叙述里应写明解码设置；若老师质疑「会不会调温度刷分」，回答是：相对比较固定温度，不做事后挑温度。

结构化输出与查询规划用温度 0.0，是为了 JSON 稳定；聊天 0.6 保留一点多样性。温度是任务相关超参，不是全局越高越好。

### R60. 如果只有一周，最小可行实验是什么？

记忆线：在现有 30 条协议上复现 ER vs Mem0 主表，并做含新近性的 MMR vs 无新近性 MMR 消融，保证跑次可核对。对话线：至少跑 base vs 最终 dpo 的 BLEU/ROUGE 相对差；若时间极紧可缩小评测子集，但尽量保持 seen/unseen 比例。

不优先改模型规模、不上 PPO、不重写前端。一周目标是「保住归因清晰的主证据」，让主张站得住，而不是扩大叙事范围。这道题考的是科研优先级：先巩固可证伪核心，再谈锦上添花。

---

一周实验的成功标准：能复现主表相对差距，能讲清新近性消融，能指出 temporal 短板。做不到这三件事，就不要急着开新故事线。

### R61. 如何用三分钟把整个项目讲完？

第一分钟讲问题：校园场景需要倾听，通用模型不会好好说；跨周需要记忆，写时抽取容易乱记。第二分钟讲方法：对话线 PT→SFT→DPO + MacBERT 调 scale 0.7/0.3；记忆线 ER 原文入库、查询时重建，Profile 确认制。第三分钟讲证据：BLEU-1 13.23→29.56（dpo 27.91）；同 reader 下 QA 约 92% vs 64%，staleness 约 14% vs 43%，F1 约 0.86 vs 0.48；新近性消融约 +8pp（84%→92%）；temporal 仍弱。最后留一句边界：问题驱动方法创新，单卡原型，指标有适用范围。

### R62. 创新点答辩时最容易被追问的三个口误是什么？

一是把训练说成「自我认知 SFT」之类独立阶段——终稿主线只有 PT→SFT→DPO。二是说分类器控制是否检索记忆——它只控制 scale。三是把 DPO 后 BLEU 略降说成失败——应结合 ROUGE-1/2 与偏好目标解释。把这三句提前练熟，能避免大量追问。

### R63. 如何解释「助理入库但只注入 user」不自相矛盾？

不矛盾，因为「入库」服务检索几何（邻接、扩窗），「注入」服务事实消费（防止咨询师语言变用户事实）。这是存储表示与提示表示的分离，类似于数据库存明细、报表只展示用户相关字段。降权、formatter 只取 user、token 预算整行裁剪，都是同一思想的配套。

### R64. 若老师要求把贡献写成「一条」，你怎么收？

可收成：面向心理支持对话，提出并验证一种「领域对齐生成 + 查询时经历重建记忆」的联合方案，在同协议下相对写时抽取记忆取得可核对的长程 QA 与抗 stale 优势，并在对话自动指标上相对裸基座取得稳定提升。一条贡献里包含双线，但用联合方案来统摄，避免听起来像两个无关项目。

### R67. 为什么说「抗 stale 主要靠读路径」？

因为写时标记过期会引入新的写时判断错误；处境是否结束，往往要到被问及时才清楚。读路径用相关性、时间桶、去冗余与前缀冲突规则，把「此刻该不该提旧状态」变成检索与编排问题。current_state 与 staleness 数字支持这一设计；它不保证永不出错，但把错误模式从「写错标签长期污染」转成「某次检索选得不好」，后者通常更容易用预算与选择器迭代。

### R68. 对话线与记忆线的交汇点只有一处，这意味着什么？

意味着生成模型并不内生维护长期用户状态；状态在外部记忆，生成前以 `<memory>` 注入。好处是可开关、可评测、可替换记忆后端；代价是注入质量上限决定跨会话表现。研究上这使「换记忆库、固定 reader」成为可能，也使「关记忆」成为干净消融。交汇点单一，是解耦成功的标志，不是系统简陋。

### R69. 如何评价 DPO 数据里 chosen 取自语料、rejected 合成这一不对称？

chosen 来自已有高质量咨询回复，保证正样本贴近真实倾听分布；rejected 合成为了定向制造失败模式，这是不对称但有目的的设计。风险在合成侧，所以要质检；好处是能覆盖「敷衍/说教」这类语料中可能不够密集的负例。理解不对称，就能解释为什么 DPO 更像「打补丁式偏好」，而不是从零学习咨询。

### R70. 若被问「你和普通 RAG 聊天机器人的差别一句话？」

普通 RAG 机器人常把知识库当文档检索；SoulHarbor 把长期记忆当经历证据库，写入不抽取，查询时重建，并与领域对齐的倾听生成耦合。差别在记忆单元与写时哲学，不在有没有向量检索。

### R71. 训练—评测—上线三者如何互相印证？

训练配置在 `train/configs/*.yaml`，线上 adapter 与 r=8、α=16 对齐；对话跑次在 `evaluate/dialogue/runs/`，记忆跑次在 `evaluate/memory/runs/`（如 ER `qa_er_*`，Mem0 `qa_mem0_*`）；运行时生成加载 DPO 产物，摘要关 LoRA，分类器只调 scale。口述时强调：数字不是 PPT 手写，而是可核对产物。保研与算法岗都吃「可复现」这一套。

### R72. 为什么把查询规划做成可选，而不是默认强依赖 LLM？

查询规划能把复杂问句拆成少量子查询，但对首包时延敏感，且再次引入 LLM 理解。ER 主体仍由 hybrid、扩窗、MMR 选窗等代码路径完成；规划失败回退 direct。可选化符合「检索智能尽量确定性、LLM 只做必要辅助」的立场，也便于消融「有无规划」对时延与准确率的影响。

### R73. 内容 F1 与 QA 准确率各回答什么问题？

QA 准确率回答：依赖记忆的问题能否答对，是任务层指标。内容 F1 回答：最终记忆库相对应记/应忘集合的精确率与召回，是库内容层指标。两者一起看，才能区分「库是对的但答题差」与「库就不对」。ER 在两者上相对 Mem0 都更好（QA 约 92% vs 64%，F1 约 0.86 vs 0.48），支撑的是形态优势，而不只是答题运气。

### R74. 若只能保留一个消融，保留哪一个？

保留含新近性的 MMR vs 无新近性 MMR。它直接证明读路径选择器有独立贡献（约 +8pp），且不依赖更换基线系统。主表 ER vs Mem0 仍然必要，但那是路线对照；消融回答「ER 内部哪一刀值钱」。两者层次不同，若时间只够做一个受控消融，新近性 MMR 最干净。

### R75. 终局一句话：你希望老师记住什么？

SoulHarbor 说明：在心理支持场景，生成对齐与记忆形态必须一起设计；把理解从写入挪到查询，并用同 reader 协议证明它相对写时抽取更抗误记、更保共现。对话线用 PT→SFT→DPO 把话说对，记忆线用 ER 把经历记对。数字可核对，短板（如 temporal、人工评测）也说得清。

## 小结

SoulHarbor 用领域微调回答「怎么说」，用 ER 原文记忆回答「怎么记」。对话自动指标相对裸基座有清晰提升；记忆同 reader 对照表明原文库加查询时重建相对写时抽取具有可核对优势。系统保持单卡与 SQLite 的原型形态。训练流水线（PT→SFT→DPO）、评测跑次与 `product_app/` 源码相互印证，构成上述结论的依据。
