# 05 工程实现与演示系统

## 定位

本文件只记**演示系统与工程细节**：目录、启动、API、前端职责、库表、并发与局限。

研究主线（动机、对话微调、ER 记忆、评测结论、面试问答）见 **01–04**。本篇不重复算法推导与实验表。

代码以 `product_app/` 为准；训练与评测分别在 `train/`、`evaluate/`。

## 启动与配置

### 启动

```bash
cd /root/autodl-tmp/SoulHarbor
conda activate /root/autodl-tmp/CondaEnv/soulhar
bash product_app/start.sh
# 换端口：PORT=8001 bash product_app/start.sh
```

`start.sh` 会：激活 conda → 若本机已有同端口的本服务则先停再启 → 自动选最新 `saves/qwen14b/lora/dpo_synth_*`（无则回退 archived SFT）→ 自动设 `models/encoders/bge-m3` → 默认 `MEMORY_BACKEND=er`、LLM 4bit、embed/classifier 走 CUDA → `uvicorn product_app.app.main:app`。

- 用户端：`http://<host>:8000/app`
- 管理端：`http://<host>:8000/admin/login`（默认密码环境变量 `SOULHARBOR_ADMIN_PASSWORD`，默认 `soulharbor_admin`）

更细的路径说明见 `product_app/README.md`。

### 关键环境变量

**应用 / 模型**（`product_app/app/config.py`，`SOULHARBOR_*`）：

| 变量 | 含义（默认） |
|------|----------------|
| `SOULHARBOR_LLM_BASE` | 基座，如 `models/Qwen3-14B` |
| `SOULHARBOR_LLM_ADAPTER` | chat LoRA；`start.sh` 可自动选最新 DPO |
| `SOULHARBOR_LLM_ADAPTER_SCALE` / `…_CASUAL_…` | 咨询 / 闲聊 LoRA scale（约 0.7 / 0.3） |
| `SOULHARBOR_LLM_4BIT` | 默认 `1` |
| `SOULHARBOR_MEMORY_ENCODER_BASE` | BGE-M3 路径 |
| `SOULHARBOR_CLASSIFIER_RUN` | 意图分类器目录 |
| `SOULHARBOR_DB_PATH` | SQLite，默认 `product_app/data/soulharbor.db` |
| `SOULHARBOR_POST_TURN_WORKERS` | post-turn 线程池，默认 `8` |
| `SOULHARBOR_MEMORY_ENABLED` | 全局记忆总开关 |

**长期记忆**（`product_app/app/memory/config.py`，`MEMORY_*`；研究细节见 03）：

| 变量 | 典型作用 |
|------|----------|
| `MEMORY_BACKEND` | `er` 启用长期记忆；其他值视为关闭 |
| `MEMORY_STORE_ENABLED` / `MEMORY_PROFILE_ENABLED` | Trace 入库 / Profile 旁路 |
| `MEMORY_PROFILE_LLM_PROPOSE` | 助理回合攒批后 LLM 抽白名单事实 |
| `MEMORY_PROFILE_LLM_PROPOSE_MAX` | 每次最多抽取条数（默认 **3**） |
| `MEMORY_PROFILE_LLM_TRIGGER_MESSAGES` / `…_AGE_SEC` | 攒批触发：默认 **5** 条 / **300** 秒 |
| `MEMORY_STITCH_MODE` / `MEMORY_STITCH_COS_THRESHOLD` | ER 自适应拼接；默认 cos **0.40** |
| `MEMORY_STITCH_ENTITY_DIST` / `MEMORY_STITCH_MAX_MISSES` / `…_MAX_SPAN` | 邻接实体逃逸距、连续失败停扩、跨度上限 |
| `EVIDENCE_SELECTION_MODE` | 默认 `mmr`（`topk` 可消融） |
| `MEMORY_MMR_LAMBDA` | MMR 相关-冗余权衡（默认 0.7） |
| `MEMORY_DECAY_*` / `MEMORY_REINFORCE_*` | 窗强度衰减与使用强化 |
| `MEMORY_WINDOW_TOP_K` / `MEMORY_ANCHOR_TOP_K` | 注入窗数（默认 6）/ 锚点数（默认 8） |
| `MEMORY_ASSISTANT_WEIGHT` | 助理块召回降权（默认 **0.55**） |
| `MEMORY_CONTEXT_TOKEN_BUDGET` | 注入上下文预算（默认 1600） |
| `MEMORY_ANN_ENABLED` | FAISS IndexFlatIP（失败回退 Python cosine） |

用户级开关存在 `users.memory_enabled`，经 `/api/memory/enable|disable` 切换，与全局 `MEMORY_BACKEND` 叠加。

## 后端 API 概览

入口：`product_app/app/main.py`。鉴权多为 Cookie（用户 `auth`、会话 `sid`；管理端独立 token）。

### 页面路由

| 路径 | 说明 |
|------|------|
| `/app`、`/login`、`/register` | 用户 SPA |
| `/admin`、`/admin/login` | 管理端 |
| `/health` | 健康检查 |

### 用户 API

| 方法 | 路径 | 作用 |
|------|------|------|
| GET/POST | `/api/me`、`/api/register`、`/api/login`、`/api/logout` | 账号 |
| GET/POST | `/api/conversations`、`…/new`、`…/select`、`…/rename`、`…/delete` | 会话列表与切换 |
| GET | `/api/history` | 当前会话消息 |
| GET/POST | `/api/memory/settings`、`…/enable`、`…/disable`、`…/forget-all` | 记忆开关与一键遗忘 |
| POST | `/api/chat` | 非流式对话 |
| POST | `/api/chat_stream` | **流式对话**（演示主路径） |

一轮对话大致：落库用户消息 → 意图分类（咨询/闲聊）→ 组 prompt（近期窗 + 可选会话摘要 + ER 检索块）→ GPU 生成 → 落库助理消息 → 写 `turn_metrics` → **异步 post-turn**。

### 管理端 API

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/admin/api/login`、`/logout` | 管理员登录 |
| GET | `/admin/api/stats` | 汇总统计 |
| GET/POST | `/admin/api/triage`、`…/triage_records`、`…/triage/update` | 分诊列表与状态更新 |
| GET | `/admin/api/conversations`、`…/{sid}`、`…/conversation-workspace` | 会话审阅 |
| GET | `/admin/api/users`、`…/user-profile-workspace`、`…/{user_id_hash}/profile` | 用户与画像只读侧 |

管理端不直接改用户记忆原文；Profile / Trace 供 triage 与工作区查看。

## 前端 Vue SPA

源码：`product_app/frontend/`；构建产物：`static/spa/`。

**用户侧**

- 登录 / 注册 / 对话页（`ChatView`）：多会话列表、流式气泡、输入框。
- 隐私与记忆（`PrivacyModal` + `stores/privacy`）：开关长期记忆、一键遗忘；**前端不展示检索到的记忆原文**。
- API 封装：`api/chat.js`、`api/memory.js`。

**管理侧**

- Vue 路由含 `/admin/login`；主工作区仍由 `templates/admin.html` 等承载（分诊队列、会话工作区、用户画像）。
- 能力：看待分流会话、更新 triage 状态、只读查看对话与 support profile。

无逐组件教程：改 UI 看 `views/`、`components/`；改契约看 `main.py`。

## 数据库表职责一览

单文件 SQLite（WAL）。业务表由 `app/db.py` 创建；记忆表由 `memory/store/repository.py` 幂等创建。

### 业务

| 表 | 职责 |
|----|------|
| `users` | 账号；列 `memory_enabled` 为用户级记忆同意 |
| `auth_sessions` | 登录 token |
| `conversations` | 会话：`sid`、标题、摘要字段、归属用户 |
| `messages` | 对话原文（role/content） |
| `turn_metrics` | 每轮咨询/闲聊路由标记 |
| `events` / `memory_events` | 通用事件与记忆操作审计（如 forget-all） |
| `triage_records` | 管理端分诊：status / assignee / note |

### 记忆（ER）

| 表 | 职责 |
|----|------|
| `memory_blocks` | Trace 分块原文（按 message/position；软删 `is_deleted`） |
| `memory_block_embeddings` | 块向量（BGE-M3） |
| `memory_embed_retry` | embed 失败重试队列 |
| `support_profile_items` | 白名单长期事实（active/deleted） |
| `support_profile_sources` | Profile ↔ message 证据链 |
| `support_profile_pending` / `support_profile_llm_state` | 攒批抽取状态（触发条数/年龄） |
| `memory_window_strength` 等 | 检索强化 / 运维辅助 |

启动时会补历史列、DROP 已废弃的旧记忆表名。细节以代码 `SCHEMA_SQL` / `TraceStore.init` 为准。

## 并发与 GPU 锁、post-turn 后台

**GPU 串行**：`chat_model.py` 内 `threading.RLock`。chat（含不同 LoRA scale）、会话摘要（裸基座）、Profile LLM 提议等凡走同一生成引擎的调用，**抢同一把锁**。Trace 写入与 BGE embed 不走该生成锁，但 embed 也可占 GPU。

**线程池**（`main.py`）：

- `_LLM_EXECUTOR`（`max_workers=2`）：把同步生成丢出事件循环；真正并行仍受 RLock 限制。
- `_POST_TURN_EXECUTOR`（默认 8）：对话返回后跑 `MemoryService.run_post_turn`。

**post-turn 做什么**（不阻塞流式首包之后的用户等待路径的收尾逻辑已落库）：

1. 若用户长期记忆开启：对 user/assistant 做 Trace `ingest`（分块 + embed，**无写时 LLM 抽取**）。
2. Profile：攒批达阈值后，在助理侧可选 LLM 抽白名单事实并直写 active。
3. 会话摘要：未摘要消息累计 token 超阈值时，用裸基座摘要；`_summary_lock` + `_summary_in_progress` 防同会话并发摘要。

单卡演示假设：**吞吐按串行推理**，线程池只排队与做非 GPU 杂活。

## 已知工程局限

1. **单机单卡演示**：无多副本、无请求级排队 UI；高峰时请求在锁上排队，延迟上升。
2. **SQLite**：适合原型与答辩演示；高并发写、跨机部署需换库与迁移方案。
3. **向量检索**：默认每用户 FAISS Flat + BM25；用户块数极大时需 HNSW / 外置向量库。
4. **抗陈旧主要靠读路径**：原文 Trace 无写时生命周期；靠相关性、衰减感知 MMR 与 token 预算抑制，不能保证永不召回过时处境。
5. **模型可能口头否认记忆**：需靠 system 前缀与主提示协同；不能只靠硬规则。
6. **首 token**：默认读路径无逐轮 LLM 规划；若打开拆句/重排等可选 LLM 步骤会拉长 TTFB。
7. **管理端与用户 SPA 形态不完全统一**：分诊主界面仍偏模板页；非生产级 RBAC / 审计。
8. **隐私边界**：前端不展示记忆原文，但管理员工作区可审阅对话与画像——演示前需讲清用途与脱敏。

答辩若被问到工程：强调「研究验证 + 可开关演示」，不是线上多租户产品。
