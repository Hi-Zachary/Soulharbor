# 保研面试问答手册

> **用途**：保研 / 推免面试**口述**。老师看不到仓库与代码，答案必须能直接说出口。  
> 视角：学生第一人称（「我」「我们」可混用）。数字以附录速查表为准。  
> 结构：定位 → 对话线 → 记忆线 → 原理公式 → 边界与未来 → 工程（简）→ **通用保研/校招追问（大幅扩充）** → 附录。  
> 需要核对实现细节时再翻技术文档；**本题不要念路径、文件名、配置项。**

---

## 使用说明

本手册从旧版百余题中精选约五十道高频、可深挖的问题，合并重复，按研究叙事重写。每题答案为 1–3 段**口述稿**，不是条目提纲，也不是给老师看的说明书。

**怎么用**

1. 先能用一分钟讲清「双线问题—方法—证据」，再背数字；数字错了比公式背不全更伤。
2. Profile 口径：白名单长期事实、直写、无则空；记住/忘掉由模型解析，无关键词门控。
3. 工程与部署放在第六部分；老师问前端 / 接口时，可说「工程侧不是本次主张重点」。
4. 被问到「创新点新不新」时，先承认组件已知，再落到场景约束、记忆形态假设与同协议证据。
5. 口述时用「我们做了什么 / 为什么 / 数字是多少」；不要说「某个 py 文件里怎样」。
6. **第七部分**补的是保研经验帖与校招算法面里常考、但前六部分未单独成题的内容：自我介绍、动机规划、个人贡献、困难、英语、Transformer/KV Cache、幻觉、遗忘、检索噪声等。仍要落到 SoulHarbor，避免空谈八股。

**必须能脱口而出的数字**

| 线 | 关键数字 |
|----|----------|
| 对话 BLEU-1 | base **13.23** → SFT **29.56** → DPO **27.91** |
| 记忆（同 reader，`all_50`） | ER QA **90.5%** / staleness **8.6%** / F1 **0.783** vs Mem0 **68.7%** / **46.6%** / **0.400** |
| 消融（归档） | 无新近性 **84.4%** → 含新近性 **92.2%**（约 +8pp） |
| 训练规模 | PT 24443 → SFT ~2万（含自我认知补充）→ DPO 3000；意图 3000/300/300 |
| LoRA / scale | r=8、α=16；咨询 0.7 / 闲聊 0.3 |

# 第一部分 定位与创新

### Q1. SoulHarbor 是什么？用一句话说清研究问题。

SoulHarbor 是面向校园场景的心理健康**辅助**对话研究原型，不是临床诊断系统。我们面对的核心矛盾是：校园咨询资源紧、污名压力大，同学缺的常常不是标准答案，而是一个低门槛的倾听入口——先被听见，而不是先被教育。

研究问题可以收成一句：在校园心理支持对话里，如何同时解决「基座模型不会好好倾听」与「跨会话记忆容易乱记」。前者对应对话线——用 PT→SFT→DPO 把说话方式对齐到倾听任务；后者对应记忆线——Trace 原文入库、查询时 ER 重建，再配严白名单 Profile，避免把瞬时情绪冻成错误特质。若只能说二十个字：「让倾听模型会好好说，也让记忆系统不乱记。」

### Q2. 为什么不直接接通用大模型 API？

通用 API 便于对话，但在心理健康场景里暴露两类结构性不足。其一是语气与边界未针对倾听对齐：容易空泛安慰、急于给建议或说教——SoulChat（EMNLP Findings 2023）已经把这类失败模式说得很清楚。其二是缺乏可靠的跨会话记忆；即便引入记忆，主流写时抽取又容易把短暂情绪固化为错误标签，后面越聊越偏。

我们因此选择职责解耦、本地可复现的方法载体：独立小分类器管语气强度；长期记忆走「原文入库 + 查询时重建」；Profile 只收白名单长期事实。API 路径更适合纯产品演示，却难完整承载本地 ER、MacBERT、LoRA scale 切换与可审计训练产物——本项目同时承担方法复现，不能把关键能力全部外置。

### Q3. 两条主线创新如何表述，才像研究贡献而不是功能清单？

对话线贡献：在 Qwen3-14B 上完成 PT→SFT→DPO 链式对齐，并用独立 MacBERT 按咨询/闲聊调节**同一份** chat LoRA 的推理 scale（约 0.7 / 0.3），使语气强度与权重文件解耦。证据是相对裸基座的 BLEU/ROUGE：BLEU-1 从 13.23 到 29.56（DPO 后 27.91）。

记忆线贡献：提出并实现 ER（Experience Rebuild）——Trace 写路径零 LLM 原文入库，读路径经 Planner → hybrid 召回 → **多查询 coverage Anchor CE** 选种子 → 自适应扩窗 → Legacy 时间感知 MMR 在查询时重建经历证据；Profile 仅白名单旁路（identity / education / location / preference），无则空。证据必须说清：正式集 `all_50` 上 QA **90.5%** vs Mem0 **68.7%**，staleness **8.6%** vs **46.6%**，F1 **0.783** vs **0.400**。口述时「贡献句 + 证据句」成对出现，避免停在口号。

### Q4. 这算算法创新，还是系统/问题驱动创新？

更稳妥的表述是**问题驱动的系统与方法创新**，而不是宣称发明全新损失或全新骨干。对话侧把续训、指令微调、DPO、PEFT、小分类器对准倾听任务，并做出「一份 LoRA + 路由 scale」的职责设计；记忆侧改变的是记忆单元与读写时序——理解从写入后置到查询，经历窗替代压缩事实句。

这类贡献常见于系统方向：新意在约束下的问题重构、可核对对照协议与消融。`all_50` 相对 Mem0 QA 约 **+22pp**；归档新近性消融约 **+8pp**（84.4%→92.2%），说明形态与选择器假设可被检验。应避免两种极端：把工程拼装说成「全新算法」，或因为用了已知组件就否认贡献。

### Q5. 老师说「微调加 RAG 到处都是，这不新」怎么回应？

我先同意前提：微调与检索增强作为名词确实不新。然后把讨论拉回特殊约束。心理场景的代价结构是「误记重于漏召」；写时抽取在入库时改写用户，错误标签会长期反复注入。经典 RAG 回答「哪段文档相关」；ER 回答「如何从原文重建一段可审计的经历证据」——自适应扩窗、衰减感知 MMR、时间排序注入、严白名单 Profile，都超出 embedding + top-k。

对照实验也不该被说成随便换了个 RAG：基线是同协议 Mem0，固定 reader，只换记忆库。差距集中在共现上下文、跨会话整合、最新状态与抗 stale，与「保住共现、抗陈旧」的设计预期一致。我们并不否认写时抽取在客服百科等场景可能更合适；主张的是在心理长程对话的代价结构下，原文重建更对齐目标。

### Q6. 为什么微调与记忆必须一起做？

只微调不记忆：模型学会倾听，跨周回来仍像陌生人；「上周冷战、这周又来」无法衔接，倾听退化成每次从零开始的安慰。只做记忆不微调：记得住细节，但基座默认语气仍可能空泛、说教；记忆块甚至会被用错语气消费，出现「记得很准但说得很伤人」。

两条线对应两类失败模式，解耦实现、联合交付。产品上记忆可关，说明记忆不是生成硬依赖；研究叙事上，完整问题定义需要两者同时成立。评测也分开度量：对话看 base/sft/dpo，记忆看同 reader 换库，避免用一条线的指标证明另一条线。一个好用的类比：微调决定「音色」，记忆决定「有没有共同经历」。

### Q7. 相对 SoulChat、EmoLLM，本项目新在何处？

SoulChat 等工作明确心理支持需要共情与倾听，并提供 SoulChatCorpus；EmoLLM 等开源实践说明中文心理语料上的续训与指令微调能改善分布适配。我们对话线明确站在这一传统上：SFT 约九成 SoulChatCorpus、约一成 EmoLLM；PT 用 EmoLLM 心理问答片段约 24443 条；再补 DPO 与 MacBERT 路由感知 scale。

相对这些工作的增量，主要不在「又训了一个心理模型」，而在把跨会话经历记忆做成与写时抽取可对照的方法问题，并用同 reader 协议给出 QA / staleness / F1。前人把「怎么说」做成可训练任务；我们进一步把「怎么记」做成可证伪的子系统。贡献叙事是叠加，不是替代。

### Q8. `is_consult` 分类器现在控制什么？不控制什么？

它只控制两件事：chat LoRA 的推理 scale（咨询约 0.7 / 闲聊约 0.3），以及 `turn_metrics.route` 用于观测与管理端分诊筛选。它**不**控制是否检索长期记忆、是否运行记忆写路径、用户是否开启记忆。记忆路径只看用户设置中的 `memory_enabled`，与 `is_consult` 完全解耦。

这样设计是因为闲聊中也可能提到上周的事；把记忆绑死在咨询路由上反而丢信息。偶发误判的代价因此只是语气强弱，而不是整条对话行为被带偏。验证准确率约 99.7% 只说明在构造的对照集上判别很准，不意味着开放域永远正确——正因为记忆不依赖它门控，误判被限制在语气层。

# 第二部分 对话线（CPT / SFT / DPO / LoRA / 分类器 / 评测）

### Q9. 训练主线分几步？各自解决什么？

| 阶段 | 数据（约） | 目的 |
|------|------------|------|
| 继续预训练 PT | EmoLLM 心理问答片段 24443 条纯文本 | 适配心理中文 token 分布 |
| 指令微调 SFT | 倾听约 20000（SoulChat≈9 成 + EmoLLM≈1 成）**+** 自我认知约 274，**同一阶段混合** | 学咨询应答；顺带锁「我是 Soulharbor」等人设 |
| DPO | 3000 对偏好数据（挂载 SFT 权重） | 压制空泛、欠共情、敷衍、说教 |
| 意图分类 | 3000 条咨询/闲聊对照（正负 1:1） | 训 MacBERT-base 二分类 |

框架是单卡 QLoRA 四比特；全链路 LoRA 秩 8、α 16。主线就是 **PT → SFT → DPO** 三步，不要把自我认知讲成第四个独立阶段——它只是 SFT 混合数据里的一小撮人设样本（大约 274 条相对两万多），占比很小，超参与倾听数据相同。评测里说的 **sft**，就是进入 DPO 前的那份 SFT 权重。三个阶段不能互相替代：PT 解决「域语言不熟」，SFT 解决「会不会接话、身份稳不稳」，DPO 解决「优选哪一种听感」。

### Q10. 为什么先 PT 再 SFT？有没有 PT 消融？

通用基座在百科、代码、新闻上分布偏多，对心理咨询口语化表达相对陌生。PT 用领域文本继续做因果语言建模，降低心理语料上的困惑度，再做 SFT 更易收敛到正确格式与风格。学习率也最高放在 PT（约 5e-5），符合「先搬分布、再学任务、最后做偏好」。

当前**没有**单独报告 PT ablation，因此不能声称「已证明 PT 必要」。答辩策略是：说明动机与工程惯例；承认因果证据不足；给出补实验设计——心理 unseen 上对比 PT 前后 perplexity，检查通用语料是否明显变差，并看下游 BLEU/ROUGE 是否因 PT 更稳。把缺口讲成可执行下一步，比硬辩「一定有用」更好。

### Q11. 为什么要微调，而不是只靠 Prompt 或 RAG？

Prompt 能写边界与口吻，但很难稳定改写模型在心理口语上的默认生成分布；system 越写越长，还会与记忆注入争上下文，并放大 Lost in the Middle。RAG/ER 解决的是外部证据从哪来，不解决给定证据后如何以倾听方式说话——同一段「上周冷战」证据，说教模型与共情模型会说出完全不同的话。

我们把「怎么说」交给 PT→SFT→DPO，把「记什么」交给 ER，生成前再拼接。证据上，裸 Qwen3-14B 的 BLEU-1 约 13.23，SFT 后约 29.56，相对跃升约 +16，说明基座默认能力加简单提示远未达到领域对齐水平。微调不是否定 Prompt/RAG，而是承认它们解决不同子问题。

### Q12. 为什么选 DPO 而不是完整 RLHF / PPO？

SFT 用高质量回复做监督，是格式与咨询节奏的底座。完整 RLHF/PPO 适合多维、需在线探索的奖励，但要奖励模型、采样环与更重的稳定性工程。DPO 把含 KL 约束的 RLHF 最优策略写成闭式，用 chosen/rejected 直接优化，匹配我们「一维、可离线描述」的偏好：少空泛、少欠共情、少敷衍、少说教。

我们在 **SFT 权重**上续训 DPO：3000 对、`pref_beta=0.1`、lr=5e-6、1 epoch。选型逻辑是问题维度 × 数据形态 × 单卡约束，而不是「DPO 一定优于 PPO」。若奖励变成安全/简洁/共情多维联合，或需要策略在线探索，再评估完整 RLHF 更合适。「不做」应讲成阶段性取舍，不要把「没做」说成「RLHF 无价值」。

### Q13. DPO 数据如何组织？合成 rejected 的风险与质检？

Prompt 池从 SoulChat 等多轮语料切「上文 + 当前用户句」，并与已进主 SFT 的样本互斥以防泄漏虚高。Chosen 取语料中较好的助手回复；Rejected 由外部模型（MiniMax-M2.7）按「仍相关但更敷衍/欠共情/说教」指令合成，再经质检过滤。

主要风险有三类：负样本流畅却并不更差甚至反超 chosen，优化会学反；负样本离题过远，对比过容易，偏好信号假强；topic 不均衡。质检脚本过滤明显不可用负样本并尽量保持 topic 均衡；β=0.1 与低学习率限制更新幅度。上限必须讲清：合成偏好对准的是可描述失败模式，不是人类全维度价值；共情胜率若要硬结论，需另做人工或 LLM-as-judge。

### Q14. DPO 后 BLEU 略降如何解释？完整自动指标怎么读？

先要能说清指标在算什么。**BLEU** 看生成 n-gram 有多像参考，偏精确率；我们是中文分词后的词级 BLEU-1 到 4。**ROUGE-1/2** 是 n-gram 重叠的 F；**ROUGE-L** 用最长公共子序列的 F，对词序微变稍宽容。BLEU 更「像不像那句」；ROUGE 更「参考盖住多少」。

在 SoulChatCorpus seen/unseen 各 1000 条上（**sft** = 进 DPO 前的 SFT 权重）：

| 模型 | BLEU-1 | BLEU-2 | BLEU-3 | BLEU-4 | ROUGE-1 | ROUGE-2 | ROUGE-L |
|------|--------|--------|--------|--------|---------|---------|---------|
| base | 13.23 | 5.55 | 2.50 | 1.32 | 20.52 | 4.17 | 15.04 |
| sft | 29.56 | 13.06 | 6.90 | 4.17 | 30.65 | 7.89 | 24.64 |
| dpo | 27.91 | 12.59 | 6.46 | 3.75 | 31.49 | 8.06 | 24.44 |

SFT 相对 base 的跃升说明领域对齐有效——这是微调有收益的主结论。DPO 的 BLEU 略低于 SFT，而 ROUGE-1/2 略高或持平，符合「优化偏好、表达更自然多样时，与单一参考答案的字面重合可能下降」。心理对话没有唯一标准答案，自动指标只适合相对比较；**不能**因为 BLEU 略降就断言 DPO 失败。DPO 要换的是听感，不是字面重合峰值。

补一句解码边界：正式跑次 temperature=**0.95** / top_p=**0.75**，线上默认约 **0.6 / 0.95**——数字是同设定下的相对差距，不宜直接等同线上听感。

### Q15. BLEU/ROUGE 测心理对话是否合理？为什么没有系统人工评测？

合理作为**相对**尺度，不合理作为**绝对**共情度量。从公式也能看出边界：BLEU/ROUGE 都依赖**单一参考**的 n-gram 或 LCS 重合；心理回复往往一词多安、无唯一金标准，会低估合理但换表述的好回复，也会高估套话式重合。我们用其证明 base→sft 的分布对齐，并解释 dpo 的 BLEU 回落；共情、安全感、是否说教等维度若要结论，需要人工量表或 LLM-as-judge，终稿未系统展开——这是明确缺口，不必回避。

补强叙事有三条：不把自动指标宣传成主观体验结论；记忆侧用固定 reader 隔离答题能力，比对话 BLEU 更硬地指向记忆形态差异；若续作，优先做小规模盲评（同 prompt 下 base/sft/dpo 的共情与说教强迫选择）。诚实承认缺口并展示已有证据链，通常好过虚构「已充分人工验证」。

### Q15b. 记忆侧 QA、staleness、内容 F1 各自什么原理？公式怎么写？

三套指标回答不同子问题。

**QA 准确率**：固定 reader 下答题正确比例 $\frac{1}{N}\sum \mathbf{1}[\mathrm{correct}]$。终版约 90 个探测点；同 reader 只换库时，差归因于记忆形态。

**过时率**：专门测「把过时状态当成当前」的那类题上的错误率，越低越好。不是「库里还有没有旧经历」，而是当前题有没有被旧证据带偏。`all_50` 上 ER 约 **8.6%**，Mem0 约 **46.6%**。

**内容 F1**：对照 `should_remember` / `should_forget` 金标准，用**同一 MiniMax reader**做 JSON 对齐得到 TP（应记命中）、FN（漏记）、FP（误存应忘），再算 $P=\mathrm{TP}/(\mathrm{TP}+\mathrm{FP})$，$R=\mathrm{TP}/(\mathrm{TP}+\mathrm{FN})$，$F_1=2PR/(P+R)$。解析失败且有应记时，实现按全漏记处理（偏严）。QA 看答题，F1 看库相对金标准齐不齐、脏不脏；F1 本身带 LLM judge 噪声，主看同协议相对差。

口述口诀：`all_50` QA **90.5% vs 68.7%**；staleness **8.6% vs 46.6%**；F1 **0.783 vs 0.400**。禁止用这三项证明对话线 DPO，也禁止用 BLEU 证明 ER。

### Q16. LoRA / QLoRA 超参如何设定？推理 scale 与 α、r 有何区别？

选 QLoRA 是为了单卡承载 14B；用同一份 chat LoRA 的 scale 区分场景，而不是挂多份适配器。全链路统一 r=8、α=16，注意力和前馈相关投影都适配。学习率阶梯大致为：PT 5e-5 → SFT 2e-5 → DPO 5e-6，越往后越保守。未做系统的 rank 网格搜索——这是够用设置，不是已证明最优。

三者独立、极易混淆：训练期 α、r 决定低秩增量写入的量级；推理 scale 是运行时额外乘数（咨询 0.7 / 闲聊 0.3）；DPO 的 β 又是与 LoRA α 无关的另一维。改 scale 无需重训；改 α/r 必须重训。MacBERT 只输出路由以选择 scale，从而实现「一份 chat LoRA、多种语气强度」。

### Q17. 为什么选 14B？为什么用 LoRA 而不是全参？

14B 在 4-bit QLoRA 下可单卡训练与推理，中文与指令能力相对够用，是效果、显存、可复现的折中。7B 更省，但在拼接记忆、摘要与多轮咨询节奏上，我们优先保留更大基座的表达余量。更大模型超出单卡原型预算。14B 是方法载体，不是规模消融后的全局最优——换 32B 可能更好，但必须重跑训练与评测，不能把现有数字直接外推。

全参更新 14B 时，权重、梯度与 Adam 状态显存远超单卡。QLoRA 将基座存为 4-bit（NF4 等），只训练低秩适配器。LoRA 假设任务增量近似落在低维子空间；我们全链路 r=8、α=16，覆盖注意力与 FFN 相关投影，因为心理对话风格变化往往不只落在注意力。表述用「在可部署约束下达到可核对收益」，避免绝对宣称「LoRA 无损全参」。

### Q18. 为什么意图分类器用 MacBERT，而不是让大模型自己判？会话摘要为什么关 LoRA？

先讲原理再讲选型。MacBERT 是中文 **双向 Encoder**（Findings of EMNLP 2020）：预训练用改进版 MLM——用近义词替换而不是裸 `[MASK]`，减轻预训练与微调的 mismatch。我们在骨架上挂序列分类头：整句编码 → [CLS] → 二分类 logits → `is_consult`。这是标准交叉熵分类，不是生成。

咨询/闲聊本身是简单二分类。用 **chinese-macbert-base** 在 3000 条对照数据上训练（正负 1:1，按字长对齐；lr $2\times 10^{-5}$，1 epoch，max_len 512），验证准确率约 99.7%。线上优先加载 trainer 的 best checkpoint。选 base 而非 large、也不用 14B 零样本判：延迟差一个量级，且避免「大模型既当裁判又当运动员」；误判代价应停在「语气强弱」，不能膨胀成整条策略切换。MacBERT 职责刻意收窄为 LoRA scale 旋钮，不门控记忆。

摘要任务需要的是压缩与保真，不是共情腔。chat LoRA 为倾听风格对齐；若带着 scale 做摘要，容易把安慰套话写进压缩文本，污染后续长期上下文。实现上摘要关掉适配器、走裸基座，温度也偏低（约 0.3）。这与「一份 LoRA 多用途」不矛盾：用途切换靠开关适配器，而不是强行共用语气。

### Q18b. BGE-M3 是什么？原理是什么？为什么记忆用它、还要不要另训？

原理上，嵌入模型把文本映成固定维向量，让语义相近的文本在空间里靠近；检索用余弦（向量 L2 归一化后即内积）。训练常见是 **双塔 + 对比学习**：查询与文档分别编码，正配对拉近、负配对推远；文档可离线预计算，这才撑得起「写时嵌入、读时召回」。

**BGE-M3**（BAAI，[arXiv:2402.03216](https://arxiv.org/abs/2402.03216)）是多功能检索模型：dense / sparse / multi-vector。我们经 FlagEmbedding 只取 **dense 1024 维**，本地路径 `models/encoders/bge-m3`，**不另训**。词法侧另用字级 BM25，再用 RRF 融合——dense 抓同义改写，BM25 抓专名数字。扩窗时邻接句与锚点的 $\cos$ 也是同一套几何。

选型三句：中文检索强、开箱即用；与 BM25 互补；本地可复现。务必补一句：**向量不是记忆本身**——证据主体是 Trace 原文；M3 只是检索键。创新在 ER 写形态与读路径重建，不在重训 embedding。

### Q18c. Qwen3-14B 作为基座，原理上和 MacBERT / BGE-M3 差在哪？

Qwen3 是 **decoder-only 因果 LM**：用因果掩码做 $p(x_t\mid x_{<t})$，整段回复按链式法则逐 token 生成；PT/SFT 都在这个最大似然框架里，DPO 再叠偏好。MacBERT / BGE-M3 是 **Encoder 系**：双向看整句，输出分类 logits 或句向量，不负责把倾诉写成自然语言回复。

一句话分工：Qwen3「怎么说」，MacBERT「说多用力」，BGE-M3「怎么找到原文」。推理时关闭 thinking，避免长思考链混进用户可见回复。为什么不端到端一个大模型包办三者？失败模式与延迟预算不同，解耦才能独立评测和降级。

### Q19. 数据质量、互斥切分与过拟合如何讲？

心理对话微调对噪声与泄漏极敏感。SFT 约 20000 条经过去重、低质过滤、长度截断与模板统一；DPO 的 prompt 池与主 SFT 按对话 **signature**（前 ≤6 条消息）互斥，避免同对话既监督又偏好。对话评测 seen/unseen 各 1000 也按同一套 signature：进过 SFT+DPO 训练池 → seen，否则 → unseen；再 topic 均衡抽样（seed 20260426）。因此 unseen 是「签名未进训练」，**不是**「从没见过的话题领域」。意图数据按字长对齐，减少「长句=咨询」捷径。互斥不是万能：主题相近仍可能残留——应主动说明。记忆 30 弧独立合成、不进入生成训练，是另一条防泄漏线。

过拟合常见迹象：seen 远好于 unseen、复读训练集套话、DPO 后多样性塌缩。我们分开报告 seen/unseen；DPO 仅 1 epoch、小学习率。DPO 后 BLEU 略降本身不一定是过拟合；更要看是否出现重复口头禅、异常变长或 unseen 崩塌。

### Q20. 基模越来越强之后，领域微调还有没有价值？

有。更强基座减少的是知识与通顺性缺口，不一定消除任务偏好错位：心理场景仍常见急于给建议、空泛安慰、说教。我们用 DPO 专门锁这些失败模式。此外还有部署与复现约束：本地 14B + LoRA 便于数据驻留、记忆向量与分类器闭环、训练产物可核对。

价值表述建议从「补笨」转为「锁分布与失败模式」。基模升级常常改善知识，但「急于给建议」这类偏好失败可能以新的流畅形式出现。领域对齐的价值，正是持续对准任务失败，而不是追基模排行榜。证据是 base→sft 的自动指标跃升，以及 dpo 相对 sft 出现符合偏好优化的 BLEU/ROUGE 模式。

# 第三部分 记忆线（ER / Profile / 对比 Mem0·MemMachine / 消融）

### Q21. 为什么需要长期记忆？长上下文能否替代？

长上下文解决的是「一轮能塞多少」，不解决「跨会话该给哪些」与「不该把什么当现状」。用户反复讲述学业压力、室友矛盾或失眠经历时，若每轮从零开始，共情再好也难以衔接。记忆系统的价值在于跨会话选择、原文证据、可控注入与隐私开关（用户可关记忆或一键遗忘）。

即便上下文窗口足够大，「全塞进去」仍会受 Lost-in-the-Middle 影响，并让旧状态污染当前判断。因此 ER 首先是「在上下文里放什么」的决策器，其次才是检索器。长上下文解决容量，不自动解决跨会话选择与 stale。

### Q22. 记忆存什么？为何坚持 Trace 原文库？

现行 ER 对 Trace **只存原文**：每条消息按确定性规则分块、BGE-M3 向量化后写入，不做抽取、不归纳、不概括。另有 Profile 旁路：仅白名单内的长期事实（identity / education / location / preference）可经 LLM 写入；无则空着。

心理场景里，任何写时理解都带风险——把「这次考砸」改写成稳定负面标签，就是写时污染。原文库把理解后置到读路径：系统保证存得全、查得准，不保证「先归纳好」。漏掉一段旧经历最多是「没帮上忙」；错误归纳却可能把用户推向错误的自我认知。因此记忆不能只追求「记得更多」，更要避免「乱记」。

### Q23. ER 与 Mem0 一类写时抽取路线差在哪里？

分歧不在「要不要记忆」，而在「记忆是什么形态」。Mem0 属于写时抽取事实句再向量检索：每轮用大模型把对话压成事实句入库，检索时注入已被压缩的事实。ER 走相反路线：对话原文原样入库，检索时再按查询扩窗重建为一段完整经历。

| 维度 | 写时抽取（如 Mem0） | SoulHarbor ER |
|------|---------------------|---------------|
| 写入 | LLM 每轮抽事实、合并、覆盖 | 原文块确定性分块 + 向量化，Trace 零 LLM |
| 存储单元 | 事实句 / 语义标签 | 原文经历（多轮窗口） |
| 检索 | 向量搜事实 | hybrid → **Anchor CE 选种子** → 扩窗重建 → Legacy 时间感知 MMR |
| 注入 | 事实句列表 | 用户原文经历 + 日期来源 + active Profile |
| 写时污染 | 结构性存在（抽取即改写） | Trace 侧结构性不存在 |

同协议对照下（`all_50`）：QA **90.5% vs 68.7%**，staleness **8.6% vs 46.6%**，内容 F1 **0.783 vs 0.400**。差距来自记忆形态，而非答题能力。

### Q24. 同协议对照时 Mem0 侧做了什么？为何选 Mem0 作基线？

对照实验让 ER 与 Mem0 在**完全相同的对话流**上逐轮写入：ER 存原文块；Mem0 走写时抽取路线——同样用大模型抽事实，同样用本地 BGE-M3 做向量、本地向量索引检索。测试点双方共用固定答题模型，只替换「该方法检索得到的记忆块」。准确率、过时率、内容 F1 的差距应归因于记忆形态，而不是答题模型、试题，或「谁的编码器更好」。

数据是 30 条按规范**合成**的校园长程弧（连续数周、多会话），每弧约 3 题并配应记/应忘金标准——不是真实来访录音。无记忆基线只能说明「记忆有没有用」，不能说明「哪类记忆形态更好」。研究主张针对写时抽取在心理场景的结构性风险，因此需要同协议的写时抽取代表；Mem0 工程完整、可对接同一对话流。自比消融（有无新近性）与 Mem0 主表回答不同问题，不能互相替代。

### Q25. ER 是否就是「不抽取、全量存原文」的 RAG？与 MemMachine 式宽画像如何对照？

不完全是。单元不同：经典 RAG 的单元是文档切片，目标是「哪段文档相关」；ER 的单元是一段经历——**Anchor CE 选种子**后沿会话做自适应扩窗，把来龙去脉扩出来。重建是显式的：扩窗、重叠合并、Legacy 时间感知 MMR（去冗余 + 相对新近性 + 周桶），这些都超出「取分最高的 top-k」。写侧哲学也不同：ER 不决定「哪句话值得记」，每条 user/assistant 消息都入库，理解完全后置。

相对更偏 MemMachine 思路的宽画像路线——追求宽覆盖、提前把摘要写进画像——我们故意做窄。宽画像在通用助手里可能提高表面连贯，但在倾听场景里错记代价高于漏记。Profile 只允许白名单长期事实；空 Profile 是合法状态，不是系统没跑起来。严白名单不是功能缺失，而是刻意比宽画像更保守。

### Q26. Profile 现在怎么做？与「Trace 写路径零 LLM」是否矛盾？

不矛盾，但表述必须准确。记忆有两条独立写通道。

**Trace（主体）**：消息 → 确定性分块 → 向量化 → 原样入库。该通道无 LLM，也是检索注入的主要数据来源。

**Profile（旁路）**：唯一允许「理解」落库的地方，但内容被 **schema 白名单** 锁死——只收 `identity`（姓名/性别/年龄）、`education`（学校/年级/专业/学历）、`location`（家乡/常住地）、`preference`（沟通偏好/爱好/生活习惯等）；诊断、人格标签、瞬时情绪、单次事件不抽。LLM 抽取（攒批触发，约 5 条消息或 300 秒）后**直写 active**；抽不到就空列表，不强行写。用户侧「记住 / 忘掉 / 更正 / 查看」由另一路 LLM 指令解析，**无关键词正则门控**；边界靠 schema 的 `is_allowed`——即便模型胡写「抑郁症患者」，也无法通过校验落库。注入时 active 全量给出（上限约 30）。

旧版曾强调 pending 确认队列；终稿已改为白名单直写 active。准确说法始终是「Trace 写路径零 LLM」；Profile 是窄白名单旁路，宁缺毋滥。

### Q27. 读路径（查询时 ER）如何组织？

流水线：Planner → hybrid 召回 → **Multi-query Anchor CE（coverage 选种子）** → 自适应扩窗 → 窗合并 → Legacy 时间感知 MMR → 时间升序注入。

**查询规划**：复杂问句可先让模型低温拆成一条或多条短查询（适合比较、多对象）；失败就退回整句检索。CE 会对「原始 query ∪ Planner 子查询」分别打分，再 coverage 式选 top-12 anchor 种子。

**hybrid**：BGE-M3 cosine（assistant 块 ×0.55）+ 字级 BM25 → RRF（$k=60$）→ fused **top-40**。字级 BM25 对人名/专名/数字敏感，与 dense 互补。RRF 只负责高召回与截断。

**Anchor CE**：对 fused top-40 上的裸 anchor 用 BGE cross-encoder（`bge-reranker-v2-m3`）做多查询打分；原始 query 保底 top-4、每个子查询 top-3，去重补齐到 12。**不做 CE 与 RRF 数值混合**；窗级 CE 已否定、默认关。

**扩窗**：语义连续为主（$\cos\ge 0.40$）；邻接（≤2）且「实体」重叠为逃逸通道。这里的实体是**正则启发式**（2–6 字中文块、英文标识、带单位数字），**不是 NER**。连续失败 2 次停；跨度与窗内条数有上限。重叠/相邻窗再合并，得到完整经历单元。

**选窗**：$R_{\mathrm{content}}=2\cdot s_{\mathrm{fused}}+1.5\cdot\mathrm{Jaccard}$（fused 来自 RRF），再叠加 decay、相对新近性（$\beta=0.8$）、周桶奖励（$0.5$），进 MMR 去冗余（默认至多 6 窗）。时间升序注入 `<memory>`（只含 user 原文 + 全量 active Profile）；全局约 1600 token，超预算整行裁剪。跨会话不靠显式链式打分，而靠多窗召回 + 时间序注入。

### Q28. 抗 stale 如何做？为何不做写时过期状态机？

「上周冷战、这周已和好」若仍被当作现状注入，即为 stale 伤害。我们刻意不做写时生命周期标记，因为「过期」本身也是写时判断、也会判错。抗 stale 放在读侧：只选与查询相关的经历；**Anchor CE** 保证多子查询证据覆盖；Legacy MMR 含相对新近性与周桶；强度衰减压低长期未强化旧窗；token 预算整行裁剪；system 前缀明确「与用户此刻说法冲突时以当前说法为准」。

评测上：`all_50` staleness **8.6% vs Mem0 46.6%**。把 stale 当读路径问题而不是写路径标注问题，是 ER 立场的一部分。旧经历仍可被问到，但不应压过用户此刻的自述。

### Q29. 衰减感知 MMR（含相对新近性）的消融说明什么？

在归档消融（无 CE 历史路径）上，选择器用 Decay-aware MMR，并加入相对新近性与未见周桶奖励。去掉新近性后同协议 QA 约 **84.4%**、staleness 明显升高；加回后约 **92.2%** / **14.3%**。正式代码已固定含 Anchor CE；该消融说明「选哪几段经历注入」本身是建模对象：只做相关−冗余时，早期高相关旧状态容易挤掉终态窗。

**现行正式默认**保留 Legacy 时间感知 MMR（recency $\beta=0.8$、week $0.5$），窗级 $R_{\mathrm{content}}$ 仍为 $2\cdot\mathrm{fused}+1.5\cdot\mathrm{Jaccard}$；**Anchor CE 放在扩窗前选种子**，窗级 CE 已否定。解读要点不变：读路径选择器不是琐碎后处理；也不要把单次消融夸大成 ER 相对 Mem0 的全部差距。

### Q30. 如何证明记忆系统有效？30 条够不够辩护？

协议刻意固定答题能力：用外部模型按规范合成长程咨询弧（正式集 `all_50`，50 案 / 250 题）；ER 与 Mem0 在同一对话流上逐轮写入；延迟测试点用**同一个固定 reader** 只接收「该方法的记忆检索块 + 试题」作答。终版 coverage CE：ER QA **90.5%** / staleness **8.6%** / F1 **0.783** vs Mem0 **68.7%** / **46.6%** / **0.400**。

30 条是受控长程弧，六类能力各若干，目标是能力维诊断与同协议对照，而不是互联网规模刷分。辩护三步：协议严格、归因清晰；逐类结果与设计预期对齐（共现/整合/抗 stale 优势大，细节双方都强，时序双方偏弱）；明确外部效度边界——结论是同协议下的相对优势，不宜直接外推到任意用户规模。30 条 × 每条约 3 题，实际是约 90 个记忆依赖探测点，再加内容 F1。

### Q31. 为何入库含助理话轮，注入却只取 user？注入位置有什么坑？

助理话轮入库，是为了扩窗时判断语义邻接；没有它，许多语义桥会断。Formatter 注入时只保留 user 原文，是为了避免把咨询师的反映式倾听当成用户亲口事实，并在有限预算下优先保留用户证据。这是「存全量、用子集」的不对称设计；assistant 召回降权约 0.55。

Qwen chat template 对多条 `role=system` 不稳定：多条 system 可能被合并，后放的记忆块容易被忽略。现行做法是把 `<memory>` 作为一条 system 放在摘要之后、未摘要原文之前，并附行为级前缀：说明其为历史背景、无关可忽略、冲突以当前说法为准、禁止补充检索结果之外的事实。离线对比中，注入块形式与位置是单变量改进较明显的一处。

### Q32. 失败演进（写时抽取→ER）如何讲才像科研？

用「假设—观测—修订」，不要按时间报流水。假设一：写时理解可提高可用性。观测：即便工具调用指标尚可，只要写入时理解就必然偶尔写错，错误长期留库，心理场景不可接受。假设二：分层与写时调和可缓解污染。观测：根因未变，底层仍在写入时改写用户。修订：Trace 不理解、读时再理解——原文入库；读路径补自适应扩窗与含新近性的 MMR；Profile 收成严白名单旁路。

中间态保留在 archive，终稿只描述 ER。真正改进的是「理解发生的时刻」，不是「检索更花哨」。收尾落到证据：同协议相对 Mem0 的差距，以及新近性消融约 +8pp。口述收束可用一句：「我们不是换了三个工程方案，而是被误记代价逼着把理解从写入挪到了查询。」

### Q33. temporal 偏弱如何归因？下一步怎么改？

时序维双方都偏弱，是共同短板。可能原因包括：题面更依赖显式先后与时间锚，而注入以相关经历窗为主，时间顺序信号不够显式；扩窗与 MMR 优化的是相关性与去冗余，不是时间推理专用目标；reader 本身对细粒度时序也非完美。

下一步可在证据链中加强时间戳呈现与排序提示，或增加时序探针数据，而不是简单加大 top-k。归因时应避免单因叙事，把它讲成双方共同的开放问题，反而更像严谨研究：你知道自己的短板在哪，也知道短板不一定能靠「再堆一点检索」解决。

# 第四部分 原理深挖（公式问答：LoRA、DPO、RRF、MMR）

### Q34. LoRA 的核心公式与直觉是什么？本项目怎么用？

LoRA（Hu et al., 2021）冻结预训练权重 $W_0$，只训练一对低秩矩阵：

$$W = W_0 + \frac{\alpha}{r}BA$$

其中 $A \in \mathbb{R}^{r\times d}$、$B \in \mathbb{R}^{k\times r}$，$r \ll \min(d,k)$。直觉是：大模型在许多任务上只需远小于全参数空间的内在维度即可接近全量微调；$\Delta W$ 落在低维子空间。PEFT 默认 $A$ 高斯随机、$B$ 置零，故训练起点 $\Delta W=\mathbf{0}$，行为等于基座。

本项目全链路 r=8、α=16（α 除以 r 等于 2）。以单层大约三千多维、r=8 粗算：全量参数平方量级，LoRA 大约是两倍 r 乘维度，比例约千分之几。运行时只加载一份对话适配器，用推理 scale 在咨询 0.7 / 闲聊 0.3 间切换；摘要则关掉适配器走基座。

### Q35. QLoRA 与 4-bit / NF4 在本项目中扮演什么角色？

QLoRA（Dettmers et al., 2023）= 4-bit 量化基座 + LoRA。常用组件包括 NF4、Double Quantization、Paged Optimizer。NF4 按标准正态分位构造 4-bit 码本，更适配预训练权重近似高斯的分布，量化误差通常优于朴素等距 INT4。口诀是：**4-bit 用于存储冻结基座；计算在 fp16；优化器只服务 LoRA。**

粗略显存对照：全量 fp16 权重约 28GB 量级，再加梯度与 Adam 可达百 GB；QLoRA 基座约 7GB 量级，主要服务 LoRA，可落在单卡可接受范围。量化主要损失细枝末节方向，主成分信号相对保留；本项目以下游自动指标与可部署性为接受标准，而不是空谈无损失。

### Q36. DPO 损失怎么写？β 的直觉是什么？

DPO（Rafailov et al., 2023）把含 KL 正则的 RLHF 目标写成闭式最优策略后，发现 reward 可用策略与 reference 的 log 比表达，从而不必显式训 RM、不跑 PPO：

$$\mathcal{L}_{\mathrm{DPO}}(\theta)=-\log\sigma\!\Big(\beta\big[\log\frac{\pi_\theta(y_w|x)}{\pi_\text{ref}(y_w|x)}-\log\frac{\pi_\theta(y_l|x)}{\pi_\text{ref}(y_l|x)}\big]\Big)$$

推导轮廓：RLHF 目标（含 KL）→ 拉格朗日得 $\pi^\ast\propto\pi_\text{ref}\cdot\exp(r/\beta)$ → 反解 $r=\beta\log(\pi^\ast/\pi_\text{ref})+\beta\log Z(x)$ → 代入 Bradley-Terry，差分时 $Z(x)$ 抵消。直觉上是最大化 chosen 相对 reference 的 log 比、压低 rejected；$\beta$ 大则约束强、更保守；$\beta$ 小则偏好学得更狠但易漂移。本项目 β=0.1 偏保守，配合 lr=5e-6、1 epoch，适合在已 SFT 的话术上做小幅偏好推动。注意：chosen/rejected 绝对概率可以同时下降，只要相对 reference 的 margin 上升即可。

### Q37. SFT 损失与「只对助手 token 计 loss」为什么重要？

$$\mathcal{L}_{\mathrm{SFT}}(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(y_t\mid x,y_{<t})$$

多轮对话里，用户和系统提示是条件，不是要模仿的答案。我们只对助手回复段计损失，这样学的是「在该情境下如何回复」，而不是复读用户倾诉或背诵系统提示。若对全对话计损失，容量会被浪费在模仿用户，推理时也更容易复读。

这与 PT、DPO 的目标区分一致：PT 对全段做下一词预测，因为目标是领域分布；DPO 比较的是助手回复的相对偏好。边界约束靠推理期系统提示，不靠 SFT 去背它。

### Q38. Hybrid 召回与 RRF 公式如何理解？

语义分 $\mathrm{sem}=\cos(q,c)$，assistant 角色块乘 0.55。词法侧对中文做单字与相邻二元组 BM25。排名融合用 Reciprocal Rank Fusion：

$$S_{\mathrm{rrf}}(d)=\sum_{r\in\{\mathrm{rank}_s(d),\mathrm{rank}_l(d)\}}\frac{1}{60+r}$$

取 fused **top-40** 进入 Anchor CE；coverage 后 **top-12** 种子进扩窗。字级 BM25 对人名、专名、数字敏感，与 dense 互补——心理对话两者都重要：「那次高等数学挂科」既有语义情境，也有专名锚点。RRF 按 reciprocal rank 融合，对原始分数刻度不敏感；60 是常见平滑项。口述重点是「融合的是排序而非原始分」，以及「互补」而不是「堆模块」。

### Q39. 自适应扩窗与衰减感知 MMR 怎么写？

扩窗：余弦大于等于阈值，或者邻接且「实体」有交。默认阈值 0.40，邻接不超过 2；连续失败两次停扩；跨度与窗内条数有上限。这里的实体**不是命名实体识别**，只是规则抓短中文块、英文标识、带单位的数字，给专名桥接用。

白板可写：

$$
\operatorname{keep}(c)
\;\iff\;
\cos(c,a)\ge\tau
\;\;\lor\;\;
\big(\mathrm{dist}(c,W)\le d_{\mathrm{ent}}\;\wedge\;
\mathcal{E}(c)\cap\mathcal{E}(W)\neq\emptyset\big)
$$

选窗侧：$R_{\mathrm{content}}=2\cdot s_{\mathrm{fused}}+1.5\cdot\mathrm{Jaccard}$（fused 来自 RRF），再叠加 decay、相对新近性（$\beta=0.8$）、周桶（$0.5$）得 $R_{\mathrm{eff}}$，最后进 MMR（相关减冗余）。口述默认值：λ 约 0.7，衰减约 90 天，$\alpha$ 约 0.5。归档消融曾显示：去掉新近性大约 84.4%，加回去大约 92.2%——说明选择器本身是建模对象。公式支撑职责分工，但贡献仍是问题驱动方法，不是新损失。

$$
R_{\mathrm{eff}}(W)=R_{\mathrm{content}}(W)\cdot\big[\alpha+(1-\alpha)D_W(t)\big]
+\beta\cdot R_{\mathrm{recency}}(W)+\mathrm{week\_bonus}(W)
$$

$$
\mathrm{score}(W)=\lambda\,R_{\mathrm{eff}}(W)-(1-\lambda)\max_{S\in\mathrm{Chosen}}\mathrm{sim}(W,S)
$$

### Q40. 五个易混旋钮怎么一次讲清？

| 名字 | 出处 | 含义 |
|------|------|------|
| LoRA α | LoRA 论文 | 训练时 $\Delta W=\frac{\alpha}{r}BA$ 的缩放系数 |
| LoRA r | LoRA 论文 | 低秩瓶颈维度 |
| 推理 scale | 运行时额外乘的强度 | 咨询 0.7 / 闲聊 0.3 |
| DPO β | DPO / RLHF | KL 约束强度，与 LoRA α 无关 |
| lr | 优化器 | 参数更新步长 |

α/r 决定训练时 $\Delta W$ 量级；β 决定策略离 reference 多近；scale 决定运行时 LoRA 影响多强。本项目常用：r=8、α=16、β=0.1、咨询/闲聊 scale 0.7/0.3、学习率阶梯 5e-5→2e-5→5e-6。把「训练超参」和「推理旋钮」拆开，是高频加分点。

# 第五部分 研究边界、局限与未来工作

### Q41. 记忆 QA 约 92% 是否意味着线上用户体验已验证？

否。该数字来自 30 条受控长程弧、固定 reader、同协议对照的离线实验，证明的是记忆形态差异，不是大规模用户研究。评测集偏小，外部基准对照与更大规模实验仍属后续工作。面试时应主动划清：内部效度优先（归因清晰），外部效度有界（不宜外推到任意部署规模）。

### Q42. 项目最主要的局限有哪些？如何主动讲？

第一，记忆评测 n=30，有利于对照与消融，但对外泛化要保守表述。第二，BLEU/ROUGE 不能单独代表倾听质量；DPO 的收益更应结合偏好目标与听感来理解，字面指标回落不等于失败，也提醒后续仍需更贴任务的评价方式。第三，没有系统人工评测与 PT/rank 消融；temporal 维双方偏弱。第四，工程形态是单卡原型，不把前端/接口当作创新主张，也不把单机 SQLite 说成已具备大规模服务能力。

主动讲局限反而更像做研究的人。模板是：承认缺口 → 说明已有证据能支撑什么 → 给出可执行的下一步，而不是辩解「其实已经够了」。

### Q43. 如果重做实验，你会改什么？如果只有一周？

优先序：补小规模盲评或 LLM-as-judge（共情/说教/记忆连贯）；扩展记忆评测弧规模与 temporal 比例，并做多种子报告区间；补 PT ablation 与 rank 敏感性；在同 reader 协议下增加「原文 top-k 无扩窗」等更细消融。不优先一上来换更大基座或上 PPO——那会同时改变多个变量，削弱归因。

一周最小可行：记忆线复现 ER vs Mem0 主表，并做含新近性 vs 无新近性消融；对话线至少跑 base vs 最终 dpo 的相对差。不优先改模型规模、不上 PPO、不重写前端。一周目标是「保住归因清晰的主证据」。

### Q44. 伦理与安全边界怎么说？

定位是校园心理**辅助**对话，不是医疗器械或诊疗决策系统；不做临床诊断、不开具治疗方案权威。记忆可关、可一键遗忘；Profile 严白名单，拒绝把情绪状态写成人格标签。生成侧用边界 system prompt 与记忆注入约束，缩小「模型自由发明用户生平」的空间——幻觉不能根除，只能结构性抑制。

若被问到危机干预：原型阶段应明确转介专业资源，而不是让模型扮演危机热线。研究叙事上，「先被听见」与「不替代专业服务」必须同时成立。

### Q45. 三分钟如何把整个项目讲完？

第一分钟讲问题：校园场景需要倾听，通用模型不会好好说；跨周需要记忆，写时抽取容易乱记。第二分钟讲方法：对话线 PT→SFT→DPO + MacBERT 调 scale 0.7/0.3；记忆线 ER 原文入库、查询时 **Anchor CE + 重建**，Profile 严白名单直写、无则空。第三分钟讲证据：BLEU-1 13.23→29.56→27.91；`all_50` QA **90.5% vs 68.7%**，staleness **8.6% vs 46.6%**，F1 **0.783 vs 0.400**；temporal 仍弱。最后留一句边界：问题驱动方法创新，单卡原型，指标有适用范围。

# 第六部分 工程与部署（放最后：单卡、流式、SQLite、Web——简短）

> 工程支撑演示与复现，**不是**本项目向老师主张的创新点。口述控制在一两分钟内。

### Q45b. 某个组件挂了会怎样？双线解耦在运行时怎么体现？

生成模型挂了，主对话就不可用。嵌入或记忆检索挂了，对话仍可继续，只是本轮可能没有记忆块，写入会进重试。记忆关掉或检索为空，就空着注入，照常生成。查询规划失败，就退回整句检索。画像抽不到，合法空着，不挡原文库。意图若不确定，我们宁可偏咨询侧语气、略强一点适配。

MacBERT **判错**也只改语气强弱，不开关记忆。这正是双线解耦在运行时的体现：语气问题和记忆问题可以分开降级。

### Q46. 单卡如何同时支持咨询语气、闲聊语气与会话摘要？

单卡上 GPU 调用串行。强度上只挂一份对话 LoRA，用推理 scale 切换：咨询大约 0.7、闲聊大约 0.3；摘要关掉适配器走基座。写入记忆、画像抽取和摘要放在回复后的后台做，尽量不挡首 token。长期记忆是原文库，写路径不需要第二份任务 LoRA。单卡约束反过来塑造了方法：量化加低秩、一份适配器、写时不靠大模型抽经历、检索主体用算法编排。

### Q47. 流式传输与落库如何设计？客户端断开怎么办？

流式输出时，生成在后台线程继续跑；客户端中断只停前端读取。后台跑完后仍把完整回复落库，前端可以用历史接口补全。这是用算力换体验和落库正确性，在单卡原型下可接受。记忆检索失败就注入空块，对话照样继续。

### Q48. 为什么用 SQLite + 按用户向量索引，而不是外置向量库？

原文和向量存在本地库里；按用户缓存在进程内做近邻检索，归一化后内积近似余弦，变了再重建。本地库是唯一事实源，缓存只加速。单机原型不必上独立向量库；用户量或实例数上去了再升级索引。方法核心——原文入库、查询时重建——可以不变，变的是工程规模。

### Q49. Web / 管理端提供什么？研究叙事里怎么定位？

用户端有登录、流式对话、会话管理、记忆开关和一键遗忘；管理端可以匿名浏览会话和分诊。两条技术线只在生成前把记忆拼进提示时交汇。Web 是为了可演示闭环，**不**把前端或接口当贡献。老师追问实现时可以说：工程保证能演示、能复现；主张的是倾听对齐和经历重建式记忆。

选贵组，我会尽量说到具体：方向是否覆盖对话、检索增强、对齐或应用 NLP；我读过哪几篇相关工作或老师近期题目；我的项目经验如何变成组里课题的接口，而不是只说学校名气或城市。若信息不够，就诚实说：我对某某方向匹配度最高，也愿意按组里主线调整，先把方法训练和实验规范学扎实。

### Q53. 你的研究兴趣是什么？未来三到五年怎么规划？

短期兴趣仍然落在「面向高风险对话场景的模型行为约束」和「长期记忆如何既可用又不乱记」。SoulHarbor 让我确认：单靠提示词或单靠检索都不够，风格对齐和记忆形态要分开建模、分开评测。

规划可以按阶段说。研一：补齐机器学习与 NLP 基础课，精读对话、RAG、对齐相关综述和经典论文，把组里工具链跑熟。研二：在导师课题下做一个可消融、可对照的小问题，争取把贡献收成清晰主张，而不是堆模块。研三：把结果写成论文或技术报告，同时保留工程复现能力。职业上我可以走科研，也可以走工业界对话/Agent 方向，但读研几年的主线应是把研究范式练会。

### Q54. 你的优点和缺点是什么？

优点我愿意说成「能把失败模式说清楚，并改成可检验假设」。做记忆时，我们不是一上来堆功能，而是先承认写时抽取在心理场景里错记代价更高，再改成原文库加查询时重建，并用同协议对照和消融把主张钉住。这和科研需要的问题意识比较接近。

缺点是早期容易把「系统能跑」误当成「问题已解决」。例如对话侧自动指标好看，并不等于共情已被证明；记忆侧三十条弧上的高准确率，也不能外推成线上用户体验。我现在会主动把局限写进叙事，并准备人工评测、更大样本和更难时序题作为下一步，而不是等老师追问才补丁。

### Q55. 这个项目里你具体负责什么？哪些是你独立做的？

口述要诚实、边界清楚。可以说：问题定义与双线拆分、训练数据组织与 PT/SFT/DPO 流程、意图分类与 scale 机制、ER 读写路径与评测协议、同协议对照和消融解读，以及把结果收成答辩叙事，这些是我能讲到底的部分。若有合作或借用开源组件，也直接说：基座模型、嵌入模型、对照系统是站在公开工作上，我们的贡献在组合约束、记忆形态假设和评测设计，不把别人的权重或库说成自己发明。

老师最烦「什么都是我做的」却答不出细节。准备一张心里清单：数据从哪来、超参怎么定、哪个数字对应哪次实验、哪个设计是后来改的——改的那次往往最像科研。

### Q56. 项目中遇到的最大困难是什么？怎么解决的？

我准备讲记忆线的方向修订，而不是讲环境配不好。最大困难是：一开始也容易相信「写入时让大模型总结一下会更整齐」，但在倾听对话里，短暂低落、冲突后的措辞很容易被写成稳定标签，后面共情会建在错人设上。工具调用看起来还行，却解决不了「写时理解必然偶尔写错、错了会长期留库」这个结构问题。

解决办法是改假设：Trace 侧写入尽量不理解，只存原文；理解放到查询时的召回、扩窗和带新近性的选择；画像收成极窄白名单。然后用同协议对照和「去掉新近性」消融证明：不是存了原文就自动好，读路径如何对待近期证据本身是方法的一部分。困难—修订—证据，这条链比「我调参调了很久」更像研究。

### Q57. 项目有什么成果？发论文了吗？获奖了吗？

没有论文不要硬编。可以说：当前成果是可复现的方法原型和同协议实验证据——对话侧相对裸基座的自动指标跃升，记忆侧相对写时抽取基线的准确率、过时率和内容 F1 改善，以及新近性消融。若还在投稿或整理技术报告，就说阶段与计划；若只是课程/实验室项目，就承认形态是研究原型，价值在问题与证据，不靠奖项撑场面。老师问成果，其实在听你是否分得清「工程演示」和「可主张贡献」。

### Q58. 老师说「这不就是把几篇论文拼起来吗」怎么接？

先承认组件层面很多是已知的：低秩适配、偏好优化、混合检索、写时抽取记忆，都不是我们首创。然后把贡献收窄到问题约束下的取舍：在校园倾听场景里，错记代价高于漏记，所以拒绝写时宽画像；在单卡约束下，用独立分类器只调语气强度，而不是再训一个大路由模型；用同 reader、只换记忆库的协议，把记忆形态差从答题能力里剥离出来。拼积木到处都有，但「拼完能否回答一个别人没问清楚的问题，并且用对照实验卡住」，才是我们想被评价的地方。

### Q59. 你还有什么问题想问我们？

准备两三个真问题，避免问官网能查到的招生人数。例如：组里研究生通常多久确定题目；组内更强调论文方法创新还是系统落地；对新同学，会更希望先复现某条线还是直接进课题；对话或记忆方向近期组里最关心的开放问题是什么。好的提问表明你在想象「进去以后怎么干活」，而不是只想要录取结果。

## 7.2 项目深挖：动机、对比、实验与叙事

### Q60. 这个 idea 是怎么来的？现有方法缺什么？

直接经验加文献。做校园心理辅助对话时，会反复看到两类失败：模型一开口就像在上课或空安慰；跨周再聊时，若记忆系统在写入时就归纳，容易把「这次考砸」冻成长期负面标签。SoulChat 等工作把倾听失败说得很清楚；记忆侧则常见写时抽取路线。我们把缺口收成：缺的是面向倾听的说话方式对齐，以及「宁可漏记、不可乱记」的记忆形态，而不是再做一个更会聊天的通用助手。

### Q61. 为什么用这条技术路线，而不是纯 Prompt、纯微调或纯 RAG？

Prompt 便宜，但很难稳定改掉基座的说教先验，也解决不了跨会话证据从哪来。纯微调能改「怎么说」，改不了「跨周该引用哪段经历、不该把旧状态当现在」。纯 RAG 能补证据，但不自动带来倾听分寸，也可能在错误摘要上检索。所以我们是微调管说话，ER 管经历证据，画像管极少硬事实，生成前再拼接。各管一段，失败模式才分得开。

### Q62. 如果让你用一句话写论文贡献，怎么写？

面向校园心理支持对话，我们提出双线方法：用继续预训练、指令微调与偏好对齐改善倾听向回复；用原文经历库与查询时重建抑制写时抽取带来的错误固化，并在固定答题模型、只换记忆库的协议下验证长期问答与抗过时能力。关键词是场景约束、记忆形态、同协议证据，而不是「我们做了一个 App」。

### Q63. 相关工作你怎么定位？SoulChat、Mem0、经典 RAG 各同在哪、异在哪？

与 SoulChat：同的是倾听叙事——共情优先、警惕过早建议；异的是我们落到可训练链路，并并行做长期记忆约束。与 Mem0 一类写时抽取：同的是都承认跨会话需要记忆；异的是我们把理解后置，用原文加重建，并用同协议数字对照。与经典 RAG：同的是 dense 与词法检索积木；异的是单元是经历窗而不是文档切片，后面还有扩窗、时间衰减和相对新近性。定位时先说同，再说异，避免一上来否定别人。

### Q64. 实验设计上，你最想强调的「干净」在哪里？

对话和记忆必须分协议。对话评测看基座、SFT、DPO 在同一倾听语料上的自动指标，回答的是「会不会更像倾听回复」。记忆评测固定答题模型，只换记忆库，回答的是「记忆形态差多少」。如果用记忆准确率证明微调成功，或用 BLEU 证明 ER，就是因果混乱。第二个干净点是消融：去掉相对新近性后准确率下降、过时率上升，说明读路径选择器不是装饰。

### Q65. 数据从哪来？有没有隐私或标注偏见问题？

训练侧主要用公开心理与闲聊语料，以及按互斥切分构造的偏好对；记忆评测弧是按规范合成的校园长程叙事，不是真实来访录音。这带来两个边界：公开语料有分布偏见，合成弧有利于对照却限制外推。我们的应对是：不把自动指标说成临床有效；记忆结论限制在同协议相对优势；产品侧强调辅助、可关记忆、危机时引导真人渠道。老师若追问真实用户数据，就承认当前证据链还不包含大规模真实来访研究。

### Q66. 你如何保证不是过拟合或数据泄漏？

倾听训练与偏好数据按对话签名互斥；自动评测也按签名区分见过与没见过训练池的样本，并且两边分数趋势一致，说明不是只背见过的参考答案。DPO 只训一轮、学习率更低，并观察是否出现套话塌缩。记忆三十弧不进入生成训练。仍然要承认：主题相近泄漏无法完全消灭，所以我们不把「未见签名」说成「全新领域」。

### Q67. 如果审稿人只让你保留一个消融，你留哪个？

留相对新近性消融。它直接打在 ER 的核心主张上：查询时如何对待近期证据。没有它，系统更容易被早期高相关旧状态带走，过时率升高；加回去后总准确率大约从百分之八十四回到九十二，过时率明显下降。这个消融证明「原文库」不够，选择器是方法的一部分。

### Q68. 你怎么看大模型幻觉？项目里怎么缓解？

幻觉在这里至少有两层。生成层：模型可能编造安抚或建议；我们用领域对齐降低说教和空安慰，用系统提示约束边界，但自动指标不能消灭幻觉。记忆层：更危险的是「错记后的一本正经」——检索到的若是错误标签，生成会显得很笃定。所以我们把记忆证据尽量留在原文，画像只收可核验硬事实，并在冲突时以用户当前说法为准。缓解幻觉靠的是证据形态和注入纪律，不只靠把模型训得更会说话。

## 7.3 校招 / 社招常考八股（落到本项目）

### Q69. 用一两分钟讲清 Transformer 里和你项目最相关的点。

生成基座是解码器因果模型：每个位置只能看左边，用自注意力聚合上文，再预测下一个词。训练和微调本质上都在优化这种条件概率。我们的 PT、SFT 都在这个框架里；DPO 则在同一条件分布上比较两种回复的相对偏好。面试时不必默写每一层公式，但要说清：因果掩码决定它是生成模型；双向编码器才适合分类和句向量，所以意图用 MacBERT，检索用嵌入模型，而不是强行让十四亿模型包办一切。

### Q70. KV Cache 是什么？为什么推理会快？

自回归生成时，每一步注意力都要用到过去所有位置的键和值。如果每步重算历史，会重复大量计算。KV Cache 把已生成前缀的键值缓存下来，新步骤只算新 token，历史直接复用，所以解码明显加速，显存会随序列变长。我们线上要流式对话，缓存是标配思想；它不改变模型学到的分布，优化的是推理效率。

### Q71. 对比学习 / 双塔嵌入和交叉编码器差在哪？你为什么用双塔？

双塔是查询和文档分别编码成向量，用余弦或内积打分，文档可以离线预存，适合大规模召回。交叉编码器把查询和文档拼在一起过模型，交互更细，但每对都要现场算，贵。我们的经历库要写时嵌入、读时快速召回，所以用 BGE-M3 的稠密双塔向量，再配词法检索；精细重排不是默认主路径。代价是单向量可能丢细粒度交互，所以才有混合检索和扩窗补上下文。

### Q72. 检索有噪声、召回了不相关片段怎么办？

先承认 dense 会语义近但指称错，词法会抓住字面却不懂转述。我们的组合是：混合融合降低单路偏差；扩窗用语义连续和邻接专名桥接补共现；选窗用最大边际相关减冗余，并加相对新近性，避免旧高相关窗霸屏；注入有 token 预算，超了整段丢而不是撕碎证据。若仍噪声大，下一步才是查询改写、更强重排或拒答策略。不要假装召回永远干净。

### Q73. 什么是灾难性遗忘？你们续训时怎么考虑？

在新任务上大幅度更新，可能损害旧能力。我们用低秩适配而不是全参猛训，本身就是把更新限制在低维子空间；学习率从 PT 到 DPO 递减；DPO 只做一轮。PT 先搬领域分布，再 SFT，再偏好，也是避免一步到位拧坏基座。我们没有系统报告「通用能力掉了多少」，所以不能说已经解决遗忘，只能说设计上在控制更新幅度，并用下游倾听指标作为接受标准。

### Q74. 对齐税是什么？和你们 DPO 后 BLEU 略降有关系吗？

对齐税通常指：偏好或安全对齐之后，某些能力或表面分数可能下降。我们的现象类似但不完全等同：DPO 后与单一参考的字面重合略降，但那是因为优化目标变成「更共情、少敷衍」，不是「更像那句参考」。ROUGE 一类覆盖指标可以持平或略升。所以我会把 BLEU 回落解释成目标切换下的可预期现象，同时承认若没有人工偏好胜率，对齐收益仍不够硬。

### Q75. 温度、top-p 对你项目意味着什么？

温度高更随机，低更贪心稳。对话评测为了可复现对比，用了偏高采样设定；线上默认更保守一些。两者数字不能直接等同听感，但相对排序仍有参考价值。摘要和结构化抽取用更低温度，因为要的是稳定压缩和合法 JSON，不是多样共情。面试时强调：解码超参是评测协议的一部分，要和训练目标分开说。

### Q76. Agent 里的短记忆和长记忆怎么分工？你们怎么对应？

常见分法：短记忆是当前会话上下文；长记忆是跨会话可检索的经验或画像。我们短的一面是对话窗口加滚动摘要；长的一面是 Trace 原文库加窄画像。衔接逻辑是：生成前按需检索长期证据，注入后与当前用户话一起条件化生成；冲突时当前说法优先。我们不做万能 Agent 工具环，但记忆分层思想是对齐的：容量问题靠短上下文，跨周连续问题靠长期库，二者不能互相替代。

### Q77. 如何系统评估一个 RAG 或记忆系统？

至少分三层：检索是否命中该命中的证据；注入后答题是否正确；有没有把过时信息当成现状。我们记忆评测用六类题覆盖细节、共现、偏好、当前状态、跨会话和时序，并报告过时率和内容层面的应记应忘 F1。固定答题模型是为了把记忆差从生成能力里分开。若做工业 RAG，还会看时延、成本、拒答率和人工忠实度；我们当前证据更偏方法对照，不假装已经是生产级评估全集。

### Q78. 上下文很长时的 Lost in the Middle 是什么？你们怎么规避？

研究表明，模型对上下文中间段落的利用往往弱于头尾。若把跨周所有原文塞进提示，旧状态和新问题缠在一起，既贵又容易中间段被忽略。所以我们不是「更长上下文替代记忆」，而是先检索再选少量经历窗，控制预算，按时间排序注入，让证据短而可审计。长上下文解决容量，不自动解决选择。

### Q79. 为什么不做知识图谱或 GraphRAG？

图谱适合稳定实体关系，维护成本高，对情绪过程也不友好。倾听对话里大量信息是状态性的、叙事性的，硬抽成三元组容易再引入写时理解错误。我们优先原文经历和查询时重建，是在数据形态不确定时选择可回溯证据。若未来有稳定的课程、院系、制度类知识，可以另做文档 RAG 或轻量图谱，那是知识库问题，与「个人经历记忆」不是同一层。

### Q80. 如果用户量到十万，你的方法哪些要变、哪些可以不变？

可变的是存储与检索工程：单机库、按用户缓存、串行 GPU，都要换成可扩展服务、批量嵌入、更合适的近似近邻。不变的是方法主张：原文经历、写弱读强、窄画像、语气与记忆解耦、分协议评测。面试里把「算法主张」和「系统规模」拆开，显得更成熟：我们现在证明的是形态有效，不是已经具备互联网服务容量。

### Q81. 心理健康场景的安全与 Prompt 攻击你怎么看？

用户可能试探越界建议，也可能注入「忽略之前的指令」。我们的立场是：系统是辅助不是诊疗；危机情绪应引导真人专业渠道；记忆可关、可遗忘；画像不允许诊断标签落库。提示攻击无法靠单一关键词拦死，需要分层：系统边界、拒答策略、审计与人工值守。本科原型做不到完整安全栈，但必须把边界讲清楚，不能靠「模型会自己正确」。

### Q82. 校招常问：微调数据和质量怎么控制？

先定义任务失败模式，再选数据。我们倾听 SFT 以公开共情对话为主，混少量领域补充和自我认知样本；偏好数据与 SFT 互斥，负样本按空泛、欠共情、说教等可描述模式合成并质检。质量上做去重、长度与模板统一、正负均衡；意图数据还按字长对齐，减少捷径。原则是质量优先于盲目堆量，并且每类数据要能说清「它在优化什么目标」。

### Q83. 你如何向非技术老师解释这个项目？

同学有时需要一个低压力的倾诉入口，但很多聊天模型要么爱讲道理，要么跨周就忘，要么乱记。我们做了两件事：教模型先听后说；记事情时尽量记原话，用的时候再整理，并且几乎不把心情写成性格。效果上，说话更接近倾听语料，跨周问答也更不容易拿旧状态冒充现在。它仍然只是辅助工具，真正的心理危机要找老师和专业机构。

### Q84. 如果面试官连续追问你不会的细节，你怎么接？

先复述问题，确认问的是原理、实现还是实验。会的部分给到边界；不会的部分明确说「这个点我还没做到 / 没测过」，然后给出若要补实验会怎么设计，或把它关联回我熟悉的模块。保研和校招都吃「知之为知之」：装会很容易在第二问穿帮；诚实加迁移，往往比硬编加分。

### Q85. 最后用三十秒收束：你希望老师记住你什么？

希望记住两句话：我在校园倾听场景里同时处理「不会好好说」和「容易乱记」；我能把方法收成可对照、可消融的证据，也清楚自动指标和三十条弧的边界。我不是来展示一个聊天网页，而是来展示自己能把问题做成研究问题。

### Q86. 如果老师质疑你的实验规模太小，你怎么辩护？

先承认，再限定结论边界。三十条长程弧确实不大，不能直接外推成大规模真实部署结论，所以我不会把九成多准确率讲成“已经证明线上体验”。但这个规模足够做两件事：第一，做**同协议对照**，把记忆形态差从答题模型里剥离出来；第二，做**能力维诊断**，看共现、当前状态、跨会话整合和时序这几类题谁强谁弱。也就是说，它更像一个研究型对照集，而不是互联网刷分集。

如果老师继续追，我会补一句：我知道更强的证据应该是什么样，比如更大样本、真人标注、多答题模型复核、甚至真实用户长期追踪；当前工作先把问题问清、把方法差验证出来，这是阶段性目标。

### Q87. 如果老师问“你的提升有没有统计显著性”，怎么回答？

最稳妥的回答不是硬说“显著”，而是先说明我们当前更强调**效应大小和协议干净**。比如记忆侧准确率从六成多到九成多、过时率从四成多降到一成多，这种量级差已经很大；对话侧也不只看单个指标，而看 base、SFT、DPO 的整体趋势和 seen/unseen 一致性。

但如果严格按论文标准推进，后续我会补置信区间、bootstrap 重采样或者多随机种子重复跑。这一题的关键不是假装已经做全，而是表明你知道“效果大”和“统计稳”是两件不同的事。

### Q88. 如果老师问“为什么不用更大的模型”，怎么答才成熟？

不要只说“显卡不够”。更成熟的答法是：我们的目标不是拼参数，而是在**单卡可复现约束下**验证方法主张。更大模型当然可能带来更好上限，但它会同时改变训练成本、部署形态和对照公平性；如果直接换 32B 或 72B，现有数字就不能横着类比了。

所以十四亿级别在这里是一个方法载体：中文能力够用、能挂对话适配和长期记忆、还能做完整评测。若以后算力更宽裕，更大的基座是自然扩展方向，但不改变我们现在要回答的问题。

### Q89. 如果老师问“为什么不用全参数微调”，怎么讲得更像研究者？

可以分三层说。第一层是资源：全参微调成本太高，不适合单卡原型。第二层是数据：我们不是几百万高质量领域样本，低秩适配更符合中小规模领域数据的约束。第三层是版本管理：LoRA 方便回滚、切换和比较，也更适合“同一基座上试不同阶段”的研究流程。

更重要的是，不要把 LoRA 说成“永远等价于全参”。正确表述是：在这个任务和预算下，它是效果、成本、可复现性的折中方案。这样的答法会比“LoRA 一定最好”可信得多。

### Q90. 如果老师问“为什么加了 cross-encoder rerank”，怎么答？

先说它解决什么：dense + BM25 负责别漏，Planner 子查询负责别漏「比较/多对象」里的某一侧；但 fused top-40 里仍可能有大量近邻 anchor，需要更细的**种子选择**。cross-encoder 对 **裸 anchor**（不是整窗）做 `(query, anchor 原文)` 交互打分，比单 query 全局 top-k 更适合这一层。

再说边界：我们把它放在 **stitch/merge 之前**，对象是 **anchor 种子**而不是经历窗；coverage 式保留「原始 query top-4 + 每子查询 top-3」再补齐到 12，**不做 CE 与 RRF 数值混合**。窗级 $R_{\mathrm{content}}$ 仍是 $2\cdot\mathrm{fused}+1.5\cdot\mathrm{Jaccard}$；decay / recency / week / MMR 管窗级去冗余与时间——职责拆开。

若老师追问“会不会太复杂”，就强调：窗级 CE 已试过并否定；Anchor CE 是为多查询覆盖补证据，不是再叠一层窗分。参数与结果见 `03` §7–§8。

### Q91. 如果老师问“为什么不用纯 BM25 或纯向量”，怎么接？

纯 BM25 擅长抓人名、课程名、数字、固定短语，但遇到同义改写、转述和口语化表达会漏；纯向量擅长抓语义近邻，但在精确指称上会出现“意思差不多、对象不对”。校园倾诉里两种情况都会出现，所以最稳的办法是混合：语义路负责“这件事像不像那件事”，词法路负责“是不是那个人、那门课、那一天”。

再往下一层说，融合也不是简单相加，而是用排名融合，尽量减少不同打分尺度难以直接比较的问题。老师一般听到这里，就知道你不是因为“大家都这么做”才混检，而是真的理解互补性。

### Q92. 如果老师问“为什么不用直接摘要做长期记忆”，怎么答？

摘要的诱惑很大，因为它短、整齐、好注入。但心理场景里，摘要最大的问题不是压缩误差本身，而是**压缩发生得太早**。用户今天的一次自我否定、一次和室友冲突、一次考砸后的情绪，如果在写入时就被概括成稳定画像，后面每一轮都可能被这个错误摘要带偏。

所以我们宁可保留原文、在查询时重建；摘要只适合做短期上下文压缩，不适合替代长期证据库。这个答法要抓住一句：摘要不是不能用，而是不能在信息最不稳定的时候拿它替代原始经历。

### Q93. 如果老师问“你们的方法最可能在哪类问题上失败”，怎么答？

我会主动说三类。第一，**时序题**仍弱，因为“知道几段经历都相关”和“精确恢复先后关系”不是同一难度。第二，**真实用户分布漂移**可能导致自动指标和离线协议高估表现，尤其是非校园、非咨询式表达。第三，**高风险安全边界**仍靠系统约束和人工转介思路，不能说模型本身已经可靠。

会主动讲失败场景，通常比一味强调优点更能赢得老师信任。因为科研不是证明自己永远对，而是知道自己什么时候可能错。

### Q94. 如果老师问“把这个项目再做半年，你最优先补什么实验”，怎么答？

我会优先补三块。第一，**更贴任务的人类偏好评测**，让 DPO 的收益不只停在自动指标解释。第二，**更大规模、更多样来源的长期记忆集**，并引入多答题模型交叉复核，增强外部效度。第三，**时间推理专项**，因为现在时序仍是共同短板。

如果老师继续追“只能选一个”，我会选第一块人工评测。因为对话线现在最容易被质疑的是“BLEU/ROUGE 不能代表共情”，补上这一块，整条证据链会更完整。

### Q95. 如果老师问“这个项目像研究还是像产品”，怎么收束？

我的回答会是：**形态上像产品原型，内核上是研究问题。** 它确实有登录、对话、记忆开关、管理端这些产品外壳，但这些更多是为了把闭环跑通、让实验可演示。真正想主张的是两个研究判断：一是倾听风格需要专门对齐；二是心理场景下长期记忆应尽量避免写时抽取，把理解后置到查询时重建。

所以我不会把前端页面当成果，而会把“问题定义—方法设计—同协议证据—局限反思”当成果。这句话很适合答辩结尾时用来定调。
