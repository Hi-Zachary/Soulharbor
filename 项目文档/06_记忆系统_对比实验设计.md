# SoulHarbor 记忆系统：对比实验设计（最终版）

> 本文是 SoulHarbor 长期记忆（AER）的**正式评测**说明。  
> 产品故事见 `00`；方案见 `05`；数据构建见 `05` §9。

---

## 1. 实验目标

验证「原文库 + 查询时自适应经历重建（AER）」相对 **Mem0**（flat 抽取式，行业主流）在**心理对话长程记忆**上的优势，聚焦四个记忆能力维度：

1. **细节/共现召回**：原文保留不丢细节（Mem0 抽取合并/覆盖会丢）；
2. **跨会话整合**：多会话信息组合（AER 跨会话证据链）；
3. **偏好/画像召回**：consent 确认制 Profile；
4. **抗 stale**：已结束/已演化处境不残留旧状态（记忆块注入只选相关、assistant 只参与检索不注入）。

---

## 2. 数据：`evaluate/memory/data/`（最终版，30 条）

**完整数据**：`evaluate/memory/data/all_30.jsonl`（30 条）。

**构建过程（MiniMax 按 SPEC 合成 + 人工验收）、schema、硬规则与样例**见  
`05_记忆系统_AER自适应经历重建_最终方案.md` **§9**。分册 JSONL / 旧 `SPEC.md` 已归档到 `archive/eval_memory_data_splits/`。

摘要：像真实多轮心理咨询的长程弧；细节具体；情境自然演进；禁记忆元操作泄漏；每条 3 题（2 MCQ + 1 judge）+ `gold_facts`。

**6 类 × 5 条**：

| category | 测什么 | 系统优势来源 |
|---|---|---|
| `detail_recall` | 召回具体细节（人名/课程/数字） | 原文 ground-truth + 词法召回 |
| `context_recall` | 召回共现上下文（"那件事里还提到什么"） | AER 扩窗、富 bundle |
| `preference_recall` | 用户表达过的偏好/需求/感受 | Profile |
| `current_state` | 某处境**最新**状态（抗 stale） | 注入只选相关、时序排序 |
| `cross_session_integration` | 结合多个会话作答 | 跨会话证据链 |
| `temporal_sequence` | 何时/先后顺序 | 原文时间戳 + 链内排序 |

## 3. 评测协议（`evaluate/memory/episodic_eval/`）

```
evaluate/memory/
├── data/                   # 30 条长程弧
├── runs/                   # 真实跑次（qa_episodic_* / qa_mem0_*）
└── episodic_eval/
    ├── run_qa_episodic.py  # AER
    ├── run_qa_mem0.py      # Mem0 同协议对照
    └── mem0_adapter.py
```

1. 每个方法按同一对话流逐轮 ingest（episodic 存原文块；Mem0 走其官方抽取/向量库）；
2. 到达延迟测试点，用**固定 reader**（MiniMax-M3）只接收"该方法的记忆检索块 + 测试题"作答；
3. **同一 reader 跨所有方法**——只换记忆库、不换 reader，测的是记忆库本身而非答题能力；
4. MCQ 精确匹配 gold（不依赖 judge）；open 题用同 reader 按参考答案做 reference-based 判定；
5. `content_f1`：把最终记忆库与 `gold_facts.should_remember/should_forget` 比对（LLM 辅助匹配）。

---

## 4. 指标

| 指标 | 定义 |
|---|---|
| **QA 准确率**（主） | 记忆依赖题答对比例（MCQ 精确 + judge） |
| **Staleness 率** | 在 current/状态类题上答成旧版本的比例 |
| **内容 F1** | 对 gold 应记/应忘事实集的 P/R/F1 |

（`overgeneralization_rate` 仅对含"应否定"探测题的数据集有意义；本数据集以 recall/context/current/integration/temporal 能力题为主。）

## 5. 真实结果（runs/ 内，非模拟）

### 5.1 主表（30 条，同一 reader）

| 方法 | QA 准确率 | Staleness 率 | 内容 F1 |
|---|---|---|---|
| **AER（aer）** | **91%–93%** | **7%–14%** | **0.79–0.89** |
| Mem0（同协议） | 64% | 43% | 0.48 |

- 最新一轮：`evaluate/memory/runs/qa_episodic_20260731_145921/summary.json`（QA 91.1%、staleness 7.1%、content F1 0.892）；
- 较早一轮：`evaluate/memory/runs/qa_episodic_20260731_134643/summary.json`（QA 93.3%、staleness 14.3%、content F1 0.785；preference/temporal 逐类更高）；
- 对照：`evaluate/memory/runs/qa_mem0_20260731_135743/summary.json`（QA 64.4%、staleness 42.9%、content F1 0.481）。
- 两个 AER 跑次之间的差异来自评测的采样性（reader 低温和时序类判定），不是记忆库换了——这也提醒我们：**单跑次的绝对数字不重要，与 Mem0 在完全同一协议下的相对差距（约 +27pp）才是可复现的结论**。跑次 JSON 里另有一份更早的 `reference_mem0_baseline_20260730`（QA 0.822，Frozen Full-vs-Mem0 历史跑次）仅作内部存档。

### 5.2 逐类 QA 准确率（代表跑次 145921）

| 类别 | AER | Mem0 | 差距来源 |
|---|---|---|---|
| context_recall | 0.93 | 0.47 | Mem0 抽取丢共现上下文 |
| cross_session_integration | 0.93 | 0.60 | AER 跨会话证据链 |
| current_state | 1.00 | 0.60 | 注入相关选择 + 时序 |
| detail_recall | 0.93 | 0.87 | 均强（Mem0 也能存到字面） |
| preference_recall | 0.93 | 0.73 | consent profile |
| temporal_sequence | 0.73 | 0.60 | 链内时序 |

**逐 probe**：recall 0.97 vs 0.89、context 0.91 vs 0.27、integration 1.0 vs 0.6、current 0.93 vs 0.57、preference 0.9 vs 0.6、temporal 0.6 vs 0.4。

### 5.3 结论与解读

1. AER 的核心优势落在 **context / integration / preference / current** 四类：原文库 + 扩窗保住共现细节，跨会话链支持整合，consent profile 记偏好，相关选择 + 时序抗 stale。
2. detail_recall 两者接近（Mem0 对字面 fact 也能记住）；temporal 均偏弱（60–73%），是共同开放点。
3. 抗过度固化是**结构性**的：记忆库只存原文、不归纳画像，一次性情绪/被反驳特质不可能被写成"确信事实"（写时污染为零）；代价是"稳定模式"需要 reader 从经历链自行推断——这一侧的能力上限取决于注入的完整性。

## 6. 诚实 limitation 与下一步

1. **temporal 弱**：时间先后/间隔类问题（60–73%）是共同短板，可考虑注入链内显式时间锚（如"第 X 周"）。
2. **stale 处理靠读路径**：没有写时生命周期；"已结束处境"主要靠查询相关选择、覆盖度去冗余与 token 预算抑制。可增加轻量离线闭环节点以更强抗 stale。
3. **规模**：30 条受控数据偏小；Mem0 基线已同协议重跑，后续可扩规模并在 LongMemEval 子集上做外部对照。
4. **LLM 重排/路由可选**：默认关闭（特征版已够用），开启时注意延迟与解析失败回退。
