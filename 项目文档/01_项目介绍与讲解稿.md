# SoulHarbor 项目介绍与讲解稿

---

## 一分钟版

老师好，我们做的项目叫 SoulHarbor，是一个面向校园心理支持的长期对话系统。

我们观察到，通用大模型用于心理支持时常有两个问题。第一，它虽然能生成通顺的回答，但容易使用重复的安慰模板，用户还没有表达完整就开始分析和给建议，面对只需要倾听和安慰的用户时显得过于理性。第二，它缺少稳定的跨会话连续性，用户隔一段时间再回来时，系统很难准确联系过去的经历、关系变化和沟通偏好；如果记忆只保存孤立事实或旧状态，又可能影响当前判断。

因此我们从同一个目标出发设计了两部分。模型侧以 Qwen3-14B 为基座，通过领域续训、监督微调和偏好优化，让模型更稳定地学习倾听、澄清、承接情绪和控制建议时机；记忆侧保存可回溯的对话证据，在查询时经过混合召回、Cross-Encoder 精排、自适应扩窗和时间感知选择，恢复与当前问题相关的个人经历。

这两部分最终在生成阶段结合：记忆告诉模型“用户过去发生过什么”，微调告诉模型“面对这些信息应该怎样回应”。对话自动指标相对基座明显提升；长期记忆在固定 reader 的评测中，问答准确率约 90.5%，陈旧率约 8.6%。

## 三分钟版

老师好，我介绍一下 SoulHarbor。我们希望解决的是校园心理支持中长期互动质量的问题，而不仅是让模型完成一次问答。

通用大模型具备较强的语言生成能力，但在心理支持场景中经常出现三类不合适的表现。第一，回答容易形成固定套路，例如先表达遗憾，再解释问题，最后列出若干建议，长期使用会显得重复和缺乏针对性。第二，模型倾向于快速解决问题，用户还在描述感受时，它就开始分析原因或提供行动方案，而不是先询问和倾听。第三，对于主要需要陪伴、理解和安慰的用户，模型往往过于理性，回答内容可能没有明显错误，但互动感受并不合适。

即使单轮回复得到改善，长期交流还有另一组问题。没有记忆时，模型每次都像重新认识用户，无法自然延续学业压力、人际关系或生活变化；简单的长期画像又容易只保留静态结论，忽略事件发生的时间、上下文和后续变化。例如用户早期说过想退出社团，后来已经改变决定，如果系统只召回最相似的旧句子，就可能把过去状态当成现在。长期记忆真正需要解决的，不只是“能否找到一句相关内容”，而是“能否找回当前有效、上下文完整、能够体现变化过程的个人经历”。

基于这个问题，我们把系统设计成两个连续层次。

第一层是回应方式适配。我们在 Qwen3-14B 上采用 QLoRA，依次进行 PT、SFT 和 DPO。PT 用于适应心理支持语域，SFT 学习倾听式的多轮回复结构，DPO 进一步区分“相关但过于说教的回答”和“更能承接情绪的回答”。运行时使用 MacBERT 区分咨询式表达与普通闲聊，对同一份 LoRA 使用不同强度，使咨询场景中的领域行为更明显，同时避免日常聊天始终带有沉重的咨询语气。

第二层是长期经历利用。系统以原始对话 Trace 作为主要证据，避免在写入时过早把一次情绪概括成永久标签。读取时先由 Planner 判断是否需要拆分检索目标，Dense 和 BM25 扩大候选范围，RRF 融合两路排名，再使用原始问题和 Planner 查询进行多查询 Anchor Cross-Encoder 精排。选出的 anchor 在原会话中自适应扩展并合并为经历窗口，最后结合相关性、时间衰减、新近性和 MMR 选择若干互补证据。少量稳定信息和明确偏好由受限 Profile 单独保存。

两层在生成前汇合。记忆系统提供可靠的个人背景和经历变化，微调模型决定怎样使用这些信息进行回应。因此项目的统一主线是：**让心理支持对话既符合当前情绪交流的需要，也能延续用户长期、不断变化的个人语境。**

实验上，对话侧 BLEU-1 从基座的 13.23 提升到 SFT 的 29.56，DPO 后为 27.91；ROUGE-L 从 15.04 提升到 24.64，DPO 后为 24.44。记忆侧在固定 reader、只更换记忆路径的 `all_50` 上，QA 约 90.5%，staleness 约 8.6%，内容 F1 约 0.783。

## 十分钟版

老师好。下面我从研究动机、整体思路、模型适配、长期记忆和实验结果五个部分介绍 SoulHarbor。

### 1. 研究动机：心理支持不仅要求回答相关，还要求互动方式合适

大模型已经能够进行开放域对话，但心理支持与一般知识问答不同。用户表达压力、失落或关系困扰时，很多时候并不是立即寻求一套完整的解决方案，而是希望先被认真听见，再逐步澄清问题。

通用模型在这个场景中常见三类问题。

第一是**回复模式重复**。模型容易使用相似的开场和固定结构，回答虽然完整，但缺少与用户具体表达的联系。用户多次交流后，会明显感到系统在重复安慰模板。

第二是**过早进入建议模式**。模型往往把对话理解成待解决的任务，很快开始归纳原因、列出步骤或建议用户应该怎么做。对于尚未表达完整的用户，这会打断叙述，也可能让用户感觉自己的情绪被转化成了一个需要立刻修复的问题。

第三是**缺少倾听和安慰所需的互动分寸**。模型可以进行理性分析，却未必知道什么时候应该少分析、多追问，什么时候只需要确认和陪伴。也就是说，问题不是模型完全不会说，而是它默认的生成倾向与心理支持中的互动目标并不一致。

### 2. 长期交流进一步带来个性化和状态变化问题

如果系统只处理单轮对话，即使每句话都比较温和，也很难形成真正连续的支持体验。用户在不同时间谈到的学业、人际关系、家庭期待和生活习惯往往相互关联。缺少长期记忆时，模型无法理解“还是上次那件事”“后来我又和她谈了一次”这样的表达，用户也需要反复介绍背景。

但长期记忆不是简单保存更多内容。现有做法容易出现三个问题。

第一是**记忆碎片化**。检索命中一条孤立消息，却缺少前因、后续和指代对象，生成模型看到的是相关句子，而不是完整经历。

第二是**静态记忆难以表达变化**。用户的决定、关系和情绪会随时间发展。旧状态往往与问题在字面上高度相似，却不一定代表当前情况。

第三是**个性化依据不可靠**。如果系统在写入时把一次性的表达直接总结成长期性格或稳定偏好，错误会在后续对话中被重复使用。真正有价值的个性化应当来自可追溯的经历和明确表达，而不是系统过早做出的推断。

因此我们把项目的研究问题统一为：

> **如何让大模型在长期心理支持中，既采用更符合倾听需求的回应方式，又能从多次交流中找到当前有效、上下文完整的个人经历作为依据。**

模型微调和长期记忆分别处理这个问题的两个部分，但在生成阶段共同决定最终回复。

### 3. 回应方式适配：从通用生成倾向到心理支持互动策略

我们选择 Qwen3-14B 作为基座，在单卡条件下采用 QLoRA，LoRA rank 为 8，alpha 为 16。训练分为 PT、SFT 和 DPO 三个阶段。

PT 主要用于缩小通用语料与心理支持表达之间的分布差异，使模型熟悉相关词汇、表达节奏和常见情境。它提供的是领域语言基础，不能单独保证模型会倾听。

SFT 直接学习多轮上下文到支持性回复的映射。训练重点不是让模型输出更多心理学知识，而是让它形成更合适的回复顺序，例如先回应用户刚刚表达的内容，再询问细节；在信息不足时不急于判断；建议出现时也尽量建立在用户意愿和已表达需求上。自动指标相对基座的主要提升发生在这一阶段，说明监督数据有效改变了输出分布。

DPO 处理的是多个可行回答之间的偏好。同一个问题可能有几种语义相关的回复，其中一种直接列出方案，另一种先承接和澄清。我们通过 chosen 和 rejected 对，使模型提高更符合倾听目标的回答概率。DPO 优化的是相对偏好，因此不能要求 BLEU 一定继续提高；它与复现某个参考句子的目标不同。

推理时，我们不维护两套生成模型，而使用 MacBERT 判断输入更接近心理咨询式表达还是普通闲聊，然后调节同一份 LoRA 的 scale。咨询场景约为 0.7，闲聊约为 0.3。这样领域适配可以按场景连续调节，而不是把每句话都处理成正式咨询。

### 4. 长期经历利用：从相关消息到可用于回应的经历证据

长期记忆分为 Trace 和 Profile 两类。

Trace 保存原始消息、会话位置和时间等信息，是长期经历的主要证据。我们没有在每轮写入时强制把对话总结成几条确定事实，因为当前还不知道未来查询会关心哪一部分。一段对话在不同问题下可能需要不同范围：询问起因时需要前文，询问最新结果时需要后续，询问沟通偏好时又可能需要多个会话共同支持。

Profile 只处理少量稳定、明确且可核验的信息，例如姓名、学校、专业、地点和用户明确表达的沟通偏好。它用于补充长期个性化，但不替代经历记忆。

读取流程首先经过 Memory Planner。简单问题形成一个检索查询，复杂问题可以拆成多个子目标。初召回阶段使用 Planner 查询：Dense 负责语义表达差异，BM25 负责人名、地点、课程和事件名称，两路各召回 50 条，再通过 RRF 融合到 40 个 anchor 候选。

随后进行多查询 Anchor Cross-Encoder 精排。CE 同时使用原始用户问题和 Planner 查询。Planner 查询分别评估候选是否支持某个子目标，原始问题保留完整的人物、事件和时间约束。系统采用 coverage selection，而不是单纯全局 top-k：原始问题和不同子查询分别保留一定数量的高分候选，再去重并补齐到 12 个 anchor，避免一个容易匹配的子问题占满所有位置。

CE 之后进行 Adaptive Stitch。每个 anchor 只在所属会话内部向前后扫描；候选消息与 anchor 保持语义连续，或在相邻范围内存在实体承接时加入。扩展受到最大跨度、最大消息数和连续失败次数限制，因此不同经历窗口长度不同。多个 anchor 产生的重叠窗口会被合并。

最终选择不再使用 CE 接管。扩窗后面对的是一个证据集合问题：系统需要兼顾内容相关性、当前状态、不同时间阶段和重复信息。我们保留原有的时间感知 MMR，将混合召回相关性与词项重合组合为内容分，再加入记忆衰减、相对新近性和阶段覆盖，最后用 MMR 减少重复。选出的 4 到 6 个窗口按时间顺序注入模型。

这条链路中各模块的职责是明确的：

- Dense 与 BM25 尽量不要漏掉可能相关的消息；
- RRF 融合语义和词法排序；
- 多查询 CE 提高 anchor 精度并覆盖多个检索目标；
- Stitch 将孤立消息恢复为经历；
- 时间感知 MMR 选择当前有效、互补且不过度重复的窗口；
- 微调模型根据这些经历生成更符合心理支持需求的回应。

### 5. 实验结果与方案演进

对话评测在相同样本和解码设置下比较 base、SFT 和 DPO。BLEU-1 分别为 13.23、29.56、27.91，ROUGE-L 分别为 15.04、24.64、24.44。SFT 相对基座有明显提升，支持领域监督能够改变模型回复分布。DPO 后字面重合指标没有继续增加，因此这一阶段更应结合偏好评测和具体案例解读。

记忆评测固定同一个 reader，只替换记忆路径，避免生成模型差异混入结论。`all_50` 包含 50 名用户、250 道问题，覆盖细节、上下文、偏好、当前状态、跨会话整合和时间过程。当前方案的 QA 约 90.5%，staleness 约 8.6%，内容 F1 约 0.783。

方案并非一次确定。最初我们尝试在扩窗之后使用 CE 直接替代窗口相关性，结果明显下降。原因是完整窗口较长，而且单个窗口的 query 相关性不能替代时间有效性和多窗口覆盖。之后将 CE 前移到 anchor 层，虽然避免了窗口数量塌缩，但纯原始问题 top-10 容易漏掉地点、导师和偏好等短证据。最终引入 Planner 子查询与原始问题共同精排，并通过 coverage selection 保留不同检索目标，才使 CE 的职责与候选阶段更匹配。

因此，这个项目的核心不是简单组合“微调”和“检索”。模型侧解决的是心理支持中的回应习惯，记忆侧解决的是长期个人语境的恢复；二者共同服务于一个统一目标：**基于用户真实、不断变化的经历，给出更有连续性和更符合倾听需求的回应。**

## 十五分钟版

老师好。十五分钟版本在前面主线的基础上，进一步解释几个关键设计选择：为什么只写提示词不够，为什么训练分为 PT、SFT、DPO，为什么长期记忆以原始 Trace 为主，为什么 Cross-Encoder 放在扩窗前，以及实验结果应当怎样解读。

### 1. 为什么只用 Prompt 不够

Prompt 可以提醒模型使用温和语气，也可以规定回答步骤，但它难以稳定改变基座模型的默认生成倾向。模型原本更擅长解释和解决问题，因此即使系统提示写了“先倾听”，在复杂上下文中仍可能快速转向建议。提示越长，还会与当前对话和记忆内容竞争上下文空间。

另一方面，Prompt 无法解决长期个人信息从哪里来。直接把完整历史拼入上下文会带来长度、噪声和注意力分散；只保留摘要又可能丢失时间和具体事件。因此我们将稳定的回应方式放入参数高效微调，将长期个人经历交给独立的记忆系统。

### 2. 为什么训练需要分阶段

PT、SFT 和 DPO 对应三个不同层面。

PT 让模型适应领域文本分布，学习心理支持相关的语言表达和语境；SFT 提供明确的输入输出监督，使模型学习多轮对话中的回应结构；DPO 则在多个语义上都能回答的结果之间建立偏好，减少说教、敷衍和过早建议。

如果只做 PT，模型可能更熟悉心理相关词汇，但不知道怎样组织一次倾听式回应；如果只做 SFT，也能获得主要提升，但在“相关却不够合适”的多种回答之间缺少进一步区分。三阶段不是为了把流程写得复杂，而是因为每一阶段处理不同的学习目标。

QLoRA 使这条训练链路可以在单卡上完成。LoRA 仅训练低秩增量，4-bit 量化降低基座权重占用。最终线上只加载 DPO 后的 chat adapter，分类器通过 scale 控制领域行为强度。

### 3. 为什么长期记忆不能只保存事实摘要

长期对话中的信息并不都适合转化成静态事实。姓名、学校和明确偏好相对稳定，但“我不想参加了”“我觉得自己什么都做不好”往往依赖具体事件和时间。系统若在写入时直接概括，就可能失去语境，也可能把暂时状态变成长期属性。

原始 Trace 的优势在于可回溯。同一段历史面对不同问题，可以重建不同范围的证据。问“为什么发生冲突”时强调起因；问“现在关系如何”时强调后续；问“用户喜欢怎样被安慰”时需要整合多次明确反馈。查询时决定证据范围，比写入时提前决定唯一含义更适合不断变化的个人经历。

### 4. 为什么使用 Planner 与多查询 CE

复杂问题往往包含多个检索目标。例如“用户与室友的矛盾如何发展，现在是否已经缓和”，同时要求过程和当前状态。如果只使用一个长 query，Dense、BM25 和 CE 可能都集中在字面上最明显的一部分。

Planner 将问题拆成更明确的检索目标，初召回分别覆盖这些方向。但我们也不完全依赖改写结果，因为子查询可能省略原问题中的地点、人物限定或时间表达。因此初召回使用 Planner 查询，而 CE 阶段同时保留原始问题和子查询：子查询负责判断候选是否支持某个局部目标，原始问题负责保留完整语义约束。

最终不采用简单平均分，也不让一个查询的 top-k 占满全部位置，而使用 coverage selection。它分别保留原始问题和各子查询的高分候选，再去重和补齐。这个设计针对的是多证据任务中的召回覆盖，而不是增加一个抽象的复杂模块。

### 5. 为什么 CE 放在扩窗前

Cross-Encoder 擅长对 query 和较短候选做细粒度匹配。如果放在扩窗后，候选包含多条消息，长度更长，而且相关内容可能被背景稀释。更重要的是，扩窗后的最终选择不仅考虑“哪个窗口最相关”，还考虑新旧状态、时间阶段和窗口之间的互补性，这不是通用 CE 的单一相关性目标。

因此 CE 只用于选择值得展开的 anchor。之后由 Stitch 恢复经历上下文，再由时间感知 MMR 做最终集合选择。这种位置安排来自实际消融，而不是先验假设。

### 6. 如何理解实验结果

BLEU 和 ROUGE 衡量与参考答案的字面重合，适合比较 base 和 SFT 是否发生明显分布变化，但不能完整衡量倾听质量。DPO 后 BLEU 略降并不自动代表效果下降，不过也不能仅凭理论就断言偏好一定改善，需要结合偏好对准确率、人工盲评或案例分析。

记忆侧的固定 reader 协议更强调归因。相同问题、相同生成模型下，只更换记忆块，可以观察信息是否被找回、是否使用了过时状态，以及注入内容与目标事实的重合情况。当前结果说明经历重建与时间选择在可控长程数据上有效，但 temporal 仍低于其他类别，表明恢复多个相关片段与准确理解状态演化仍是不同难度。

### 7. 项目贡献的表述

项目可以概括为三点。

第一，针对心理支持场景中模板化、过早建议和缺乏倾听感的问题，完成从领域续训、监督微调到偏好优化的模型适配，并通过场景分类调节同一 LoRA 的使用强度。

第二，针对长期对话中连续性不足、记忆碎片化和状态变化难以处理的问题，构建以原始 Trace 为证据、多查询 Anchor CE 选种子、自适应扩窗恢复经历、时间感知 MMR 选择最终窗口的读路径。

第三，通过分阶段消融验证模块位置和目标是否匹配，包括窗级 CE 的失败、裸 Anchor CE 的证据遗漏，以及多查询 coverage 对检索目标覆盖的改善。

这些技术组件本身大多来自成熟方法，项目价值主要体现在心理支持场景下的问题组织、模块职责划分、系统实现和实验归因。

### 8. 收束

SoulHarbor 的整体故事不是两条互不相关的技术路线，而是长期心理支持中的两个必要条件。只有模型知道怎样倾听，却不了解用户过去的经历，回应会缺乏连续性；只有系统记住很多历史，却仍然模板化地分析和建议，个性化也不会带来好的互动体验。

因此我们的目标是让系统同时做到：**从长期交流中找到准确的个人语境，并以更符合心理支持需要的方式回应。**

---

## 收尾句

我们希望系统不是简单记住更多内容，而是能在合适的时候找回与用户当前状态真正相关的经历，并以更合适的方式继续这段对话。
