## 1. 问题定义与研究动机

### 1.1 校园心理支持：需求长什么样

高校心理咨询资源长期紧张：预约等待长、咨询师人力有限，同时污名化与「不想麻烦别人」的心态，让一部分学生更倾向先找一个**低门槛、随时可及**的倾诉入口。这类入口不必替代专业咨询，但至少应做到三件事：

1. **随时可说**：不受排班限制；
2. **说得像人在听**：共情、倾听、安慰优先于急于给方案；
3. **隔周还能接上**：学业压力、室友矛盾、失眠等经历跨会话仍可被衔接，而不是每次都从零自我介绍。

通用大模型已经能「聊天」，但在上述场景中会暴露两类**结构性**不足——不是换一句 system prompt 就能消掉的。

### 1.2 第一类不足：对话能力不适配（「怎么说」）

SoulChat（Chen et al., Findings of EMNLP 2023）等工作明确指出：用户寻求心理支持时，真正需要的往往是**共情、倾听与安慰**，而不是立刻抛出的通用建议。若不加领域适配，模型常见失败模式包括：

- **空泛安慰**：「一切都会好起来的」；
- **说教 / 急于给方案**：用户还在倾诉，模型已开始列清单；
- **复读与敷衍**：「我理解你的感受」循环，却不推进理解；
- **百科腔**：像在回答「什么是焦虑」，而不是在陪一个人说话。

EmoLLM 等开源实践进一步表明：在中文心理相关语料上做继续预训练与指令微调，可以明显改善基座对心理对话分布的适应。这些工作共同说明——**心理健康对话是一个需要专门数据与对齐的任务**，而不是「通用助手 + 心理人设」的简单叠加。

校园场景还多一层约束：**咨询倾诉**与**日常闲聊**所需的说话方式不同。前者需要更稳定的共情与分寸；后者需要更轻，避免「假装在做治疗」。若每轮都让 14B 模型自我裁定并切换人格，成本高、不稳定，也难离线评测。

### 1.3 第二类不足：长期记忆的形态风险（「怎么记」）

没有跨会话记忆时，模型再共情，用户隔周回来仍是陌生人——上周的考试失利、冷战、失眠无从衔接。有了记忆，若采用主流「写时抽取」路线——每轮用大模型把对话压成事实句再入库——工程上简洁，但对心理场景尤其危险：

- 抽取会损失共现细节（时间、语气、上下文条件）；
- 更严重的是：可能把**瞬时情绪**固化成**稳定负面标签**（例如把「这次面试没发挥好」写成「用户自卑 / 能力差」）。

由此引出本项目的核心判断——**记忆误记的代价不对称**：

> **漏记一段旧经历**：最多是「这轮没帮上忙」；  
> **错记并反复注入**：可能在后续每一轮强化错误自我认知，把用户推向错误的自我叙事。

因此，记忆系统不能只追求「记得更多」，更要避免「乱记」。设计上应偏向：**写入时尽量不替用户下结论；检索时再从原文重建可用证据**。

### 1.4 问题形式化（研究问题 RQ）

综合以上，SoulHarbor 同时面向两个可分开表述的研究问题：

| 编号 | 问题 | 失败时的典型表现 |
|------|------|------------------|
| **RQ1** | 如何让开源中文基座在校园心理对话中更共情、少敷衍，并区分咨询/闲聊语气强度？ | 空泛、说教、百科腔；闲聊时「过度治疗」 |
| **RQ2** | 如何在跨会话记忆中保留可用经历，同时从结构上降低写时误归纳的风险？ | 无记忆则失连续；写时抽取则乱贴标签、陈旧状态反复注入 |

两条问题对应两条技术线；它们在产品里交汇，但在研究叙事与评测协议上必须**解耦**——否则「换记忆方法也换了答题模型」会让因果说不清。

### 1.5 非目标（明确边界）

为避免答辩时被追问「是不是想替代心理咨询」，此处写清边界：

- **不是**临床诊断系统，不做疾病判定与处方；
- **不是**宣称「共情已达人类咨询师水平」——自动指标只做相对比较；
- **不是**多卡大规模预训练新基座——在既有 Qwen3-14B 上做领域适配与对齐；
- **工程演示**服务于研究可复现，但工程细节不是 Part A 的主线。

## 2. 总体方案：双线解耦

### 2.1 一句话立场

> **对话线负责「怎么说」；记忆线负责「怎么记」。**  
> 两条线在工程上解耦，只在生成前把记忆块拼进上下文时交汇。  
> 记忆侧进一步收敛为：Trace **写入尽量不「理解」用户**；读路径再把原文扩窗重建成经历证据。

### 2.2 对话线（概览）

基座选用 **Qwen3-14B**：中文与指令遵循较强，在 **4-bit 量化 + LoRA** 下可单卡部署。训练基于 LLaMA-Factory 的 **QLoRA（NF4）**，全链路统一 **rank $r=8$、$\alpha=16$**，按

$$\text{CPT（PT）} \rightarrow \text{SFT} \rightarrow \text{DPO}$$

链式续训，各阶段保留独立 LoRA 目录。线上只挂载最终 **DPO chat LoRA**。

意图方面：用独立的 **MacBERT-base** 二分类器判断本轮是否为咨询意图，其**唯一**职责是调节同一份 chat LoRA 的推理强度：

- 咨询：scale $\approx 0.7$；
- 闲聊：scale $\approx 0.3$；
- 会话滚动摘要：**关闭 LoRA**，走裸基座。

分类器**不**控制记忆开关——闲聊里也可能提到上周的事；把记忆绑死在咨询路由上反而丢信息。偶发误判的代价应只是语气强弱，而不是整条对话行为被带偏。

### 2.3 记忆线（概览，细节见 Part B）

长期记忆子系统称为 **ER（Experience Rebuild）**。核心命题是：

> 不要在写入时把人生压缩成几条确信事实；而要在提问时，从原文里重建那段经历的证据。

写路径：用户与助理消息按确定性规则分块，用 BGE-M3 向量化后**原样**入库（Trace **零 LLM 抽取**）。旁路 Profile 仅对白名单内的长期画像（姓名、教育、稳定偏好等）做有限抽取。

读路径：混合召回（dense cosine + 字级 BM25 → RRF）→ 自适应扩窗 → 衰减感知选择 → 按时间注入用户原文。

同协议对照（固定答题模型、只换记忆库）表明：长程记忆 QA 准确率可由约 64%（写时抽取基线）提升至约 92%（ER）。**完整协议、消融与表格见 Part B。**

### 2.4 双线如何交汇、为何解耦

```text
用户本轮话
    │
    ├─► MacBERT：is_consult → 仅决定 LoRA scale（怎么说的强度）
    │
    └─►（若用户开启记忆）ER 检索 → 注入历史原文 / 画像
              │
              ▼
        Qwen3-14B + chat LoRA（scale 依路由）
              │
              ▼
           生成回复
              │
              ▼
        post-turn：Trace 原文入库；必要时裸基座做会话摘要
```

解耦的研究含义：

| 维度 | 解耦带来的好处 |
|------|----------------|
| 评测 | 对话 BLEU/ROUGE 与记忆 QA 可分开报告，互不污染因果 |
| 失败隔离 | 语气不好 ≠ 记忆坏了；记错了 ≠ 微调失败 |
| 迭代 | 可单独重跑 DPO 或单独改 ER，而不必整系统重训 |
| 安全叙事 | 「乱记」风险主要落在记忆形态，而不是生成模型本身 |

### 2.5 本章小结

SoulHarbor 不是「一个大模型包办一切」，而是：

- 用 **PT→SFT→DPO** 解决 RQ1 的语气与分寸；
- 用 **原文 Trace + 查询时 ER** 解决 RQ2 的连续与防误记；
- 用 **MacBERT 旋钮** 在同一份 LoRA 上区分咨询/闲聊强度。

下一章给出支撑上述流水线的基础技术原理（含公式）；再下一章展开对话线的数据与超参。

## 3. 基础技术原理

本章目标：让你能**手写关键公式**，并理解本项目为何选该技术。工程 API、目录路径、启动脚本见附录 A（索引到 `05`）。

### 3.1 LoRA（Low-Rank Adaptation）

#### 3.1.1 原始线性层与全参微调的困难

Transformer 中大量计算可写成线性变换

$$y = Wx,$$

其中 $x \in \mathbb{R}^{d_{\mathrm{in}}}$，$W \in \mathbb{R}^{d_{\mathrm{out}} \times d_{\mathrm{in}}}$，$y \in \mathbb{R}^{d_{\mathrm{out}}}$。全参数微调直接更新整个 $W$：

$$W' = W + \Delta W, \qquad y = (W + \Delta W)x.$$

问题在于 $W$ 往往很大。例如 $W \in \mathbb{R}^{4096 \times 4096}$ 就有

$$4096 \times 4096 = 16{,}777{,}216$$

个参数。全参微调不仅要存权重，还要存梯度与优化器状态，显存开销极大——对单卡训练 14B 级别模型不现实。

#### 3.1.2 低秩假设

LoRA 假设：适应新任务时，真正需要的权重变化 $\Delta W$ 虽然形状很大，但**有效秩通常较低**。因此不直接训练完整 $\Delta W$，而分解为

$$\Delta W = BA,$$

其中

$$A \in \mathbb{R}^{r \times d_{\mathrm{in}}}, \qquad B \in \mathbb{R}^{d_{\mathrm{out}} \times r}, \qquad r \ll d_{\mathrm{in}}, d_{\mathrm{out}}.$$

$r$ 称为 LoRA 的 **rank（秩）**。由矩阵理论，

$$\operatorname{rank}(BA) \le r.$$

直觉：$r$ 个独立的「调整方向」之和——

$$\Delta W = \sum_{i=1}^{r} b_i a_i^\top.$$

#### 3.1.3 完整前向公式（含缩放）

实际实现通常加入缩放系数。**经典 LoRA 前向**为：

$$
\boxed{y = Wx + \dfrac{\alpha}{r} BAx}
$$

或等价地写 $\Delta W = \dfrac{\alpha}{r} BA$。其中：

- $r$：rank；
- $\alpha$：scaling parameter；
- $\alpha / r$：缩放比例，用于在改变 $r$ 时稳定 LoRA 分支的数值尺度。

本项目统一取 $r=8$、$\alpha=16$，故

$$\frac{\alpha}{r} = 2,$$

前向为 $y = Wx + 2\, BAx$。注意：这不意味着 LoRA「贡献是基座的两倍」——$A$、$B$ 中的数值本身通常很小；scale 是相对强度旋钮。

高效计算时**不必**显式构造完整 $BA$，而是依次算 $h = Ax$（维数为 $r$），再 $z = Bh$：

```text
                 ┌──────── W（冻结）────────┐
输入 x ──────────┤                           ├── 相加 ── 输出 y
                 └── A → B → 乘以 (α/r) ────┘
```

#### 3.1.4 参数量对比

全量更新 $\Delta W$ 需要 $d_{\mathrm{out}} \cdot d_{\mathrm{in}}$ 个参数；LoRA 只需

$$r(d_{\mathrm{in}} + d_{\mathrm{out}}).$$

对 $4096 \times 4096$、$r=8$：

$$\frac{8\times 4096 + 4096\times 8}{4096^2} = \frac{65{,}536}{16{,}777{,}216} \approx 0.0039$$

即约 **0.39%**（单层方阵）。整模可训练比例还取决于插入了哪些投影层（`q/k/v/o`、MLP 等）。

相对全参微调，LoRA 的优点不只是省显存：低秩约束本身带有**隐式正则**，在中小规模领域语料上不易把基座「拧坏」。

#### 3.1.5 初始化：为何 $A$ 随机、$B=0$

训练开始时期望 **LoRA 不改变原模型输出**，即初始 $\Delta W = BA = 0$。常见做法：

$$
\boxed{A \sim \text{随机初始化},\quad B = 0}
$$

于是 $BAx = 0$，初始 $y = Wx$。

**为何不能 $A=B=0$？** 忽略 $W$ 与缩放，令 $z = BAx$，上游梯度 $g = \partial \mathcal{L}/\partial z$。则

$$
\frac{\partial \mathcal{L}}{\partial B} = g (Ax)^\top, \qquad
\frac{\partial \mathcal{L}}{\partial A} = B^\top g \, x^\top.
$$

关键结构是：

$$
\frac{\partial \mathcal{L}}{\partial A}\ \text{含有 } B, \qquad
\frac{\partial \mathcal{L}}{\partial B}\ \text{含有 } A.
$$

若 $A=B=0$，则两边梯度皆为 0，LoRA 分支**永远无法离开零点**（死分支）。

标量直觉：令 $z=ba$，$\mathcal{L}=(ba-t)^2$。则

$$\frac{\partial \mathcal{L}}{\partial a}=2(ba-t)b, \qquad \frac{\partial \mathcal{L}}{\partial b}=2(ba-t)a.$$

当 $a=b=0$ 且 $t\neq 0$ 时，损失不为 0，但两个梯度都是 0——误差存在却无法更新。

取 $A$ 随机、$B=0$ 时：初始输出仍为 0；但 $\partial\mathcal{L}/\partial B = g(Ax)^\top$ 一般非零，$B$ 先动起来；随后 $A$ 也获得梯度。也可以反过来 $A=0$、$B$ 随机，经典实现多采用前者。

#### 3.1.6 反向传播更新什么

$W$ 冻结：$\partial\mathcal{L}/\partial W$ 不用于优化。只更新

$$A \leftarrow A - \eta \frac{\partial\mathcal{L}}{\partial A}, \qquad
B \leftarrow B - \eta \frac{\partial\mathcal{L}}{\partial B}.$$

#### 3.1.7 推理时的两种用法

1. **保留双分支**：$y = Wx + (\alpha/r)BAx$——便于切换不同 adapter、调节 scale（本项目线上采用此思路）。
2. **合并进基座**：$W_{\mathrm{merged}} = W + (\alpha/r)BA$，之后直接 $y=W_{\mathrm{merged}}x$。对 QLoRA，合并涉及反量化，可能引入误差，故常保留 adapter 单独加载。

#### 3.1.8 与本项目的对应

| 项 | 取值 / 做法 |
|----|-------------|
| $r$ / $\alpha$ | 8 / 16（PT、SFT、DPO 全链路一致） |
| 目标模块 | `lora_target: all`（注意力与 MLP 投影等） |
| 线上 | 一份 DPO adapter；用 PEFT `set_scale` 做 0.7 / 0.3 |

### 3.2 QLoRA（NF4，为何单卡可训 14B）

#### 3.2.1 LoRA 与 QLoRA 的一句对比

$$
\begin{aligned}
\text{LoRA:} &\quad \text{冻结高精度基座} + \text{训练低秩 } A,B \\
\text{QLoRA:} &\quad \text{冻结 4-bit 量化基座} + \text{训练高精度 } A,B
\end{aligned}
$$

#### 3.2.2 前向形式

设 $W_q$ 为 4-bit 存储的权重量化编号，$s$ 为量化 scale，则

$$
\boxed{y = \operatorname{Dequantize}(W_q, s)\, x + \dfrac{\alpha}{r} BAx}
$$

训练期间通常**不更新** $W_q$ 与 $s$，只更新 $A$、$B$（以 FP16/BF16 等高精度存储）。

#### 3.2.3 NF4 是什么（直觉）

**NF4（4-bit NormalFloat）** 是一种面向「权重近似正态分布」设计的 4-bit 量化数据类型：在有限的 $2^4=16$ 个代表值上，按正态分布分位数安排量化格子，使对「正态权重」的量化误差更小。QLoRA 论文还常用 **double quantization** 进一步压缩量化常数本身的开销。

对本项目读者只需记住三点：

1. 基座以 4-bit 驻留显存，前向时再反量化参与矩阵乘；
2. LoRA 仍以较高精度训练，保证适配能力；
3. 这使得 **~14.8B** 参数的 Qwen3 在**单卡**上做继续预训练 / SFT / DPO 成为现实路径。

#### 3.2.4 「为何单卡 14B」——显存账的定性说明

全参 14B 的 FP16 权重本身约 $14.8\text{B} \times 2\text{B} \approx 30\text{GB}$ 量级，再加上梯度、Adam 状态、激活与 KV cache，单卡极易爆。QLoRA 把**基座权重**压到约 4-bit，并把**可训练参数**限制在低秩 adapter（千万至亿级，远小于全参），再配合 gradient checkpointing、小 micro-batch + 梯度累积，单卡训练才跑得通。

本仓库配置：`quantization_bit: 4`，`gradient_checkpointing: true`，`per_device_train_batch_size: 1`，`gradient_accumulation_steps: 16`。

### 3.3 继续预训练 CPT（下一 token 损失）

#### 3.3.1 CPT 在训练什么

继续预训练（Continued Pretraining, CPT；本仓库配置称 PT）是：在**已经完成通用预训练**的语言模型上，继续用「预测下一个 token」的目标，吸收某一领域/风格/时段的文本分布。

对 decoder-only 模型，序列 $(x_1,\ldots,x_T)$ 的联合概率分解为

$$
P(x_1,\ldots,x_T) = \prod_{t=1}^{T} P(x_t \mid x_{<t}), \qquad x_{<t}=(x_1,\ldots,x_{t-1}).
$$

#### 3.3.2 损失函数（因果语言建模）

$$
\boxed{
\mathcal{L}_{\mathrm{CPT}}
=
-\frac{1}{N}
\sum_{t \in \mathcal{V}}
\log P_\theta(x_t \mid x_{<t})
}
$$

其中 $\mathcal{V}$ 是参与损失的有效 token 集合，$N=|\mathcal{V}|$。实现上常对 logits 做一位错位（shift）：位置 $t$ 的输出预测 $x_{t+1}$。

验证集上常看困惑度

$$\mathrm{PPL} = \exp(\mathcal{L}).$$

#### 3.3.3 Loss mask vs Attention mask（必须分清）

| 概念 | 控制什么 | 典型实现 |
|------|----------|----------|
| **Attention mask** | 当前 token **能看见**哪些位置（因果：不能看未来；padding 不可见） | 下三角 + pad 屏蔽 |
| **Loss mask** | 哪些位置的预测错误**计入损失** | `labels[i]=-100` 表示忽略 |

因果注意力示意（可见为 1）：

$$
\begin{bmatrix}
1&0&0&0\\
1&1&0&0\\
1&1&1&0\\
1&1&1&1
\end{bmatrix}
$$

**CPT 的默认策略**：几乎所有有效文本 token 都参与 loss（padding 除外）。  
**SFT 的默认策略**：通常只对 assistant 段计 loss（见 §3.4）。

因此：「数据看起来像不像问答」并不决定阶段类型；**哪些 token 进入 loss** 才决定。

#### 3.3.4 数据形态与本项目 CPT

典型 CPT 使用纯文本字段，例如 `{"text": "..."}`。本项目 PT 数据来自 EmoLLM 心理问答片段，构建为

```text
[USER] …问题…
[ASSISTANT] …回答…
```

整段作为普通 token 流做 CLM——`[USER]` / `[ASSISTANT]` 也会被预测。目的主要是**拉近心理中文分布**，并为后续「先用户后助手」的轮次结构做铺垫；并不指望 CPT 单独学会 chat template。

#### 3.3.5 CPT 与 SFT 的核心区别

| | CPT | SFT |
|--|-----|-----|
| 目标 | 学习文本分布 / 领域知识与用词 | 学习「如何按指令回答」 |
| Loss 范围 | 通常**几乎全 token** | 通常**仅 assistant** |
| 数据 | 连续文本或拼成文本的 Q-A | 指令—对话（ShareGPT 等） |
| 风险 | 过拟合、遗忘通用能力；可能削弱「助手感」 | 过拟合模板；未必压制敷衍偏好 |

常见流水线：

$$
\boxed{\text{基座} \rightarrow \text{CPT} \rightarrow \text{SFT} \rightarrow \text{偏好对齐（如 DPO）}}
$$

### 3.4 SFT（Supervised Fine-Tuning，assistant-only loss）

#### 3.4.1 在算什么

监督微调把多轮对话写成模型可见的 chat 序列，但优化目标是：**在给定上下文（system / 历史 / 当前用户）时，提高标准助手回复的似然**。

记上下文为 $x$，助手回复 token 为 $y=(y_1,\ldots,y_M)$，则

$$
\mathcal{L}_{\mathrm{SFT}}
=
-\sum_{m=1}^{M}
\log P_\theta(y_m \mid x, y_{<m}).
$$

用户与 system 段在实现里通常把对应 `labels` 设为 $-100$，即 **assistant-only loss**。这样模型学的是「怎么答」，而不是把用户的话也当成要复述的目标。

#### 3.4.2 与 CPT 对照（本项目）

- CPT：`cutoff_len=1024`，全段 CLM，lr $5\times 10^{-5}$，3 epoch；
- SFT：`cutoff_len=2048`，assistant-only，lr $2\times 10^{-5}$，1 epoch。

SFT 学习率更低：因为已在（或即将在）适配过的权重上微调，过大 lr 易破坏指令遵循。

#### 3.4.3 ShareGPT 形态（直觉）

样本形如多轮 `human` / `gpt` 交替。框架套用 chat template 后得到 `input_ids`；仅 `gpt` 段进入损失。本项目主 SFT 还带统一 system 人设，让「SoulHarbor 助手」的称呼与语气在监督信号里稳定出现。

### 3.5 DPO（Direct Preference Optimization）

#### 3.5.1 要解决什么

SFT 让模型模仿「好的回答」，但心理场景中「空泛 / 欠共情 / 敷衍 / 说教」往往也是通顺的中文——仅靠模仿正样本，不一定能**主动压住**这些失败模式。偏好对齐引入成对比较：同一上下文 $x$ 下，chosen 回复 $y_w$ 优于 rejected 回复 $y_l$。

#### 3.5.2 经典 sigmoid DPO 损失

原版 DPO（Rafailov et al., NeurIPS 2023）在 implicit reward 视角下，得到可直接对策略优化的目标。常用 **sigmoid** 形式为：

$$
\boxed{
\begin{aligned}
\mathcal{L}_{\mathrm{DPO}}(\theta)
=
-\mathbb{E}_{(x,y_w,y_l)\sim \mathcal{D}}
\Big[
\log \sigma\Big(
\beta \big[
(\log \pi_\theta(y_w\mid x) - \log \pi_{\mathrm{ref}}(y_w\mid x))
-
(\log \pi_\theta(y_l\mid x) - \log \pi_{\mathrm{ref}}(y_l\mid x))
\big]
\Big)
\Big]
\end{aligned}
}
$$

其中 $\sigma$ 为 sigmoid。直观含义：

- 相对参考策略 $\pi_{\mathrm{ref}}$，提高 chosen 的相对对数概率；
- 同时降低 rejected 的相对对数概率；
- 二者差距越大，损失越小。

本仓库：`pref_loss: sigmoid`，`pref_beta: 0.1`。

#### 3.5.3 $\beta$ 的含义

$\beta > 0$ 控制**偏离参考策略的幅度**（与 KL 约束强度相关的温度式系数）：

- $\beta$ **过大**：策略敢于大幅偏离 $\pi_{\mathrm{ref}}$，偏好学得猛，但易不稳定 / 过拟合偏好集；
- $\beta$ **过小**：几乎不学偏好，接近停留在参考附近。

$0.1$ 是社区常用的稳妥起点；本项目未做大规模 $\beta$ 网格搜索，以稳定可复现为先。

#### 3.5.4 相对 RLHF / PPO：为何选 DPO

经典 RLHF 路径大致为：

$$
\text{SFT} \rightarrow \text{训练奖励模型 RM} \rightarrow \text{PPO 等强化学习更新策略}.
$$

其工程与实验负担包括：额外 RM、强化学习训练不稳定、超参多、算力与实现复杂度高。

DPO 的关键吸引力是：在一定假设下，**可直接用偏好对闭式优化策略**，无需单独 RM，也无需 PPO 循环。对本项目（单卡、中等规模偏好数据 3000 对、目标明确为压制「敷衍 / 欠共情」）而言，DPO 是更匹配的对齐工具。

代价与注意：

- 偏好数据质量决定上限（rejected 必须真的「差在点子上」）；
- 自动 n-gram 指标不一定随 DPO 单调上升（见第 5 章）；
- 学习率通常再降一档（本项目 DPO lr $=5\times 10^{-6}$），避免过度偏离。

#### 3.5.5 本项目偏好对构造（摘要）

- **上下文 / chosen**：来自 SoulChat 与主 SFT **互斥**的切片；chosen 取语料中较好的共情回复；
- **rejected**：由外部模型（MiniMax）按「空泛、欠共情、敷衍、说教」指令合成；
- 互斥是为了避免同一对话既 SFT 又 DPO 造成的泄漏与虚高。

### 3.6 检索基础：dense cosine、BM25、RRF

> 完整 ER 管线在 Part B；此处只给对话线读者也需要的**检索三件套直觉**，因记忆读路径与评测都会用到这些概念。

#### 3.6.1 Dense 检索与余弦相似度

将查询 $q$ 与文档块 $d$ 编码为向量 $\mathbf{e}_q, \mathbf{e}_d$（本项目记忆侧用 BGE-M3，维数 1024）。余弦相似度：

$$
\cos(q,d)
=
\frac{\mathbf{e}_q^\top \mathbf{e}_d}{\|\mathbf{e}_q\|\,\|\mathbf{e}_d\|}.
$$

若向量已 L2 归一化，则 $\cos(q,d)=\mathbf{e}_q^\top \mathbf{e}_d$（内积即可）。Dense 擅长语义相近但字面不同的匹配（「睡不着」↔「失眠」）。

#### 3.6.2 BM25 直觉（词法检索）

BM25 是经典稀疏检索打分：查询词在文档中出现得越「特有且足够频」，分数越高，并对文档长度做归一。直觉：

- 稀有专名、数字、精确短语往往靠词法更稳；
- 纯语义向量有时会「意思对但指称错」。

中文场景可用**字级** n-gram（如 unigram/bigram）估计词项，对姓名、课程名、日期更敏感。Dense 与 BM25 **互补**：一个抓语义，一个抓字面锚点。

#### 3.6.3 RRF（Reciprocal Rank Fusion）

当两路或多路检索各给出一份排序列表时，需要融合。**RRF** 不依赖原始分数量纲，只看排名：

$$
\mathrm{RRF}(d)
=
\sum_{i \in \text{systems}}
\frac{1}{k + \mathrm{rank}_i(d)}.
$$

其中 $\mathrm{rank}_i(d)$ 是文档 $d$ 在第 $i$ 路排序中的名次（从 1 起），$k$ 为平滑常数（常见 $k=60$）。排名越靠前，贡献越大；未出现在某路时可视为无穷远或不加分（实现细节依代码）。

本项目记忆 hybrid 召回：BGE-M3 cosine 与字级 BM25 → RRF 融合得锚点，再进入扩窗等后续步骤（Part B）。§3.7.3 会把 BGE-M3 本身的原理补全；§3.6 只给检索打分直觉。

### 3.7 三个预训练模型：原理与选型

三者分工先立住：

```text
Qwen3-14B + chat LoRA  →  怎么说（自回归生成）
MacBERT-base           →  说多用力（分类 → LoRA scale）
BGE-M3 (+ 字级 BM25)   →  怎么找到经历原文（双塔编码 + 检索）
```

#### 3.7.1 Qwen3-14B — 因果语言模型（生成基座）

##### 原理：自回归下一个词预测

**Qwen3-14B** 是 decoder-only **因果语言模型**（Causal LM）：给定前文 token 序列 $x_{1:t-1}$，预测下一个 token 的条件分布

$$
p_\theta(x_t \mid x_{1:t-1})
=
\mathrm{softmax}\big(W_{\mathrm{lm}}\, h_t\big),
$$

其中 $h_t$ 是 Transformer 在位置 $t$ 的隐状态，$W_{\mathrm{lm}}$ 为词表投影。整句（或整段回复）的联合概率按链式法则分解：

$$
p_\theta(x_{1:T})
=
\prod_{t=1}^{T} p_\theta(x_t \mid x_{1:t-1}).
$$

**因果掩码**保证位置 $t$ 只能看见 $\le t$ 的上下文（不能偷看未来），因此训练目标就是最大似然 / 交叉熵：

$$
\mathcal{L}_{\mathrm{LM}}
=
-\sum_{t} \log p_\theta(x_t \mid x_{1:t-1}).
$$

本项目的 **PT（CPT）** 正是在领域语料上继续做这件事；**SFT** 则把「用户提示 + 期望回复」拼成序列，仍用同一因果损失，只是监督信号更结构化；**DPO** 不再直接改最大似然目标，而是用偏好对相对排序（见 §3.5）。

推理时逐 token 采样或贪心解码；流式输出就是把已生成的前缀不断喂回模型。温度、top-p 等只改变从 $p_\theta(\cdot\mid\cdot)$ 里怎么抽样，不改变模型本身。

##### 与 Encoder（BERT 族）的关键差别

| | Qwen3（Decoder） | MacBERT / BGE-M3（Encoder 系） |
|--|------------------|--------------------------------|
| 注意力 | 因果（只看左边） | 双向（整句互见） |
| 典型输出 | 下一个 token / 一段话 | 句向量或分类 logits |
| 本项目用途 | **写回复** | 分类 / 检索，**不直接生成倾诉回复** |

##### Qwen3 的 thinking / non-thinking

Qwen3 支持「思考再答」与「直接答」。倾听对话里，长思考链容易把内部推理暴露成用户可见废话，也拉长延迟。本项目推理模板用 **`qwen3_nothink`**：关闭 thinking，让生成路径更贴近「短、稳、可流式」的对话助手。

##### 选型与本项目用法

| 项 | 说明 |
|----|------|
| **规模** | 约 **$14.8\times 10^9$** 参数；路径 `models/Qwen3-14B`（`SOULHARBOR_LLM_BASE`） |
| **为何选** | ① 中文与指令遵循够做校园心理对话；② **14B + 4-bit QLoRA** 单卡可训可推；③ LLaMA-Factory / PEFT 成熟。未选纯 API：要本地可控、可挂 ER/MacBERT。未选 7B：记忆拼接与多轮倾听需要更大表达余量。 |
| **作用** | 唯一生成引擎：用户可见对话、会话摘要（关 LoRA）、可选查询规划 / Profile JSON 抽取 |
| **训不训** | **基座冻结（QLoRA）**；可训部分是 LoRA（$r=8,\alpha=16$）。线上只挂 **一份** DPO chat LoRA，`set_scale`：咨询 0.7 / 闲聊 0.3 |

#### 3.7.2 MacBERT-base — 双向编码器 + 序列分类

##### 原理：从 BERT 的 MLM 说起

**BERT** 类模型是 **双向 Encoder**：每个 token 可以看见整句上下文。预训练经典目标是 **MLM（Masked Language Modeling）**：随机遮住部分 token，用两侧语境预测被遮位置。

原始 BERT 常用 `[MASK]` 符号。微调下游时输入里通常**没有** `[MASK]`，于是出现 **pretrain–finetune mismatch**。

**MacBERT**（Cui et al., Findings of EMNLP 2020，[arXiv:2004.13922](https://arxiv.org/abs/2004.13922)）面向中文，用 **近义/相似词替换** 等方式改写 MLM：被「遮」的位置填的是真实词表中的近义词，而不是特殊 `[MASK]`，从而缩小预训练与下游分布差距。本项目骨架是 **`chinese-macbert-base`**。

##### 原理：序列分类头在算什么

意图路由不是生成，而是 **二分类**。实现上为 `AutoModelForSequenceClassification`：

1. 编码整句（或用户当前话轮）得到隐状态序列；
2. 取 **[CLS]**（或池化）向量 $\mathbf{h}_{\mathrm{cls}}\in\mathbb{R}^{d}$；
3. 线性头得到 logits $\mathbf{z}=W_c\mathbf{h}_{\mathrm{cls}}+b_c\in\mathbb{R}^{2}$；
4. Softmax / argmax 得到 `is_consult∈{0,1}`。

训练损失为交叉熵：

$$
\mathcal{L}_{\mathrm{cls}}
=
-\log p(y\mid x)
=
-\log\frac{e^{z_y}}{\sum_{c\in\{0,1\}} e^{z_c}}.
$$

数据：SoulChat 作咨询正例、LCCC 作闲聊负例，**1:1**，规模 **3000 / 300 / 300**（训/验/测）。验证准确率约 **99.7%**，测试约 **99.0%**。

##### 为何不用 14B 做分类

| 维度 | MacBERT-base | 让 Qwen3 零样本判意图 |
|------|--------------|------------------------|
| 延迟 | 毫秒～几十毫秒 | 一次完整 LLM 前向，贵一个量级 |
| 稳定性 | 固定头、可离线测准 | 提示敏感、格式漂移 |
| 职责 | **只**出 scale | 易与生成耦合，误判代价膨胀 |
| 显存 | 小 | 与生成争同一块卡 |

选 **base 而非 large**：任务足够简单，再加大主要换更慢推理；显存应留给 14B 与 BGE-M3。

##### 选型与本项目用法

| 项 | 说明 |
|----|------|
| **路径** | 预训练 `models/encoders/chinese-macbert-base`；微调产物 `outputs/classifiers/intent/`（优先 best checkpoint） |
| **作用** | `is_consult` → **只**调 chat LoRA 的推理 scale 与路由指标；**不**开关记忆、不改写 Trace |
| **训不训** | **训**：在对照数据上微调编码器 + 分类头；线上加载微调 checkpoint |

#### 3.7.3 BGE-M3 — 文本嵌入与双塔检索

##### 原理：embedding 模型在学什么

生成模型输出「下一词」；**嵌入模型**把变长文本映成固定维向量，使**语义相近的文本在向量空间里靠近**。检索时：

$$
\mathrm{score}(q,d)
=
\cos\!\big(\mathbf{e}_q,\mathbf{e}_d\big)
=
\frac{\mathbf{e}_q^\top \mathbf{e}_d}{\|\mathbf{e}_q\|\,\|\mathbf{e}_d\|}.
$$

向量已 L2 归一化时，余弦退化为内积——这正是本项目 FAISS **`IndexFlatIP`** 的用法（见 §3.6.1）。

训练上，现代检索嵌入多采用 **对比学习 / 双塔（bi-encoder）**：查询塔与文档塔（可共享权重）分别编码；正配对拉近、负配对推远（InfoNCE 等）。推理时文档可**离线预计算**向量入库，查询只编一次——这是相对 cross-encoder「每对拼在一起算分」的效率优势，也是 Trace 能「写时嵌入、读时秒级召回」的前提。

##### BGE-M3 的「M3」：三种能力，本项目只用 dense

**BGE-M3**（BAAI，[arXiv:2402.03216](https://arxiv.org/abs/2402.03216)）名中的 **M3** 指多功能：

| 能力 | 含义 | 本项目 |
|------|------|--------|
| **Dense** | 单向量（本仓库 **1024** 维）表整段语义 | **使用**：`FlagEmbedding.BGEM3FlagModel` 取 dense |
| **Sparse** | 类词项权重，偏词法 | 不用；词法侧另有**字级 BM25** |
| **Multi-vector** | 多向量细粒度匹配（ColBERT 风格） | 不用；省存储与复杂度 |

不另训：官方/本地权重冻结；路径 `models/encoders/bge-m3`。创新点不在「重新训更好的 embedding」，而在 ER 的写入形态与读路径重建。

##### 与 BM25 / RRF 如何配合（原理层）

- **Dense（M3）**：抓「睡不着 ↔ 失眠」这类字面不同、语义相近；
- **字级 BM25**：抓人名、课程名、日期、数字等**特有字面锚点**（向量有时「意思对、指称错」）；
- **RRF**（§3.6.3）：两路排序融合，不依赖分数量纲是否可比。

扩窗阶段还会对邻接句与锚点再算 $\cos(c,a)$——仍是同一套 dense 几何，只是用途从「召回」变成「要不要把邻居拼进经历窗」。

##### 关键纪律：向量 ≠ 记忆

长期记忆的证据主体是 **Trace 原文**；$\mathbf{e}_d$ 只是检索键。老师问「有没有向量库」：有按用户缓存的 FAISS，但**记的是原文，不是把人生压缩进 1024 维**。

##### 选型与本项目用法

| 项 | 说明 |
|----|------|
| **为何选** | 中文检索强、开箱即用；与 BM25 互补；本地可复现（隐私）。未选纯词法：漏同义改写；未选更大编码器：单卡预算与「只做文本经历」不匹配 |
| **写** | 每条 Trace 分块嵌入入库（失败进重试队列） |
| **读** | dense 召回 + 扩窗余弦；再与 BM25→RRF 衔接 |
| **训不训** | **不另训** |

---

#### 3.7.4 三者对照（答辩一页纸）

| | Qwen3-14B | MacBERT-base | BGE-M3 |
|--|-----------|--------------|--------|
| **家族** | Decoder Causal LM | Encoder + 分类头 | 检索嵌入（bi-encoder） |
| **核心运算** | $p(x_t\mid x_{<t})$ | $p(y\mid x)$ 二分类 | $\cos(\mathbf{e}_q,\mathbf{e}_d)$ |
| **本项目输出** | 自然语言回复 / 摘要 / JSON | `is_consult` → scale | 1024-d 向量 |
| **是否另训** | 只训 LoRA | 训分类器 | 否（冻结） |
| **挂掉时** | 对话主路径不可用 | 默认偏咨询路由 | 记忆块可空，对话可继续 |

若老师追问「为什么三个模型而不是端到端一个大模型」：生成、路由、检索的**失败模式与延迟预算不同**；解耦后可独立评测、独立降级，也避免「同一个 14B 既当运动员又当裁判又当图书管理员」。

### 3.8 评测指标：原理与公式

> 本项目两套评测回答不同 RQ，**指标不可混用证明**。  
> - **对话线（RQ1）**：BLEU / ROUGE ——「生成是否更像倾听域参考」。  
> - **记忆线（RQ2）**：QA 准确率 / Staleness / 内容 F1 ——「同 reader 下，记忆形态差多少」。  
> - **意图分类**：Accuracy —— MacBERT 二分类是否分对。  
> 实现：对话见 `evaluate/dialogue/lib/metric.py`；记忆见 `evaluate/memory/er_eval/run_qa_er.py` 中 `score_questions` / `content_f1`。

#### 3.8.0 共同预备：n-gram 与分词

文本先切成 token 序列。本项目对话评测用 **jieba 中文分词**后按词计 n-gram（不是按汉字字符）。

$n$-gram：连续 $n$ 个 token 构成的片段。例如分词后「我 / 最近 / 失眠」的 2-gram 有「我 最近」「最近 失眠」。

下文记：

- 假设（hypothesis）$h$：模型生成；
- 参考（reference）$r$：语料标准回复（本评测单参考）；
- $\mathrm{Count}_n(x)$：文本 $x$ 中某 $n$-gram 的出现次数；
- $\mathrm{ClipCount}_n(g)$：该 $n$-gram 在 $h$ 中的计数，但**不超过**它在 $r$ 中的计数（防止胡乱重复刷分）。

---

#### 3.8.1 BLEU（Bilingual Evaluation Understudy）

##### 在测什么

BLEU 问的是：生成里的用词组合，有多少**精确出现**在参考里？本质偏 **精确率（precision）**：奖励「说出来的片段像参考」，不太直接惩罚「参考里有、生成没说」。

##### 修正 n-gram 精确率

对阶数 $n$，

$$
p_n
=
\frac{\sum_{g\in n\text{-grams}(h)} \mathrm{ClipCount}_n(g)}{\sum_{g\in n\text{-grams}(h)} \mathrm{Count}_n(g)}.
$$

分子用 clip：同一短语在假设里重复 10 次、参考只出现 1 次，最多只算 1 次命中。

##### 几何平均与简短惩罚（经典完整式）

经典语料级 BLEU 常写为

$$
\mathrm{BLEU}
=
\mathrm{BP}\cdot \exp\!\Big(\sum_{n=1}^{N} w_n \log p_n\Big),
$$

其中权重常取均匀 $w_n=1/N$（$N=4$ 即常用 BLEU-4），$\mathrm{BP}$ 为 **brevity penalty**（生成过短时惩罚）：

$$
\mathrm{BP}
=
\begin{cases}
1, & |h| > |r|, \\[4pt]
e^{1-|r|/|h|}, & |h| \le |r|.
\end{cases}
$$

##### 本项目实际报告的 BLEU-1…4

实现用 NLTK `sentence_bleu`，对每条样本分别算四个权重设定，再对全集平均，最后 **×100** 写成百分数：

| 报告名 | 权重 $(w_1,w_2,w_3,w_4)$ | 直觉 |
|--------|--------------------------|------|
| BLEU-1 | $(1,0,0,0)$ | 只看 unigram 重合 |
| BLEU-2 | $(1/2,1/2,0,0)$ | 兼顾 1–2 gram |
| BLEU-3 | $(1/3,1/3,1/3,0)$ | 兼顾 1–3 gram |
| BLEU-4 | $(1/4,1/4,1/4,1/4)$ | 经典四阶几何平均 |

短句上 $p_n$ 易为 0，实现启用 **SmoothingFunction().method1**，避免 $\log 0$。答辩说「词级 sentence BLEU，method1 平滑，百分制」即可。

##### 读数纪律

- 越高 → 与**那一句**参考的用词组合越像；  
- **不等于**共情更好；开放生成常有「合理但换说法」导致 BLEU 偏低；  
- DPO 后 BLEU 略降可以与「偏好优化 ≠ 贴参考」同时成立（见第 5 章）。

---

#### 3.8.2 ROUGE（Recall-Oriented Understudy for Gisting Evaluation）

##### 在测什么

ROUGE 族更偏 **召回 / 覆盖**：参考里的信息，生成盖住了多少？本项目用 `rouge` 库报告的是各指标的 **F 值**，再 ×100。

对给定 $n$，先定义 n-gram 重叠的精确率与召回：

$$
P_n
=
\frac{\sum_g \min\big(\mathrm{Count}_n(h,g),\,\mathrm{Count}_n(r,g)\big)}{\sum_g \mathrm{Count}_n(h,g)},
\qquad
R_n
=
\frac{\sum_g \min\big(\mathrm{Count}_n(h,g),\,\mathrm{Count}_n(r,g)\big)}{\sum_g \mathrm{Count}_n(r,g)}.
$$

F1：

$$
F_n
=
\frac{2 P_n R_n}{P_n + R_n}
\quad (P_n+R_n>0).
$$

- **ROUGE-1**：$n=1$（词重叠）  
- **ROUGE-2**：$n=2$（词对重叠）

##### ROUGE-L：最长公共子序列（LCS）

不必连续，但须保持相对顺序。令 $\mathrm{LCS}(h,r)$ 为最长公共子序列长度，$m=|r|$，$n=|h|$：

$$
R_{\mathrm{lcs}} = \frac{\mathrm{LCS}(h,r)}{m},
\qquad
P_{\mathrm{lcs}} = \frac{\mathrm{LCS}(h,r)}{n},
\qquad
F_{\mathrm{lcs}}
=
\frac{(1+\beta^2) R_{\mathrm{lcs}} P_{\mathrm{lcs}}}{R_{\mathrm{lcs}}+\beta^2 P_{\mathrm{lcs}}}.
$$

常用 $\beta=1$（等权 F1）。允许词序不完全相同，比严格 n-gram 对「同义改写但顺序微变」更宽容一点，仍远不是语义等价度量。

##### BLEU vs ROUGE（一句话）

| | BLEU | ROUGE（本项目报 F） |
|--|------|---------------------|
| 更偏 | 生成像不像参考（精） | 参考内容盖住多少（召回→F） |
| 心理对话 | 易低估「换说法的好回复」 | 同样受单一参考限制 |
| 本项目观察 | DPO 后常略降 | ROUGE-1/2 可略升或持平 |

---

#### 3.8.3 分类准确率（MacBERT）

二分类样本集上：

$$
\mathrm{Accuracy}
=
\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\big[\hat{y}_i = y_i\big].
$$

本项目报告验证 ≈ **99.7%**、测试 ≈ **99.0%**（正负 1:1）。准确率高只说明路由稳，**不**证明倾听质量；路由唯一用途是选 LoRA scale。

---

#### 3.8.4 记忆 QA 准确率

固定 reader，第 $i$ 题答案与金标准精确匹配则记对：

$$
\mathrm{QA\text{-}Acc}
=
\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\big[\mathrm{correct}_i\big].
$$

终版 $N$ 来自 30 弧 × 每弧约 3 题（约 90 个探测点）。**同 reader、只换记忆库**时，准确率差应归因于记忆形态，而非答题模型。

逐类 QA（`detail_recall` 等）是同一公式在 subclass 上的子集平均。

---

#### 3.8.5 Staleness 率（过时率）

专门度量「**已过时状态仍被当成当前事实**」。协议里对 `probes ∈ {staleness, current}` 的题目子集 $S$：

$$
\mathrm{StalenessRate}
=
\frac{1}{|S|}\sum_{i\in S}\mathbf{1}\big[\neg\,\mathrm{correct}_i\big].
$$

即：在抗陈旧 / 当前状态探针上的**错误率**。越低越好。  
ER **14.3%** vs Mem0 **42.9%**：原文 + 含新近性的选窗，比写时抽取更少把旧状态当现状。

注意：staleness **不是**「库里还有没有旧 Trace」——旧经历可以保留以备回问；错的是**当前题仍被旧证据带偏**。

（实现里另有 `overgeneralization_rate`：在 `probes=overgeneralization` 子集上的错误率，主表通常强调 QA / staleness / F1。）

---

#### 3.8.6 内容 F1（应记 / 应忘）

金标准提供两袋事实：

- $\mathcal{R}$：`should_remember`（应长期可回忆）  
- $\mathcal{F}$：`should_forget`（应忘掉 / 不应固化）

评测用 **与 QA 同一路的 MiniMax reader**（`content_f1()` in `run_qa_er.py`）对照「记忆库列出的事实」与金标准，要求模型只输出 JSON：

```text
remembered_ok / forgotten_ok / false_remember / missed
```

| 符号 | 对应 JSON 字段 | 含义 |
|------|----------------|------|
| $\mathrm{TP}$ | `remembered_ok` | 应记且库中有对应 |
| $\mathrm{FN}$ | `missed` | 应记但漏了 |
| $\mathrm{FP}$ | `false_remember` | 应忘却误存 / 误固化 |

$$
\mathrm{Precision}
=
\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}},
\qquad
\mathrm{Recall}
=
\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}},
\qquad
F_1
=
\frac{2\cdot \mathrm{Precision}\cdot \mathrm{Recall}}{\mathrm{Precision}+\mathrm{Recall}}.
$$

边界约定（与代码一致）：分母为 0 时按「该侧无约束」给 1.0 或 0.0 的缺省，避免空集除零。若 JSON **解析失败**且存在应记项，实现把应记全部记为 `missed`（偏严、避免空分虚高）。

直觉：QA-Acc 看「答题对不对」；内容 F1 看「库内容相对应记/应忘金标准齐不齐、有没有脏」。两者互补——会答对选择题，仍可能库里堆了该忘的标签。

**诚实上限**：内容 F1 本身带 **LLM-as-judge 噪声**（对齐「语义是否命中」而非字符串全等）；主结论仍应以同协议下的相对差距为主，不宜把 0.84 读成「绝对事实完整度」。

### 4.1 总览：数据 → 权重 → 线上

```text
上游语料（SoulChat / EmoLLM / LCCC / 自我认知补充 / MiniMax 合成）
        │
        ▼
   构建脚本 → train/data/llm/*.jsonl
        │
        ▼
 CPT (pt.jsonl, 24443)  →  pt_* LoRA
        │
        ▼
 SFT（倾听 ~20000 + 自我认知 ~274，同一阶段混合）→  sft_* LoRA
        │
        ▼
 DPO (dpo.jsonl, 3000)  →  dpo_synth_*  【线上 chat LoRA】
        │
        └─ 并行：MacBERT 意图分类（3000/300/300）→ intent checkpoint
```

线上推理：**只挂一份 DPO chat LoRA** + MacBERT 意图头；中间 PT/SFT 目录保留以便复现与回滚，默认不同时加载。

### 4.2 数据来源与职责

| 来源 | 是什么 | 在本项目中的用途 |
|------|--------|------------------|
| **SoulChatCorpus** | 心理多轮共情对话语料（SoulChat，Findings of EMNLP 2023） | SFT 主体（约九成）；意图**正样本**；DPO prompt 池（与 SFT **互斥**）；对话 BLEU/ROUGE 评测池 |
| **EmoLLM** | 开源心理向微调项目整理的中间语料 | PT：`pt.json` → 24443 条；SFT 混入约一成 `data_pro` 多轮 |
| **自我认知补充** | 助手身份 / 能力边界问答（约 274 条，中英混） | **并入同一 SFT 阶段**，锁「我是 Soulharbor」等人设 |
| **LCCC** | 大规模中文闲聊（清华 COAI） | 意图分类**负样本**（`is_consult=0`） |
| **MiniMax** | 外部生成 API | **仅**合成 DPO 的 rejected（敷衍/欠共情等）；不进线上推理 |

### 4.3 各阶段数据规模与格式

| 阶段 | 活跃文件 | 条数 | 格式要点 | 产出 |
|------|----------|------|----------|------|
| CPT | `pt.jsonl` | **24443** | `{"text":"[USER]…\n[ASSISTANT]…"}` 全段 CLM | 中间 PT LoRA |
| **SFT** | `sft_instruction.jsonl` + 自我认知补充 | **~20000 + ~274** | ShareGPT；倾听为主、人设为辅，**同一阶段混合** | 进 DPO 前的 **sft** 权重 |
| DPO | `dpo.jsonl` | **3000** | ShareGPT 上下文 + `chosen` / `rejected` | **线上 chat** |
| 意图 | `intent_*.jsonl` | **3000 / 300 / 300** | train/valid/test，正负 1:1 | MacBERT checkpoint |

SFT 混合直觉：SoulChat ≈ 90% + EmoLLM data_pro ≈ 10% 构成倾听主干，并对首轮用户句互斥去重；另混入约 274 条自我认知问答，保证「你是谁 / 能做什么」有稳定监督。人设占比很小，**不单独算一个训练阶段**。

DPO 互斥：进入 DPO 的 prompt 不与主 SFT 训练样本重叠，减少「同一对话既模仿又偏好」的泄漏。

**格式直觉（答辩可口述）**：

- CPT：一条样本就是一段连续文本（常带 `[USER]`/`[ASSISTANT]` 标记），对几乎所有 token 做下一词预测——学的是域分布，不是「怎么答」。  
- SFT：ShareGPT 多轮；训练时只对 assistant 段计 loss（label $-100$ 屏蔽用户/system）。  
- DPO：同一上下文下给一对回复；`chosen` 来自共情向语料，`rejected` 由外部模型按「空泛/欠共情/敷衍/说教」指令合成（温度约 0.8）；损失比较的是相对 reference 的 log 比差。  
- 意图：instruction + 多轮截断输入 → JSON `{"is_consult":0/1}`；正负 1:1，负样本来自 LCCC 闲聊。

校园占比：SFT 构建脚本默认 `--campus-ratio 0.62`，用话题与校园相关度提高校园场景比例，减少「校园词=咨询」的伪相关（意图侧另用字长对齐的闲聊负样本）。

### 4.4 各阶段训练目标（研究语言）

| 阶段 | 优化目标（人话） | 损失类型 |
|------|------------------|----------|
| **CPT** | 让基座更熟悉心理中文的用词、句式与问答共现 | 全 token 因果 CE |
| **SFT** | 学会咨询节奏下的应答方式与助手格式；混合自我认知样本锁身份 | assistant-only CE |
| **DPO** | 相对 reference，抬高共情 chosen、压低敷衍 rejected | sigmoid DPO |
| **意图** | 稳定区分咨询 vs 闲聊，供 scale 旋钮使用 | 交叉熵分类 |

### 4.5 超参数总表（权威：`train/configs/*.yaml`）

公共设置：Qwen3-14B；QLoRA **4-bit**；LoRA **$r=8$，$\alpha=16$**；`lora_target: all`；cosine 调度；`warmup_steps=20`；`per_device_train_batch_size=1`；`gradient_accumulation_steps=16`；`fp16`；`flash_attn: sdpa`；`gradient_checkpointing`；`seed=42`；模板 `qwen3_nothink`（关闭 thinking）。

| 项 | CPT（PT） | SFT | DPO |
|----|-----------|-----|-----|
| 配置文件 | `pt.yaml` | `sft_main.yaml` | `dpo.yaml` |
| 学习率 | **$5\times 10^{-5}$** | **$2\times 10^{-5}$** | **$5\times 10^{-6}$** |
| epoch | **3** | **1** | **1** |
| cutoff | **1024** | **2048** | **2048** |
| 特有项 | 领域 CLM | `val_size=0.02`，`load_best_model_at_end` | `pref_beta=0.1`，sigmoid |

#### 4.5.1 超参阶梯为什么这样设

| 选择 | 理由 |
|------|------|
| CPT lr 最高（5e-5） | 需要明显搬动领域分布；过小约等于没训 |
| SFT lr 中（2e-5） | 在适配权重上学格式与话术，过大易毁指令遵循 |
| DPO lr 最低（5e-6） | 只做偏好微调，防止过度偏离 reference |
| CPT 3 epoch / SFT·DPO 1 epoch | CPT 语料短片段可多看；偏好对齐易过拟合，少 epoch |
| CPT cutoff 1024 | PT 样本偏短（约百字级），1024 足够且省显存 |
| SFT/DPO 2048 | 多轮对话更长，覆盖多数样本的上下文 |

### 4.6 意图分类：MacBERT

> 编码器 / MLM / 分类头原理见 **§3.7.2**；本节只写任务定义、数据与线上职责。

#### 4.6.1 任务定义

二分类：本轮用户侧文本属于 **咨询倾诉**（`is_consult=1`）还是 **日常闲聊**（`is_consult=0`）。

输入构造原则与训练一致：主要使用**用户话轮**（带 `[USER]` 前缀），不把助手回复当作分类依据——判断的是「用户在倾诉还是闲聊」，不是「助手像不像咨询师」。

#### 4.6.2 数据与指标

- 规模：train / valid / test = **3000 / 300 / 300**；
- 正负严格 **1:1**；按轮数与字长对齐，降低长度捷径；
- 正样本来自 SoulChat，负样本来自 LCCC；
- 编码器：**chinese-macbert-base** + 分类头；
- 训练超参（`train/configs/intent_classifier.json`）：`max_length=512`，lr **$2\times 10^{-5}$**，**1 epoch**，batch 16，seed 42；
- 线上加载：优先 `trainer_state.json` 记录的 best checkpoint（常见如 `checkpoint-188`）；
- 报告指标：**验证准确率约 99.7%，测试约 99.0%**。

#### 4.6.3 为何用独立分类器，而不是让 14B 自己判

1. **快且稳**：毫秒～几十毫秒级，可离线评测；
2. **与生成解耦**：避免大模型既当裁判又当运动员；
3. **误判代价可控**：只影响 LoRA scale，不开关记忆、不改写记忆库；
4. **base 足够**：分流任务简单，再上 large 主要换来更慢推理。

#### 4.6.4 线上唯一职责

`is_consult` → 选择 chat LoRA scale（0.7 vs 0.3）并写入路由指标。**不**门控长期记忆。

### 4.7 线上推理：scale 0.7 / 0.3 与摘要关 LoRA

同一份 DPO adapter，前向仍是

$$y = Wx + s\cdot\frac{\alpha}{r} BAx,$$

其中运行时再乘场景系数 $s$（实现上通过 PEFT 的 adapter scale）：

| 场景 | scale $s$ | 动机 |
|------|-----------|------|
| 咨询路由 | **0.7** | 更强共情与咨询分寸 |
| 闲聊路由 | **0.3** | 减轻「过度治疗」腔 |
| 会话摘要 | **关闭 adapter（裸基座）** | 客观压缩，避免共情腔渗进摘要 |

设计要点：

- **不 merge** 进基座 → 可调 scale、可回滚、可 A/B；
- **不挂第二份任务 LoRA** → 单卡显存与加载简单；
- 摘要关 LoRA → 压缩任务与对话偏好分离。

### 4.8 链式续训与产物关系（答辩口径）

方法主线就是三步：**PT → SFT → DPO**。SFT **只有一个阶段**：倾听指令（约 2 万）与自我认知补充（约 274）视为**同一批混合数据**一起训——人设数据占比很小，作用是钉住「我是 Soulharbor / 能做什么」，避免助手身份漂移；主目标仍是倾听应答。

```text
裸 Qwen3-14B
    │  CPT（pt.yaml）
    ▼
 SFT（倾听语料 + 自我认知补充，混合）→ 评测表里的「sft」
    │
    ▼
 DPO（挂载上一份 SFT adapter）→ dpo_synth_* 【线上 chat】
```

| 阶段 | 配置（仓库） | 备注 |
|------|--------------|------|
| PT | `pt.yaml` | 领域 CLM |
| SFT | `sft_main.yaml`（倾听）+ 自我认知数据文件 | **答辩按混合一批训表述**；超参同为 r=8、α=16、QLoRA |
| DPO | `dpo.yaml` | 从 SFT 权重续训；线上只挂这一份 |

对话评测表的 **sft**：即进入 DPO **之前**的那份 SFT 权重。对比的是「SFT 后 vs DPO 后」。

仓库里自我认知数据可单独成文件，便于构建；**研究叙事按「SFT 混合一批」表述，不要讲成第四个训练阶段**。线上默认只加载最终 DPO。

### 4.9 本章小结

对话线用公开心理/闲聊语料与合成偏好，在单卡 QLoRA 上完成 CPT→SFT→DPO；用 MacBERT 把「咨询/闲聊」从生成模型中拆出，变成可评测的 scale 旋钮。下一章给出自动评测数字，并解释为何 DPO 的 BLEU 可能略降却仍被选为线上权重。

## 5. 对话线评测与解读

### 5.1 评测设定

| 项 | 内容 |
|----|------|
| 数据 | SoulChatCorpus 派生的 **seen / unseen 各 1000** 条 |
| 对比模型 | `base`（裸 Qwen3-14B）；**`sft`**（SFT 混合训练后、进 DPO 前）；**`dpo`**（线上 chat LoRA） |
| 指标 | 词级 **BLEU-1…4**、**ROUGE-1/2/L**（jieba 分词） |
| 解码 | 正式跑次 **temperature=0.95，top_p=0.75，do_sample**（见各 `*_seen/config.json`） |
| 聚合 | 每模型对 seen/unseen **按条数加权**（各 1000 → 等价算术平均） |
| 跑次 | `evaluate/dialogue/runs/soulchat_corpus_eval_20260426_092741/` |

#### 5.1.1 seen / unseen 怎么切（答辩必背）

脚本：`evaluate/dialogue/sampling/sample_soulchat_eval_sets.py`（seed **`20260426`**）。

1. 用对话前至多 **6** 条消息算 **signature**（`soulchat_signatures`）；  
2. 对照 **主 SFT + DPO 训练 JSONL** 已用过的 signature 集合；  
3. signature **出现在训练集** → 候选 **seen**；**未出现** → 候选 **unseen**；  
4. 按 **topic 均衡** + reservoir 抽样，各取 1000。

因此 unseen **不是**「从没见过的话题名」，而是「这条对话签名未进 SFT/DPO 训练池」——仍可能同属熟悉 topic。口述时不要说成「完全没见过的领域」。

#### 5.1.2 评测解码 vs 线上解码

| | 正式 BLEU/ROUGE 跑次 | 线上对话（`chat_model.py`） |
|--|----------------------|------------------------------|
| temperature | **0.95** | 默认 **0.6** |
| top_p | **0.75** | 默认 **0.95** |

数字证明的是「同解码设定下 base→sft→dpo 的相对差距」，**不能直接等同线上听感**。若老师追问：承认设定不同；相对排序仍有参考价值；要对齐线上需用线上温度重跑或做人工盲评。

重要限制（答辩时主动说清）：

- 参考回复**不是唯一标准答案**；心理对话允许多种合格回应；
- BLEU/ROUGE 测的是与参考的 **n-gram / 子序列重合**，**不直接等于共情质量**；
- 指标适合做 **base → sft → dpo 的相对比较**，不适合单独宣称「已达咨询师水平」；
- 本评测**不测记忆**；记忆能力见 Part B 的长程 QA。

### 5.2 指标含义（读表前）

> **完整定义与公式见 §3.8.1–§3.8.2。** 此处只给读表直觉。

| 指标 | 在测什么 |
|------|----------|
| **BLEU-n** | 修正 n-gram **精确率**视角：生成用词组合有多像参考（本项目词级 sentence BLEU，×100） |
| **ROUGE-1/2** | unigram / bigram 重叠的 **F**（更偏覆盖参考信息） |
| **ROUGE-L** | 基于 **LCS** 的 F，允许词序不完全相同 |

BLEU 更「像不像那句参考」；ROUGE 更「参考里的内容盖住了多少」。二者在开放生成里经常不完全同向——这正是 DPO 后「BLEU 略降、ROUGE 略升」可以同时成立的数学原因之一（精偏指标对换说法更敏感）。

### 5.3 主结果表（seen+unseen，n=2000 / 模型）

| 模型 | BLEU-1 | BLEU-2 | BLEU-3 | BLEU-4 | ROUGE-1 | ROUGE-2 | ROUGE-L |
|------|--------|--------|--------|--------|---------|---------|---------|
| base | 13.23 | 5.55 | 2.50 | 1.32 | 20.52 | 4.17 | 15.04 |
| **sft** | **29.56** | **13.06** | **6.90** | **4.17** | 30.65 | 7.89 | **24.64** |
| **dpo** | 27.91 | 12.59 | 6.46 | 3.75 | **31.49** | **8.06** | 24.44 |

数据来源：`aggregate_per_model_seen_unseen.json`（四舍五入至百分位两位）。**sft** = 进入 DPO 前的 SFT 权重（跑次目录名可能为历史命名，答辩统一称 sft）。

### 5.4 分 split 速览（可选深读）

整体趋势在 seen / unseen 上一致：SFT/DPO 远高于 base；DPO 相对 SFT 呈现「BLEU 略降、ROUGE-1/2 略升或持平」的同一模式。说明提升不是「只背见过的参考答案」。

| 模型 | split | BLEU-1 | ROUGE-1 | ROUGE-L |
|------|-------|--------|---------|---------|
| base | seen | 13.05 | 20.49 | 15.00 |
| base | unseen | 13.42 | 20.56 | 15.09 |
| sft | seen | 29.84 | 31.14 | 25.03 |
| sft | unseen | 29.27 | 30.16 | 24.25 |
| dpo | seen | 27.84 | 31.66 | 24.64 |
| dpo | unseen | 27.98 | 31.32 | 24.24 |

### 5.5 如何解读：SFT 相对 base 的跃升

相对 base：

- BLEU-1：约 $13.23 \rightarrow 29.56$（**+16.3**）；
- ROUGE-L：约 $15.04 \rightarrow 24.64$（**+9.6**）。

结论：**领域 SFT（及此前 CPT）有效**——回复在词面与参考心理对话显著更接近，不是「微调无效」或「只换了人设句子」。

### 5.6 如何解读：DPO 相对 SFT 的 BLEU 略降

观察：

- DPO 的 **BLEU-1…4 略低于 SFT**（BLEU-1：$29.56 \rightarrow 27.91$）；
- DPO 的 **ROUGE-1 / ROUGE-2 略高**（31.49 / 8.06 vs 30.65 / 7.89）；
- ROUGE-L **基本持平**（24.44 vs 24.64）。

这与 DPO 的优化目标一致：

> DPO 优化的是「更共情、少敷衍」的**偏好**，不是「更贴近某一句参考原文」的 n-gram 重合。

当模型表达更自然、更多样，或刻意避开参考里某些套路句时，**与单一参考的字面重合可能下降**，而信息覆盖类指标（ROUGE）仍可持平或上升。因此：

1. **不能**因为 BLEU 略降就断言 DPO 失败；
2. **应当**把 DPO 理解成在 SFT 已经拉开的大幅优势之上，做失败模式压制；
3. 线上选择 DPO，是因为偏好目标与产品失败模式（敷衍、欠共情）对齐，且自动指标整体仍远强于 base；
4. 若未来要证明「共情更好」，需要补充人工评测或偏好胜率，而不是只看 BLEU。

### 5.7 答辩可用的三句结论

1. **领域适配有效**：SFT/DPO 相对裸基座，BLEU-1 大约 +14～16，ROUGE-L 大约 +9～10。  
2. **SFT 与 DPO 同量级**：自动指标上两者都远强于 base；DPO 不追求 BLEU 单调上升。  
3. **指标边界清楚**：BLEU/ROUGE 是相对比较工具；记忆能力与「是否乱记」必须用另一套协议（Part B）验证。

### 5.8 与双线叙事的衔接

对话线评测回答的是 RQ1 的一部分：「领域微调后，回复是否更像心理支持对话分布」。  
它**不回答** RQ2。把记忆 QA 的提升错误归因于 DPO，或把 BLEU 提升错误归因于 ER，都是叙事上的因果混淆——这也是第 2 章坚持双线解耦、分协议评测的原因。

## 6. 长期记忆：问题与相关范式

### 6.1 为什么「有记忆」仍可能是问题

跨会话陪伴需要记忆：用户隔周回来，学业压力、室友冲突、失眠等经历应能被衔接。但「记得」可以有多种形态——把对话压成事实句、压成宽画像、切片进向量库、或原样保存经历文本。形态不同，**错误模式也不同**。

心理支持场景的关键约束是 **代价不对称**：

> **误记**（把瞬时情绪写成稳定负面特质，并在后续轮次反复注入）＞ **漏召**（某次没想起一段旧经历）。

漏召的最坏结果通常是「这轮帮不上忙」；误记的最坏结果是持续污染自我叙事。因此记忆系统设计不能只优化「召回更多」，必须从结构上降低「乱记」。

### 6.2 相关范式（对照用）

| 范式 | 代表取向 | 写入时做什么 | 查询时做什么 | 对心理场景的主要风险 |
|------|----------|--------------|--------------|----------------------|
| **写时抽取** | Mem0 一类 | 每轮/攒批用 LLM 把对话压成事实句再入库 | 对事实库做检索 / 排序 | 抽取即改写；瞬时状态易固化为稳定标签 |
| **宽画像 Semantic/Profile** | MemMachine 一类 | schema 很宽，尽量把语义摘要写进画像 | 画像全量或半全量注入 | 「什么都记得一点」；字段边界松 → 情绪/人格类标签易进长期层 |
| **RAG 文档切片** | 经典检索增强 | 文档切块 + 向量化；目标是「哪段文档相关」 | dense / 稀疏检索 + top-$k$ | 单元是文档段而非「一段经历」；缺扩窗与时序重建时，易丢共现上下文 |
| **经历原文 + 扩窗** | 与 ER 同向 | 保存经历原文（少或不做写时归纳） | 命中锚点后再扩展邻域，重建可用证据 | 若不加选窗与新近性，旧高相关窗可能挤掉终态 |

四类范式不是互斥标签，而是**写入理解强度 × 读路径重建强度**上的不同坐标。SoulHarbor 的 ER 刻意站在「写弱、读强」一侧。

### 6.3 写时抽取为何在心理场景代价高

写时抽取的工程吸引力很强：事实句短、易检索、易展示。但在倾诉场景中，用户话轮充满**条件句、反讽、自我否定、尚未成形的判断**。LLM 抽取器天然倾向「下结论」：

- 「这次面试没发挥好」→ 可能被写成「用户自卑 / 能力差」；
- 「我和室友又吵了」→ 可能被写成稳定的「人际关系差」标签；
- 已结束的焦虑（考试已过）→ 若无显式生命周期，旧事实仍可能被反复召回（**stale**）。

一旦错误标签进入长期库，后续每一轮注入都会强化它——这正是「误记 > 漏召」的机制来源。工具调用类指标再好，也无法从结构上消灭「写入时理解」带来的偶发误归纳。

### 6.4 宽画像与经典 RAG 的边界

**宽画像**追求覆盖：身份、情绪、人格、事件摘要都可能进 Profile。对通用助手，这能提高表面连贯；对心理陪伴，它把最不稳定的信息放进最持久的层。SoulHarbor 的结论是：画像必须**窄**，且允许为空。

**经典 RAG** 回答「哪段文档与查询相关」。ER 也用 dense + BM25 + RRF，但检索单元之后还有**经历重建**：自适应扩窗、同会话合并、衰减感知 MMR（含相对新近性）、按时间注入用户原文。换言之，ER 借用了 RAG 的检索积木，但优化目标是「重建一段可审计的经历证据」，而不是「返回分最高的 $k$ 段文本」。

### 6.5 SoulHarbor 的选择（一句话 + 分工）

> **Trace：原文零 LLM 写入；查询时 ER 重建。**  
> **Profile：窄白名单 LLM 抽取，校验通过后直写 active；无则空着。**

| 子系统 | 职责 | 写入是否调用 LLM | 空库是否合法 |
|--------|------|------------------|--------------|
| **Trace** | 可回溯的过程材料（用户/助理原文块） | **否**（分块 + BGE-M3） | Trace 随对话增长；检索可为空 |
| **Profile** | 少数可核验长期事实 | **是**，但仅白名单字段 | **是**——空 Profile 是纪律，不是缺陷 |

白名单（`profile/schema.py`）：

- `identity`：`name` / `gender` / `age`
- `education`：`school` / `grade` / `major` / `degree`
- `location`：`hometown` / `residence`
- `preference`：`communication` / `hobby` / `lifestyle` / `other`

诊断、人格标签、瞬时情绪、单次事件**不在白名单内**；即便模型胡写，代码 `is_allowed` 也会拒绝落库。记住 / 忘掉由 `commands_llm.py` 解析，**无关键词正则门控**。

这与早期「确认制 pending」方案不同：**现行实现是 allowlist 抽取后直接写入 active**（历史 pending 表保留兼容，但非主路径）。Part A §2.3 的表述与此一致。

### 6.6 本章小结

长期记忆的研究问题不是「要不要记忆」，而是「用什么形态记、在什么时候理解」。心理场景的代价结构把设计推向：**写入时尽量不替用户下结论；理解后置到查询时重建；结构化写入收成窄白名单。** 下一章按代码路径展开 ER 的写与读。

## 7. ER 写路径与读路径（对照代码的自然语言说明）

> 代码根目录：`product_app/app/memory/`。默认配置见 `config.py`（`MemorySettings`）。本节公式与默认超参以该文件及 `store/stitch.py`、`store/select.py`、`store/reinforce.py` 为准。

### 7.1 总览

```text
【写路径 · post-turn】
  user/assistant 消息
      ├─► Trace：确定性分块 → BGE-M3 嵌入（可重试）→ 原文入库
      └─► Profile（旁路）：攒批门控 → LLM 白名单抽取 → schema 校验 → 直写 active
           （记住/忘掉：commands_llm；无关键词 detector）

【读路径 · 生成前】
  本轮用户话
      → Memory Planner（direct / split）
      → hybrid：FAISS IP（BGE-M3）top-50 + 字级 BM25 top-50 → RRF（k=60）→ fused top-40
      → Multi-query Anchor CE（原始 query ∪ Planner 子查询；coverage 选 top-12 种子）
      → 自适应扩窗（cos≥0.40 或 邻接实体逃逸）
      → 同会话重叠合并
      → Legacy 时间感知 MMR（$R_{\mathrm{content}}=2\cdot s_{\mathrm{fused}}+1.5\cdot\mathrm{Jaccard}$；recency β=0.8、week 0.5；λ=0.7）
      → 按时间升序注入
      → 使用强化 η=0.1
      → Profile 全量 active（≤30）
      → formatter：仅用户原文；窗数 ≤6；token 预算 1600
```

> **窗级 CE 已否定并移除**。CE 只选 anchor 种子，不替换窗级 $R_{\mathrm{content}}$。默认旋钮见 `product_app/app/memory/config.py`（Dense/BM25 top-50，RRF 40，CE keep 12 / orig 4 / sub 3，窗 top-6，recency 0.8 / week 0.5）。

### 7.2 写路径：Trace（零 LLM）

1. **分块**（`store/chunker.py`）  
   - 软上限 `chunk_soft_limit=500`（字符）；超过则按句读切分。  
   - 目标块长约 `150–350`（`chunk_target_min/max`）。  
   - 规则确定、无模型参与：不抽事实、不合并概括、不生成摘要标签。

2. **嵌入**（`embeddings.py` + `store/ingest.py`）  
   - 编码器：**BGE-M3**，dense 维 **1024**；检索侧默认 **FAISS `IndexFlatIP`**（向量 L2 归一化后内积 ≈ 余弦）。  
   - 失败进入重试队列，`embed_retry_max=5`。

3. **入库单元**  
   - 用户与助理消息均可入库；助理块在召回融合时降权（`assistant_weight=0.55`），因经历证据优先用户原话。  
   - **不做**：写时事实抽取、写时调和、层级晋升、写时时间衰减关闭。

Trace 的哲学一句：**库里留下的是「当时说了什么」，不是「系统认为用户是什么人」。**

### 7.3 写路径：Profile（窄白名单旁路）

代码入口：`profile/schema.py`（白名单）、`extractor.py`（攒批抽取）、`commands_llm.py`（用户指令）、`policy.py`（结构校验，**无诊断词表**）、`service.py` / `engine.py`（接入）。

**白名单**（与源码 `ALLOWED` 一致）：

| tag | 允许 feature |
|-----|----------------|
| `identity` | `name`, `gender`, `age` |
| `education` | `school`, `grade`, `major`, `degree` |
| `location` | `hometown`, `residence` |
| `preference` | `communication`, `hobby`, `lifestyle`, `other` |

存储形态：`[tag/feature] 中文标签：value`（如 `[identity/name] 姓名：小王`）。同一 key **upsert**。`value` 最长约 80 字。

| 项 | 默认 / 行为（对照 `config.py`） |
|----|-------------|
| 开关 | `MEMORY_PROFILE_ENABLED=1`，`MEMORY_PROFILE_LLM_PROPOSE=1` |
| 攒批触发 | 未抽消息数 ≥ **5** 或批次年龄 ≥ **300s**；**助理回合后**触发抽取 |
| 每次上限 | **最多 3**（`MEMORY_PROFILE_LLM_PROPOSE_MAX`） |
| 落库 | `is_allowed` + 用户原文证据重叠通过 → **直写 active**；空 `commands` → **不写** |
| 指令 | `commands_llm` → `remember/forget/correct/inspect/none`；**无关键词 detector** |
| 解析缓存 | 同一句用户话只 LLM 解析一次（读路径 inspect 与写路径 remember/forget 共用） |
| 注入 | `list_for_inject` 全量 active，硬顶 **≤30**，不按查询过滤 |

与 MemMachine 式宽画像的差异：对方倾向宽 schema、条条可写；SoulHarbor **宁缺毋滥**——空 Profile 合法。与「确认制 pending」旧叙事的差异：现行主路径**不再要求用户确认才 active**；边界完全靠白名单 + 结构校验（pending 表仅遗留兼容）。

### 7.4 读路径逐步说明

#### （1）Planner → hybrid 召回 → Anchor CE 选种子

- `QueryRouter`（`retrieval/router.py`）：**无关键词门控**。有 LLM 时用结构化规划（`generate_structured`，温度 0）输出 JSON `{"mode":"direct"|"split","queries":[...]}`；`split` 时多条短查询（比较/多对象题）；失败、解析失败或 `MEMORY_SPLIT_QUERY_ENABLED=0` → **整句 direct**。  
- 每路查询：`SemanticSearcher`（FAISS IP / cosine）与 `LexicalSearcher`（字级 unigram+bigram BM25）各取 top **50**（`MEMORY_SEMANTIC_TOP_K` / `MEMORY_LEXICAL_TOP_K`）。  
- **助理块降权**：语义与词法两侧均乘 `MEMORY_ASSISTANT_WEIGHT=0.55`，避免助理长回复淹没用户经历锚点。  
- **RRF**（`store/fusion.py`，$k=60$）：

$$
\mathrm{RRF}(d)=\sum_{i\in\{\mathrm{sem},\mathrm{lex}\}}\frac{1}{k+\mathrm{rank}_i(d)}.
$$

- 融合后取 **fused top-40**（CE 开时 `MEMORY_RRF_TOP_K=40`）进入 **Multi-query Anchor CE**（`store/rerank.py`，`bge-reranker-v2-m3`）。

对每个 $q_j\in Q$（原始 query ∪ Planner 子查询）、每个 anchor $a$：

$$
s_j(a)=\mathrm{CE}\big(q_j,\operatorname{text}(a)\big),\quad
s_{\max}(a)=\max_j s_j(a).
$$

**不做 CE 与 RRF 数值混合。** Coverage 选种子：原始 query 保留 CE top-4；每个 Planner 子查询 top-3；去重后按 $s_{\max}$ 补齐/截断到 **12**，并保证每查询至少 1 条（coverage）。

#### （2）自适应扩窗（stitch）

对每个锚点，在同会话消息序列上向左/右生长（`store/stitch.py`）。候选消息 $c$ 相对锚点 $a$ 与当前窗 $W$ 的保留条件为：

$$
\boxed{
\operatorname{keep}(c)
\;\iff\;
\cos(c,a)\ge\tau
\;\;\lor\;\;
\big(\mathrm{dist}(c,W)\le d_{\mathrm{ent}}\;\wedge\;
\mathcal{E}(c)\cap\mathcal{E}(W)\neq\emptyset\big)
}
$$

其中默认 $\tau=0.40$（`stitch_cos_threshold`），$d_{\mathrm{ent}}=2$（`stitch_entity_dist`）；$\mathrm{dist}$ 为候选相对当前窗边缘的 position 距离。连续未命中达 `stitch_max_misses=2` 则停止该方向；窗跨度与消息数受 `stitch_max_span=12`、`bundle_max_messages=8` 约束。

**$\mathcal{E}(\cdot)$ 不是 NER。** `store/text_sim.py` 的 `entities()` 是启发式正则：抓 2–6 字中文块、英文标识符、以及带「度/分/周/天/年/月/日」的数字等。目的是给「邻接 + 专名桥接」一条廉价逃逸通道，**不是**命名实体识别模型。答辩被问「用了什么 NER」时，应明确说：没用；是正则启发式 token 集合。

直觉：余弦保证语义连续；**邻接 + 实体重叠**是逃逸通道，避免专名桥接被纯向量阈值切断。

#### （3）合并 → Legacy 时间感知 MMR

同会话重叠窗先 `merge_windows`。随后对合并后的经历窗做 **Legacy 时间感知 MMR**（`store/select.py`），**不使用窗级 CE**。

**内容相关**（正式默认）：

$$
R_{\mathrm{content}}(W)=2\cdot s_{\mathrm{fused}}(W)+1.5\cdot\operatorname{Jaccard}(q,W).
$$

其中 $s_{\mathrm{fused}}$ 仍来自 **RRF**（anchor 侧 fused 分映射到窗）。正式代码固定走多查询 Anchor CE，无开关回退。

选择器默认 `mmr`（`store/select.py`）。

**窗强度衰减**（相对上次强化时间 $t_W$）：

$$
\boxed{
D_W(t)=w_{\min}+(w-w_{\min})\exp\!\Big(-\frac{t-t_W}{\tau_d}\Big)
}
$$

默认 $w_{\min}=0.2$，$\tau_d=90\times 86400$（约 90 天）。

**相对新近性**（Legacy，正式默认开）：对候选窗按时间戳排序，新近性项 $\beta=0.8$（`MEMORY_MMR_RECENCY_BETA`），$\tau_r\approx 21$ 天；未见周桶奖励 $0.5$（`MEMORY_MMR_WEEK_BONUS`）。

**衰减后相关 / 有效分**：

$$
\boxed{
R_{\mathrm{eff}}(W)=R_{\mathrm{content}}(W)\cdot\big[\alpha+(1-\alpha)D_W(t)\big]
+\beta\cdot R_{\mathrm{recency}}(W)+\mathrm{week\_bonus}(W),
\quad \alpha=0.5.
}
$$

职责分工：Anchor CE 管「选哪些种子」；$R_{\mathrm{content}}$ 管窗级相关（fused + Jaccard）；decay / recency / week 管时间因素；MMR 管去冗余。历史上曾试验窗级 CE 接管 $R_{\mathrm{content}}$，均未超过当前主线，默认关。

**MMR 选窗**（冗余为字 bigram Jaccard）：

$$
\boxed{
\mathrm{score}(W)=\lambda\,R_{\mathrm{eff}}(W)-(1-\lambda)\max_{S\in\mathrm{Chosen}}\mathrm{sim}(W,S)
}
$$

默认 $\lambda=0.7$，选出至多 **`bundle_top_k=6`** 个窗；再按最早时间戳升序排列后注入。

#### （4）强化、Profile、格式化

- **使用强化**（`store/reinforce.py`）：被注入的窗更新强度  

$$
w^{+}=w^{-}+\eta(1-w^{-}),\quad \eta=0.1
$$

  （$w^{-}$ 为衰减后强度；同一会话内同一窗最多强化一次。）

- **Profile**：active 全量注入，上限 30。  
- **formatter**（`context/formatter.py`）：只渲染**用户**原文（助理不进 `<memory>` 证据行）；全局 token 预算 **1600**；窗数上限与选择器一致为 6。

### 7.5 默认超参速查

| 符号 / 配置 | 默认 |
|-------------|------|
| chunk soft / target | 500 / 150–350 |
| Dense / BM25 top-k | 50 / 50 |
| RRF $k$ / fused top-k | 60 / **40** |
| Anchor CE | **开**；coverage；keep **12**（orig 4 + sub 3/查询） |
| 窗级 CE | **关**（窗级 CE 已移除） |
| stitch $\tau$ / $d_{\mathrm{ent}}$ | 0.40 / 2 |
| MMR $\lambda$ / recency $\beta$ / week bonus | 0.7 / **0.8** / **0.5** |
| decay $w_{\min}$ / $\tau_d$ / $\alpha$ | 0.2 / 90d / 0.5 |
| reinforce $\eta$ | 0.1 |
| inject 窗数 / Profile / budget | ≤6 / ≤30 / 1600 |
| assistant 语义降权 | 0.55（`MEMORY_ASSISTANT_WEIGHT`） |
| FAISS ANN | 默认开（`MEMORY_ANN_ENABLED=1`；失败回退 Python cosine） |
| 跨会话显式链 | **默认关**（`MEMORY_CROSS_SESSION_LINKING=0`）；跨会话靠多窗召回 + 时间序注入，不做旧版链式打分 |

选窗实现细节（对照 `select.py`）：$R_{\mathrm{content}}=2\cdot s_{\mathrm{fused}}+1.5\cdot\mathrm{Jaccard}$；MMR 早停默认关（`MEMORY_MMR_STOP_ON_NEGATIVE=0`）。冗余度量是窗全文的字 bigram Jaccard，不是句向量。

### 7.6 本章小结

ER 把「智能」放在读路径：原文 Trace 保证可审计；**Anchor CE** 在扩窗前选种子；扩窗重建共现；Legacy 时间感知 MMR 去冗余并调节活跃度；Profile 只承载白名单硬事实。下一章用同协议实验检验这套形态是否真的更准、更不陈旧。

## 8. 记忆评测协议与结果

### 8.1 协议设计原则

要回答的是 RQ2：**在固定答题模型时，只换记忆库，长程 QA 差多少？**  
因此必须 **同 reader、同数据、同测试题**；差异应主要来自记忆的写入与组织方式，而不是生成模型强弱。

| 项 | 设定 |
|----|------|
| 数据 | `evaluate/memory/data/all_50.jsonl`：**50** 条可控校园长程叙事弧（六类能力桶 + hard_mixed 难例），共 **250** 题 |
| 弧从哪来 | 外部模型按规范**合成**的连续数周、多会话咨询叙事（非真实来访录音）；配应记/应忘金标准 |
| Reader | **MiniMax-M3**（固定；只读「该方法记忆块 + 试题」） |
| 对照 | **ER（Trace + 多查询 coverage Anchor CE 读路径）** vs **Mem0（写时抽取基线）** |
| Mem0 侧配置 | `mem0_adapter.py`：官方 mem0 + **MiniMax LLM 抽取** + 本地 **BGE-M3 1024** + **磁盘 FAISS**；与 ER **同对话流 ingest、同 reader** |
| 主指标 | QA 准确率（case-avg；亦可看 micro） |
| 辅指标 | Staleness 率、内容 F1（应记/应忘，LLM 对齐）、subclass QA |
| 正式 ER 跑次 | `evaluate/memory/runs/qa_er_all50/` |
| 正式 Mem0 跑次 | `evaluate/memory/runs/qa_mem0_all50/` |

流程直觉：按同一对话流逐轮 ingest → 在延迟测试点检索记忆块 → 交给固定 reader 作答 → 选择题精确匹配；内容 F1 对照金标准应记/应忘集。

**公平性一句话**：两边共用试题与 reader；差别只在「写入形态 + 该方法吐出的记忆块」。Mem0 侧也用本地 BGE-M3，不是「ER 用好编码器、Mem0 用差编码器」的不对称。

### 8.1.1 三个主指标在算什么（公式摘要）

> 展开推导见 **§3.8.4–§3.8.6**。

**QA 准确率**（全集或某 subclass）：

$$
\mathrm{QA\text{-}Acc}=\frac{1}{N}\sum_{i=1}^{N}\mathbf{1}[\mathrm{correct}_i].
$$

**Staleness 率**（仅 `probes∈{staleness,current,current_state}` 子集 $S$；越低越好）：

$$
\mathrm{StalenessRate}=\frac{1}{|S|}\sum_{i\in S}\mathbf{1}[\neg\mathrm{correct}_i].
$$

**内容 F1**（LLM 对齐应记/应忘后）：$\mathrm{TP}=$ remembered_ok，$\mathrm{FN}=$ missed，$\mathrm{FP}=$ false_remember，

$$
P=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}},\quad
R=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}},\quad
F_1=\frac{2PR}{P+R}.
$$

口述分工：QA 看「题答对没」；staleness 看「有没有把旧当现在」；F1 看「库相对金标准脏不脏、漏不漏」。

### 8.2 问题类型分别测什么

| category | 测什么 | 与 ER 设计的对应 |
|----------|--------|------------------|
| `detail_recall` | 人名 / 课程 / 数字等细节 | 原文入库 + 词法召回 |
| `context_recall` | 共现上下文 | 自适应扩窗 |
| `preference_recall` | 稳定偏好 / 沟通需求 | Trace 证据 + 窄白名单 Profile |
| `current_state` | 最新状态（抗 stale） | Legacy 时间感知 MMR + Anchor CE 种子覆盖 |
| `cross_session_integration` | 多会话整合 | 多窗召回 + 时间排序注入 |
| `temporal_sequence` | 先后顺序 | 原文时间戳 + 时序注入 |
| `hard_mixed` | 混合难例（多线索交织） | 全链路：覆盖式 CE + 扩窗 + 新近性选窗 |

### 8.3 主结果 @ `all_50`（终版 coverage Anchor CE）

| 方法 | QA（case-avg） | micro | Staleness | 内容 F1 |
|------|----------------|-------|-----------|---------|
| **ER** | **90.5%** | **90.8%**（227/250） | **8.6%** | **0.783** |
| Mem0 | **68.7%** | **71.2%**（178/250） | **46.6%** | **0.400** |

跑次：`qa_er_all50` / `qa_mem0_all50`。相对 Mem0：QA 约 **+22pp**，staleness 约 **−38pp**，内容 F1 约 **+0.38**。

| 项 | 默认 |
|----|------|
| Dense / BM25 top-k | 50 / 50 |
| RRF top-k | 40 |

| MMR recency β / week bonus | 0.8 / 0.5 |
| MMR stop-on-negative | 0（关） |

### 8.4 逐类 QA（`all_50`）

| 类别 | ER | Mem0 |
|------|-----|------|
| context_recall | 1.00 | 0.47 |
| detail_recall | 1.00 | 0.87 |
| preference_recall | 0.87 | 0.73 |
| cross_session_integration | 0.93 | 0.60 |
| current_state | 0.87 | 0.60 |
| temporal_sequence | 0.73 | 0.60 |
| hard_mixed | 0.91 | 0.75 |

解读要点：

- 优势集中在**共现、跨会话整合、抗 stale、难例混合**——与「原文 + Anchor CE + 扩窗 + 新近性选窗」叙事对齐；  
- `detail_recall` 双方都强，Mem0 也不差；  
- `temporal_sequence` 是共同短板（0.73 vs 0.60），不宜夸大时序能力。

### 8.5 消融：相对新近性（归档）

正式代码已固定含 Anchor CE。历史消融曾在无 CE 管线上开关 MMR 新近性：无新近性约 **84.4%** QA / **42.9%** stale → 加回后约 **92.2%** / **14.3%**（约 **+8pp** QA）。跑次已归档。结论：**不是「存了原文就自动好」**；查询时如何对待近期证据，本身构成方法的一部分。

### 8.6 边界与 caveats（必须主动说清）

1. **$n=50$**：受控叙事弧利于对照，但规模仍有限，**不可直接外推**为大规模真实校园部署结论。  
2. Reader 固定消除了「换答题模型」的混淆，但仍受 reader 能力上限约束。  
3. 本协议**不替代**对话线 BLEU/ROUGE；两条评测回答不同 RQ。

### 8.7 本章小结

同 reader 下，终版 coverage CE 在 `all_50` 上相对 Mem0 更准、更不陈旧；归档新近性消融说明读路径选窗是一阶因素。下一章把可主张的创新点与局限收束成答辩可用表述。

## 9. 创新点归纳与局限

### 9.1 可主张的创新点（收成两条主线）

**（1）对话线：面向校园心理倾听域的适配与对齐**

- 在 Qwen3-14B 上以统一 LoRA（$r=8$，$\alpha=16$）完成 **CPT → SFT → DPO**；  
- 用独立 MacBERT 只调节 **scale 0.7 / 0.3**（摘要关 LoRA），把「咨询/闲聊」从生成模型中拆出；  
- 证据：SoulChat 派生评测上相对裸基座 BLEU/ROUGE 大幅跃升；DPO 不以 BLEU 单调上升为成功标准。

**（2）记忆线：ER（Experience Rebuild）——原文 Trace + 查询时重建 + 窄白名单 Profile**

- 结构上取消 Trace 写时抽取，把理解后置到 hybrid 召回、**多查询 Anchor CE**、自适应扩窗、Legacy 时间感知 MMR；  
- Profile 仅允许 schema 白名单长期事实，LLM 抽取后直写 active，可为空；  
- 证据：`all_50` QA **90.5% vs 68.7%**，staleness **8.6% vs 46.6%**，F1 **0.783 vs 0.400**；归档新近性消融约 **+8pp** QA。

### 9.2 明确不主张为「创新」的部分

- Vue 前端、FastAPI 路由、SQLite 单机部署、启动脚本——属于**演示与工程可复现**，不是研究贡献叙事的主轴（见附录 A）。  
- dense / BM25 / RRF / LoRA / DPO 等名词本身不新；主张落在**问题约束下的组合与取舍**（误记代价、写弱读强、双线解耦评测）。

### 9.3 局限

| 局限 | 含义 |
|------|------|
| 记忆评测 $n=50$（30+20） | 相对优势可信，外推需谨慎 |
| temporal 仍偏弱 | 时序题双方都不高 |
| 无大规模真人盲评 | 对话「共情更好」缺人工/偏好胜率主证据 |
| 单机原型 | SQLite + 单卡；多租户与长尾延迟未作为研究重点 |
| Profile 直写 | 白名单降低乱记，但不等于零误抽；空 Profile 策略依赖抽取器保守性 |

### 9.4 答辩可用的收束句

> 校园场景需要低门槛倾听；通用模型不会好好说，写时抽取容易乱记。  
> SoulHarbor 用双线回应：对话上 PT→SFT→DPO 与场景化 LoRA；记忆上原文 Trace、查询时 ER 重建与严白名单 Profile。  
> 证据上，对话匹配相对基线明显提升；记忆同读对照更准、更不陈旧——同时承认三十弧样本与时序短板的边界。

## 10. 端到端推理时序（研究视角）

> 本节描述**一轮用户消息**里，对话模型与记忆子系统如何协作。刻意少写 FastAPI / 进程细节；工程落点见附录 A。

### 10.1 时序图（逻辑）

```text
用户本轮话 u_t
    │
    ├─(A) MacBERT(u_t) → is_consult ∈ {0,1}
    │         └─► 仅决定 chat LoRA scale s ∈ {0.7, 0.3}
    │
    ├─(B) [若用户开启记忆] ER.read(u_t)
    │         planner? → hybrid → stitch → merge → CE rerank → decay-MMR → chrono
    │         → <memory> 用户原文证据 + Profile（可空）
    │
    ├─(C) 构造 prompt：system（含记忆块）+ 历史 + u_t
    │
    ├─(D) Qwen3-14B + chat LoRA @ scale s  → 生成回复 a_t
    │
    └─(E) post-turn（可异步，不挡首 token）
              ├─ Trace.ingest(u_t), Trace.ingest(a_t)   # 零 LLM
              ├─ Profile.maybe_extract（攒批门控）       # 白名单 LLM，可空
              └─ 条件触发：会话滚动摘要（裸基座，关 LoRA）
```

### 10.2 研究视角下的「谁在理解用户」

| 阶段 | 是否「理解」用户 | 说明 |
|------|------------------|------|
| Trace 写入 | **否** | 只存原文块与向量 |
| Profile 写入 | **有限** | 只理解白名单字段；无则不写 |
| ER 读路径主体 | **算法重建** | 扩窗与 MMR 是确定性/可配置规则，不是再训一个记忆模型 |
| 可选查询规划 | **轻量** | 结构化拆查询；失败可回退 |
| 生成模型 | **是** | 在注入的证据上说话；不应独自承担「长期事实真相」 |

关键叙事：生成模型负责「怎么说」；记忆子系统负责「提供可审计证据」。冲突时，**当前用户说法 + 白名单 Profile** 优先于陈旧 Trace 窗——而抗 stale 主要靠读路径选窗，而不是写时给每条事实贴过期标签。

### 10.3 失败隔离（为何双线解耦在运行时也成立）

| 组件挂了 / 空了 | 主对话 | 记忆 | 口径 |
|-----------------|--------|------|------|
| **Qwen3 / chat LoRA** | 不可用 | 写不依赖生成 LLM；管理端只读仍可能可用 | 生成是硬依赖 |
| **MacBERT** | 启动期加载失败则服务起不来；API 若未传入意图，生成侧默认偏 **咨询 scale（is_consult=1）** | 不受影响 | 宁可语气偏强，不误走闲聊弱适配 |
| **BGE-M3 / 嵌入** | 可继续聊 | 写失败进重试队列；读侧可能空记忆块 | 「没记上」≠「说不出话」 |
| **检索空 / 关记忆** | 可继续聊 | 注入空 `<memory>` | 产品上记忆可关 |
| **Profile 抽空** | 正常 | 合法空画像 | 宁缺毋滥 |
| **查询规划失败** | 正常 | 回退整句 direct | 规划非硬依赖 |
| **会话摘要** | — | 关 LoRA、低温压缩 | 与对话偏好解耦 |

研究叙事：语气坏了不必等于记忆坏了；记错了也不必等于微调失败——所以两条线要能分开评、分开降级。

### 10.4 与评测协议的对应

- 对话 BLEU/ROUGE 评的是（C）（D）在固定参考下的词面接近程度；  
- 记忆 QA 评的是（B）产出的记忆块能否支撑固定 reader 答对长程题；  
- 二者不要在因果上混用。

## 11. 术语表

| 术语 | 含义 |
|------|------|
| **SoulHarbor** | 本项目：校园心理支持场景下的双线系统（对话适配 + 长期记忆） |
| **对话线** | CPT→SFT→DPO + MacBERT scale；负责「怎么说」 |
| **记忆线 / ER** | Experience Rebuild：原文 Trace + 查询时经历重建 |
| **Trace** | 原文消息块及其向量索引；写路径零 LLM |
| **Profile** | 窄白名单长期画像；LLM 抽取直写 active，可空 |
| **RQ1 / RQ2** | 对话适配问题 / 长期记忆形态与防误记问题 |
| **CPT / PT** | 继续预训练（下一 token CLM）；本仓库配置常写 `pt` |
| **SFT** | 监督微调；本项目为倾听语料 + 自我认知补充的**混合一批**；assistant-only loss |
| **DPO** | 直接偏好优化；本仓库 sigmoid，$\beta=0.1$；挂载 SFT 权重续训 |
| **LoRA / QLoRA** | 低秩适配 / 4-bit 基座上的 LoRA；本项目 $r=8$，$\alpha=16$ |
| **scale** | 推理时 LoRA 分支强度；咨询 0.7、闲聊 0.3 |
| **BGE-M3** | 双塔检索嵌入（[arXiv:2402.03216](https://arxiv.org/abs/2402.03216)）；本项目只用 dense **1024** 维；**不另训**；原理见 §3.7.3 |
| **MacBERT** | 中文 Encoder + MLM 改进（Findings of EMNLP 2020）；意图二分类 → scale；原理见 §3.7.2 |
| **Qwen3-14B** | Decoder 因果 LM 基座（约 14.8B）；$p(x_t\mid x_{<t})$；挂 DPO chat LoRA；原理见 §3.7.1 |
| **bi-encoder / 双塔** | 查询与文档分别编码再比向量；相对 cross-encoder 可离线预计算文档向量 |
| **MLM** | Masked Language Modeling；MacBERT 用近义替换减轻 `[MASK]` mismatch |
| **Causal LM** | 因果语言建模；只看左侧上下文预测下一 token |
| **BM25** | 字级词法检索 |
| **RRF** | Reciprocal Rank Fusion；本项目 $k=60$ |
| **anchor** | hybrid 融合后的扩窗种子命中 |
| **stitch / 扩窗** | 自锚点沿会话生长经历窗；cos 或邻接实体条件 |
| **实体 $\mathcal{E}$** | **非 NER**：`text_sim.entities` 正则启发式（中文块/英文标识/带单位数字） |
| **自我认知数据** | 约 274 条人设问答；**并入 SFT 混合数据**，不单独成训练阶段 |
| **seen / unseen** | 按对话 signature（≤6 轮）是否出现在 SFT+DPO 训练池划分；topic 均衡抽样 |
| **MMR** | Maximal Marginal Relevance 选窗；本项目含衰减与相对新近性 |
| **$D_W$ / $R_{\mathrm{eff}}$** | 窗强度衰减；含新近性与周奖励的有效相关分 |
| **staleness** | 抗陈旧探针子集上的错误率（§3.8.5）；越低越好；≠「库里还有没有旧 Trace」 |
| **内容 F1** | 相对应记/应忘金标准的 $P/R/F_1$（§3.8.6） |
| **QA-Acc** | 固定 reader 下答题正确率（§3.8.4） |
| **BLEU** | 修正 n-gram 精确率视角的生成–参考重合（§3.8.1）；本项目词级 ×100 |
| **ROUGE** | n-gram / LCS 重叠的 F（§3.8.2）；本项目 ×100 |
| **同 reader 协议** | 固定答题模型、只换记忆库的对照设定 |
| **Mem0** | 写时抽取式记忆基线（本评测对照） |
| **MemMachine** | 宽画像取向的对照叙事（非本仓库依赖） |
